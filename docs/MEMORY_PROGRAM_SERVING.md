# Serving a learned byte-memory program on a large causal host

**What is usable now.** In a trusted single-device process, keep the expensive causal model on its own byte frontier, a small policy over typed working registers, and native readers with exact version/scope bindings. The host runs on observed tokens, **not on memory instructions**. The workbench can read, feed a result to another read, join, save, recall, or emit without another large-model call. An optional graph replays only the known one-byte host dataflow. Following an unknown pointer or searching an unchosen index is never part of that graph.

**What isn't established.** No held-out general-LM advantage for learned programs over direct retrieval, no end-to-end large-model training comparison, no successful monolithic FP32 GDN2 long-chunk launch on this card, no arbitrary tokenized LLM plug-in, distributed KV, open-load SLA or multi-tenant service. A tokenizer ID from a subword model is **not** an observed byte or a normalized next-byte distribution. These local research comparisons used versioned, document-bounded raw-byte streams and a 256-way host. The GDN2 dependency is external and its license must be reviewed before any other use. Nothing here authorizes a rollout.

## Minimal integration contract

1. Authenticate/admit data capabilities and bind one new `Session` to one document/window. Pin the model weights, native descriptor/version, session nonce, precision and byte horizon. Fail closed on missing/incompatible scope. Positional reads verify coordinates; histogram/MEM summaries aren't positions. Cells and graph handles belong to this session, not a shared archive. No optimizer updates or concurrent device streams on this inference owner.
2. Prepare the host arena **once**, with a finite list of real step widths and explicit byte limits. For the qualified FP32 27-layer GDN2, use `ResidentArena(net, capacity=16, context=64, widths=(1,16), byte_budget=256<<20, private_budget=64<<20)` under `torch.no_grad()`. `net` is the loaded **inner byte model**, in eval mode, not its trainer. Reject over-capacity admission. By default a non-bucket width takes the real eager step. With the [qualified four-width store](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_WIDTH_COVER.md) `(1,4,8,16)`, call `arena.set_cover(True)` once while empty: a non-bucket width is split across at most six already captured exact graphs, with no padded clients. The real-width cover improved B3/7/13/15 sampled rates by 1.28–1.82× on the 150M host, using 50 MiB total private pools. Preparation can have transient allocations; the graph limit is checked on actual private pools *before publication*. Budget process/device high-water separately. For longer prompts, [S9](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_LONG_PREFILL.md) failed to launch the stock long FP32 chunk on Ada: **do not use `chunk_prefill=True`**. [S10](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_SEGMENT_PREFILL.md) qualified `segmented_prefill=True, context=2048` instead. It carries all native recurrent/conv state between ≤64 observed bytes at a time; 512-prompt complete service was 1.41–3.76× the same FP32 token-by-token prompt ingestion. This is parity to streaming recurrence, not monolithic stock long-chunk or a quality claim.
3. `ticket = arena.admit(session.id)` and `session.observe(actual_prompt)`. `arena.prefill([ticket], [actual_prompt])` returns `(hidden, base_logp)` for the **next unobserved byte**. Use the host's full trained features if training a new policy; the retained engineering fixture used `hidden[:,:256]` solely to match a prior C14 policy's input width, not because those features are calibrated. Run `policy.batch_runner()` on those inputs and the bound sessions. Its `EMIT` stages the response and commits valid cells. For pure direct retrieval or bare neural generation, bypass the memory policy explicitly.
4. Deliver the actual selected byte and `session.observe(bytes([b]))` exactly once. Before the next prediction call `arena.advance([ticket], [previous_visible], [b])`; don't re-encode the prompt, newly written memory, or a token from another client. `arena.read(tickets, frontiers)` reuses cached host outputs **without advancing**. Regroup tickets only with their corresponding symbols/frontiers. No oracle target in serving. If a request fails or is cancelled, don't reuse an uncertain frame; retire the admission and its session.
5. `arena.release([ticket])` even on early termination, then close the live native session/descriptors when no pending I/O uses them. Release scrubs both causal and cached output rows; neutral graph work uses charged, unadmittable rows so a surviving client can keep progressing. `arena.close()` after all tickets are released. The context manager clears on exit. This is logical erasure of owner-controlled tensors, **not** physical memory sanitization or an isolation boundary against arbitrary code on the device.

Important code: [`host_cache.py`](../ndm/memory_program/host_cache.py) (ownership/frontiers + C14 attention), [`recurrent_host.py`](../ndm/memory_program/recurrent_host.py) (native recurrent/three conv states), [`host_graph.py`](../ndm/memory_program/host_graph.py) (known-step graph), [`resident_host.py`](../ndm/memory_program/resident_host.py) (finite buckets/lifecycle), [`packed.py`](../ndm/memory_program/packed.py) and [`triton_operands.py`](../ndm/memory_program/triton_operands.py) (dynamic controller), [`serving.py`](../ndm/memory_program/serving.py) (ready-session experiment). The [actual retained-host service driver](../experiments/expressivity_tasks/x47_xsa_attention/wide_host_bench.py) also has a bare no-index bypass and pairs every trajectory with a reference.

## Changing membership in a trusted process

[`ByteService`](../ndm/memory_program/byte_service.py) binds the host admission, raw prompt, controller state, live native descriptor, output limit and (for sampled programs) the action-independent RNG to a single opaque `Ticket`. It has no network listener. [S12](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_ARRIVAL_SERVICE.md) checked 128 admissions under independently clocked offers (including 16 early cancellations), all returned prefixes exact vs the closed oracle. Its sampled offer-to-first-byte p95 was over 2 seconds on that short offered workload, despite a 37–38 ms median interresponse interval. Open the immutable domain and arena **outside** the service so they outlive all their clients:

```python
# Owner thread; fixed eval-mode CPU policy, eval-mode GPU host, verified TRAIN prompt in this example.
with torch.no_grad(), ByteService(arena, policy=policy, mode='sample', seed=7530,
                                  limits=domain.limits, features=lambda h: h[:, :256].contiguous()) as svc:
    t = svc.admit(prompt, lambda: domain.binding(document_row), limit=12, row_id=stream_seed_id)
    reply = svc.step([t])[0]  # synchronous return: this actual byte is already observed
    svc.release([t])          # cancel early or release after the limit
```

Each call to the zero-argument factory must return a **new context manager** for `(fresh_session, private_attachment)` whose exit closes that binding; never supply another user's or already advanced session. [`ServingDomain`](../experiments/expressivity_tasks/x47_xsa_attention/arrival_domain.py) shows the checked local whole-P100 case, not an arbitrary index/ACL adapter. Pass `direct=callable` **instead of** `policy` to bypass the workbench: the callable receives these clients' attachments and bound base log-probabilities. The outer intake owner may service `svc.ready` or a subset; use `svc.available` to bound queues outside the engine. `CapacityError` doesn't open a descriptor. Delivery exceptions poison the owner: don't retry the same tick, reuse uncertain native state, or assume network exactly-once delivery. `trace=True` returns private per-client execution data; don't log or share it by default.

For the **trained direct comparator**, use `feature_direct=DirectReadout(frozen_cpu_head, verified_bank)` instead of `direct=` or `policy=`, and `features=lambda h: h[:, :256].contiguous()` for the T9 bridge. Open one fresh [`DirectStream`](../ndm/memory_program/direct_service.py) per admission, yield `(stream.session, stream)`, and close it on exit. Its table consumes only the prompt and that client's committed bytes. The adapter checks the binding before host admission and uses a single host packet per tick. [S14](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_DIRECT_ARRIVAL.md) matched 2,784 actual arrival replies against closed oracles on the retained 150M and dense replicated 2.22B shapes. Terminal-page transport cut wire to ~19% but cleared 1.10× throughput on only one of four comparisons; keep page traversal as the serving default. Domain setup alone cost 2.22–4.61 s before the first offer. Do not claim that steady rates include this cost.

For **online DIRECT/ENTER**, pass `entry=EntryReadout(frozen_conditional_model, direct_bank, gate_seed=7823)`, `mode='sample'` and `seed=7530` to `ByteService` for the [S17 fixture](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_DEMAND_TAPE.md). Yield `(session, EntryStream(session, byte_limit=context))` per admission, close the stream and its private readers on exit, and give simultaneously active requests distinct `row_id`s. Only the selected predictor runs, on the current actual host features; never feed an ENTER the direct-augmented scores. `step` acknowledges the byte to the combined stream once. This is not T11's teacher-forcing queue or the async `drive` interface. The local [`PrivateTape(..., demand=True)`](../experiments/expressivity_tasks/x47_xsa_attention/private_tape.py) adapter maintains all observed bytes in a bounded **private** mirror but starts a private native index only when a selected live branch/locate requires it. At 19 ENTERs among 348 generated replies the peak number of open private workers was 2 instead of 16, with 5 instead of 380 native appends. It passed the resource/latency gate but not panel-wide 1.10× throughput. Archive position service and whole-mount admission still cost resources. Do not treat an unsynchronized physical index as the logical tape watermark.

Across successive client groups, keep immutable mount admission separate from private readers and caches. [S15](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_BRANCH_DOMAIN.md) checked four disjoint waves on precomputed causal host features. A single pinned m20 process with fresh revocable grants produced the same 1,024 direct/sampled prefix predictions as four fresh processes. Open time dropped to .235× and complete domain wall to .710×, but native peak rose from 261.2 to 370.4 MiB (1.418×). Keep fresh m20 lifetimes by default. Releasing a Python page cache does not reset a native process's high-water mark. Neither mode permits sharing live sessions, positions, writes or document counts across clients.

If successive groups have **the same whole-mount authority**, [S16](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_PINNED_DESCRIPTOR.md) qualified a narrower reuse boundary: `with P100Image(manifest, scope='whole', max_waves=4) as image`, then `with image.wave('P100', version, scope='whole') as (domain, descriptor)` for each group. Borrow one grant from `domain`, close private clients and return it before exiting the wave. This keeps the verified document-boundary metadata and file pins, not a worker. The four-wave prefix panel kept all predictions and `R` traffic exact at .380× complete domain wall, **including** the first image build and all four new native processes. Worst m20 peak was 261.1 vs 261.2 MiB. This does not qualify an unlimited daemon, thread handoff to an async positional reader, or shorter offer-to-first-byte time on a live GPU service.

For synchronous positional and span-value reads, nest `with ScopedRecords(descriptor, text_receipt, scope='whole', branches=grant, encode=value_encoder) as records` inside the grant. Give clients `records.readers()`, **not** the descriptor, worker or raw bound methods. Close the record owner before returning the grant; grant expiry also revokes a forgotten companion. [S18](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_RECORD_RETIREMENT.md) checked actual positive positions and values across 24 freshly verified domains. Holding nine public readers after ordinary close kept three 123 MiB starts arrays alive even after GC; scoped readers kept none, saving ~369 MiB of current RSS with a 1.009× mean six-wave wall. Do not infer a live GPU leak from this test or force GC as a substitute for the lifetime boundary. These callbacks check their owner thread and are **not** S13 offload callbacks.

When offers precede mount setup, measure from the **actual offer through final close**, not from an already-open grant. [S19](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_ONCLOCK_MOUNT.md) tested four successive grants of eight waiting clients on each live host. Metadata reuse preserved every generated reply and shortened whole-panel offer-to-first p95 on both sizes. But the replicated lifecycle ratio was .882 (required ≤.85), and the retained first group's cold p95 ratio was 1.300692 (required ≤1.30). Keep fresh grants/workers and do not promote image reuse as a serving latency default on that evidence. Queued descriptors carry no host slot or authority to pre-open the next wave.

For a caller supplying independently offered work, `await svc.drive(tickets, on_batch, on_retire, offload=[immutable_positions])` consumes an **async iterable of already admitted tickets**, not a list of guesses about later clients. The intake owns its bounded waiting queue and calls `admit` only when a slot is free. `on_batch(replies)` receives a committed batch and may return tickets *in that batch* to stop early. At the limit or a requested stop, the actor finishes, releases its own rows/binding, and calls `on_retire(tickets)` so intake can reuse capacity. Don't call `step`, `release` or `close` concurrently with a drive. The service joins its one serialized immutable reader before shutdown even on a failed drive. Any earlier deliveries stand; a caller exception is not rollback or network acknowledgment. The open and barrier paths are independently selectable. [S13](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_OPEN_COHORT.md) qualified the former for bounded client lifetimes (185/239 peer responses during verified positional reads, no differing prefixes). It **failed** its combined speed/latency default gate: peer p95 intervals fell, but the spaced median rose 29% and burst throughput gained only 6.6%. The caller must keep the domain, fixed weights and `no_grad` owner context alive throughout; no unrelated coroutine may mutate them.

On the retained 150M synchronous host, [`ScopedRecords(..., defer_position=True)`](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_DEMAND_POSITION.md) still verifies and pins the archive at admission. In S20 the first chosen unresolved occurrence read paid for launch: four → zero positional processes per sparse trial, four → two with unrestricted programs. Positives were not free (mean worst native tick 1.135 → 1.279 s). The option passed both registered traffic profiles; it is not a change to asynchronous capability lifetime or a training-quality result.

## Size the whole service

For the measured 150M GDN2, each slot needs `4 * [27 * (2*128*256 + (256+256+512)*4) + 640 + 256]` = **7,523,840 bytes** for FP32 recurrence, q/k/v conv, last hidden and base. At capacity 16 plus 16 neutral scrub slots: **229.61 MiB**; width-1/16 private graph pools add **24 MiB reserved**. These aren't total allocations. S6 post-release allocator figures including the loaded host were 819.59 MiB allocated, 1,364 MiB reserved, stable across its last 36 churn waves. Host RSS and mmap/native workers are additional. S7 wide shape multiplied head-state size by four, not by parameter-count ratio; its arena alone was ~918 MiB. Weights need separate charging (8.28 GiB wide). Do not extrapolate from one shape by multiplying tokens/s by parameter count.

When four CPU threads are available for the 48-wide controller, [S8](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_CONTROLLER_PLACEMENT.md) found one packed causal host→CPU transfer faster than sending every dependent pointer decision to the GPU. The retained 150M B16 CPU workbench generated 738 greedy / 254 sampled bytes/s; the faster GPU comparator gave 591 / 209. CPU core-seconds rose substantially. Bind `place_inputs(hidden, base, width=policy.host.in_features, device=policy.embed.weight.device)` once before running the policy; construct numeric values and cells on that policy device rather than copying pages mid-program. The Triton scorer is an option, not a requirement on the host or on every legal choice.
