# The model chooses the memory program

**Interface decision after W3.** Fix the meaning of an instruction, not the pattern the model is supposed to find. A join combines two sets of bindings on a shared key. Neither set has to be a pair of child branches; either can be the result of an earlier search, a computation, a prior join, or a restored bookmark. An edge histogram is a useful first read, not the definition of memory.

W3's extractor selected a 4/2-byte address, an earlier occurrence, its second successor, and the two most frequent archive edges **before the network ran**. Its controller could change values, scores and trust; it could not change those requests. Its negative result is about that program only. Don't respond to it by designing another suffix/copy heuristic.

## Contract

- **The host provides** the actual observed byte tape, a causal LM state, a set of admitted versioned mounts, and an instruction/row/work budget. Each mount advertises input and output column types and an operation on keys. It may expose branch counts, eligible occurrences, aligned spans, or stored features. A new compatible archive needs a provider, not a new policy head. Queries can only see authorized data. Unsupported scope or exactness is a refusal; an unmaterialized index node isn't an empty relation. A locator returning a verified span is not implied by the ability to return a count.
- **A register holds a relation:** rows of named keys, log masses, and neural vectors. A byte string is comparable by content. A location includes source, version/session and document-relative coordinates; equality of two raw offsets is not a join. Keep duplicates and their masses unless an explicitly different operator aggregates them. The writable registers belong to this document/session, never to the shared archive.
- **The model issues instructions.** It chooses a visible byte span, the source and key column to look up, which returned row(s) to follow, the two input registers and key fields to join, what computed value to write and where to save it, which saved relation to recall, or whether to stop. Results become operands of the *next* instruction. A small workbench or recurrent controller can do this on top of a causal LM. The number of layers, registers, rounds, rows and admitted sources can be bounded without fixing their semantic roles. Registers can represent many occurrences without eagerly enumerating a large interval if the provider has an exact handle/aggregate for it.
- **Composition, not a menu of recipes.** For example, look up a selected old span in a mounted archive; save part of the result; later recall it and join it to a new lookup on a compatible field; use the surviving bindings to request values in another read. The same policy interface can instead emit immediately or do just one branch read. None of these *whole programs* is a special opcode. Swapping a mount, returning three edges instead of two, or choosing a different input register must not require a new trainer or feature extractor.
- **Learn values and decisions separately.** Gradients through a selected row can train its vector, the writer, and the attention over it. They do **not** train the integer address or opcode. For chosen-only sampling retain the conditional log probability of every operation **and operand**, and assign subsequent LM loss (including losses after recall) to the trajectory that incurred it, with a baseline and an explicit read price. Exact marginalization on small bounded alternatives is also valid, but merging states from different write histories isn't. Initialize a useful direct lookup/read path for greedy execution; leave competing choices legal and sampleable. A bias toward the word `JOIN` is not an initialized algorithm.

## Executable interface

[`ndm.memory_program`](../ndm/memory_program/) implements the reference machine. The controller is a small Transformer over a causal LM state and a rebuilt view of working registers and saved cells. Its trainable opcode head and conditional pointer head issue **one instruction and its operands** per round. A mask checks types, not whether a query would be profitable. There is no target argument to `policy(sessions, hidden, base_logits)`. Instruction results are first-class pages, not just numbers added to the current byte logits.

| Instruction | Chosen operands and effect |
|---|---|
| `SLICE` | Endpoint and length inside the visible tape window → bytes **and** a session/document-bound location. |
| `LOOKUP` | Register, key column, mounted capability → extend each row with all returned bindings, mass and optional value. The resulting extension, location or key can itself be looked up. |
| `FOCUS`, `PROJECT`, `CONCAT` | Select a row, keep a key column (without removing duplicates), or form a new byte key from two bound strings. None append to the observed tape. |
| `JOIN` | Two registers and one field in each: exact many-to-many equality join. Multiply masses (add log masses), preserve both bindings, fuse values. No fixed number of candidates. |
| `RELATE` | Two registers: score their bounded Cartesian product using learned query/key compatibility conditioned on current state. Preserve both bindings. This is learned pair weighting, **not** proof of equality. |
| `SAVE`, `RECALL` | Choose a result and writable cell; store the bindings, masses and newly computed vectors. Recall an entire page at a later byte. Overwriting a cell does not mutate an already read register. |
| `EMIT` | Stop with the base LM, or attend to a register's values and optionally vote from a chosen byte column. All 256 bytes stay in support. |

`MemoryPolicy(host_dim)` starts with a working direct program in its transition and operand weights: select the most recent single byte, look it up in a byte-edge reader, emit a half base / half empirical byte mixture on success. It is **not** a learned optimal starting strategy or W3's calibrated direct model. Registrations are capabilities, not per-dataset output neurons. A provider of verified positions or semantic feature records can return span keys and/or neural values through the same `Reader` contract. The [span-reader profile](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_MEMORY_PROGRAM_PROFILE.md) added bounded native occurrences and actual span contents/following values alongside the branch readers. It supports verified whole P100 queries (raw interval cap eight) and the current live document, not partial document ACLs or enumeration of arbitrary large intervals. A learnable hash embedding is used for some pointer features; exact key equality never uses a hash embedding.

For a natural byte LM, provide `causal_encode(x) -> (hidden, logits)`, verified raw document windows, and fresh sessions with their own live append callbacks. No join labels, preselected source addresses, task IDs, or synthetic tags:

```python
from ndm.memory_program import MemoryPolicy, Session, teacher_force

policy = MemoryPolicy(host_dim)  # instantiate once; optimize shared policy/value parameters
# Per batch: mount before constructing sessions; use a new live context for each window.
sessions = [Session([archive_reader, live_reader], advance=append, session_id=sid,
                    document=doc_id, start=offset)
            for live_reader, append, sid, doc_id, offset in bindings]
batch = teacher_force(policy, causal_encode, sessions, raw_windows, mode='sample',
                      key_price=key_cost, instruction_price=step_cost, baseline=prior_batch_baseline)
optimizer.zero_grad(); batch.objective.backward(); optimizer.step()
# Report batch.mean_nll, not the numerical value of the policy-gradient surrogate.
```

`teacher_force` groups equal-length windows for the causal backbone. At each real byte it executes sampled decisions, scores the next byte, **then** advances the corresponding sessions. Use fresh sessions at a window boundary/weight update. The in-graph writer gets ordinary gradients through later reads; each sampled instruction and operand also gets the **remaining** within-window loss and work cost as its score-function weight. Greedy and replay traces are not silently treated as on-policy samples. The sampled all-byte NLL is conditional on the sampled trajectories, not an exact marginal over every possible memory history. This estimator can have high variance; the interface isn't a claim that long programs train well.

**Efficiency boundary.** Across active examples, rebuild the Transformer view once per round; dispatch only chosen queries, grouped by reader object and row cap. Deduplicate equal keys in that round and restore every input binding, including duplicates. For the existing immutable m20 transport, the [adapter](../ndm/memory_program/m20.py) resolves a batch of arbitrary chosen keys depth by depth, with a bounded mount-local node cache. It distinguishes a positive edge without a child page from a proven absent edge; it doesn't open a new XSA process per instruction. Excess work returns an explicit refusal with no partial register. A select on an empty result can fall back to the base LM. Conditional sampling now returns chosen indices across active documents together at each operand depth. The Python reference still constructs many small tensors and materializes bounded tables; it is **not** the high-throughput fused training or serial decode implementation. Millions of target bytes in W3's static cache do not price this machine.

## Engineering order and success criterion

Test dispatch and gradients as software contracts, not as an LM research result. Profile the actual chosen program (host, native serving, packing, device, and end-to-end clocks) before promoting the reference to a large trainer. Batch pointer sampling and replace page materialization/reduction with resident kernels where profiling warrants it. W3's cached two-child features cannot train dynamic addressing: they omit the outcomes of different requests. Caching immutable **answers to keys** is fine; caching which key the future controller will choose is not.

**Packed training path.** Use `PackedMemoryPolicy(host_dim)` in place of `MemoryPolicy(host_dim)` for FP32; their state dicts are interchangeable. `teacher_force` packs current register rows, fields and legal operand features across active documents, reusing unchanged saved-cell views without severing gradients. Numeric packing indices never replace the logical keys. To check a fixed program use `mode='replay', replay=plans` (document → prediction → instructions); its result has no training objective. The [P2 parity and cost report](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_PACKED_PROGRAM.md) compares all intermediate bindings, masses, byte distributions and gradients on a natural batch, then measures **fresh** sampled updates: 77.0 targets/s on four documents and 161.7 on 32. Even a single million-target arm does not fit the remaining budget. `P100/occurrences` and backward are now both material costs; a faster resident read alone is not a solution.

**Serving is a different clock.** [S1](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_TRITON_SERVING.md) and [S2](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_COHORT_SERVING.md) generated bytes, not teacher-forced targets. The Triton scorer computes legal operand logits and their first adjoints; it does not search the archive. Independent ready sessions can continue during another client's verified positional walk. Batching compute by dependency stage helped sampled traffic, but neither scheduler passed its whole promotion gate. The byte barrier is still the comparison default.

The causal host runs **once per observed byte**, not once per instruction. An inference host can `admit(session)`, `prefill(handles, actual_prompts)`, and `advance(handles, expected_frontiers, newly_observed_bytes)` via [`CachedByteHost`](../ndm/memory_program/host_cache.py). The result is a batch of causal hidden states and base log probabilities; all of a client's memory instructions for this prediction use the same pair. Only a delivered byte advances that client's live index, and a final delivered byte need not enter the host until the next request. `read` returns the already-computed pair, never a new prediction step. Use fresh handles at document/window boundaries, explicit tensor-byte and length limits and `release`/`clear` in a `finally` block. This is a single trusted process with immutable weights, not cross-tenant KV sharing. [S3](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_CACHED_HOST.md) matched complete C14 service trajectories while reducing host positions 4,064→95/client; that was *not* a comparable wall-time speedup. [S4](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_LARGE_BYTE_HOST.md) also executed the programs on a retained 149.9M-parameter GDN2. The arena then holds each layer's recurrent matrix and three short-convolution states, not KV. Full-prefix and incremental paths generated identical bytes/events; sampled B16 served 131 bytes/s cached vs 128 full. The subsequent [capacity and placement guide](MEMORY_PROGRAM_SERVING.md) covers static host graphs, resident churn checks and the dense 2.22B shape probe. A state/weight-change boundary in training is not solved by the inference API. On a separate [first-order training-path qualification](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_HOST_VJP.md), an exclusive deterministic host could stage CPU leaves and recompute each original microbatch for its VJP: all tested 150M host + policy adjoints matched, without retaining GPU host activations through the rollout. B32 peak fell 7,723→2,057 MiB, but full gradient wall exceeded its registered overhead limit. No weights were updated.

**Optional sparse entry model.** [`SparseProgram`](../ndm/memory_program/sparse_clock.py) adds a trainable host-only BASE/ENTER decision; it is a **different predictor** with a different memory-contact budget. In teacher forcing `sparse_teacher_force(..., clock='compact')` groups each document's next chosen ENTER and appends its intervening already-scored BASE bytes. The gate itself never reads the workbench or later input, so it is legal to regroup that way. The score-function term charges every decision, including bypasses and subsequent losses after a write. [T2](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_SPARSE_CLOCK.md) checked a real 150M gradient batch with a 1/16 untrained prior, 248/4096 actual entries: 1,197 vs 779 targets/s on equivalent paths, zero optimizer steps. Quality/optimal contact rate are unknown. Don't run this clock for a gate conditioned on unknown cell state or program results.

**Strong retrieval bypass.** [`DirectEntryProgram`](../ndm/memory_program/direct_entry.py) instead chooses DIRECT (the trained four-expert head) or ENTER (P2 on the *original* host scores). Only the chosen path queries memory. `EntryStream` binds direct counts and program cells to the same raw observations. `direct_entry_teacher_force(..., clock='queue')` groups currently chosen ENTERs without advancing a waiting stream; direct probes are priced in the all-byte objective, not free fallback predictions. [T11](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_DIRECT_ENTRY.md) matched all choices, direct evidence, argmaxes and first derivatives within registered tolerances on T4 retained features. At the untrained gate's 248/4096 entries, mean complete gradient wall fell from 4.706 to 3.296 s; no optimizer step or host gradient. This supports a training schedule for this predictor, not its quality, a learned entry rate or a live-service queue discipline.

**Frozen hosts and private feature files.** For offline teacher forcing only, a deterministic, immutable byte host can supply features without also selecting the memory program. [`Window` and `PacketBinding`](../ndm/memory_program/frozen_packet.py) identify the ordered raw *inputs*, their source/split/document-relative origin, and the exact host/precision/bridge recipe. Compute the binding independently at the producer and consumer. [`record_frontiers`](../ndm/memory_program/stream_packet.py) uses an exclusively owned, empty evaluation arena: prefill one real byte, advance one byte, record `hidden[:width]` and normalized `base_logp` for that frontier, then release before slot reuse. No target byte, memory query or sampled choice belongs in the file. `write_packet(path, binding, features, byte_limit=...)` returns a digest and size. Transfer the digest via a trusted receipt; don't trust a self-asserted hash next to untrusted data. `FrozenPacket.load(path, binding, expected_sha, byte_limit=...).encoder(fresh_sessions)` supplies the ordinary `teacher_force` encoder. The learner still needs its own authorized native readers and fresh rollout. A file with 256 hidden features and 256 logits costs 2,048 payload bytes **per target**, is private like its source, and cannot train any of the frozen producer's weights. A weight, kernel, precision, feature, or source change requires a new binding. This does not speed up live free generation, whose next input is not yet known. The [T3 failure](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_FROZEN_PACKET.md) explains why the stock BF16 training-chunk source was **not** qualified. [T4](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_STREAM_PACKET.md) reproduced true FP32 serving-frontier packets on the retained 150M and dense replicated 2.22B geometries. The CUDA-invisible retained learner matched the complete coupled forward trajectory, but two gradient hashes and the updated policy differed; **exact coupled update equivalence did not qualify**. For fresh *offline CPU vs offline CPU* reproducibility, [T5](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_CPU_UPDATE_REPRO.md) qualified strict deterministic PyTorch algorithms in independent, exclusive four-thread workers: all gradients/updated parameters/moments identical on both sizes, 1.024× mean retained wall vs ordinary. Default workers differed at 403 gradient elements on a repeated update. Set `torch.use_deterministic_algorithms(True, warn_only=False)` before creating the worker workload; don't toggle this process-wide policy around other clients.

An alternate [`SegmentRecorder`](../ndm/memory_program/segment_packet.py) returns every frontier from short FP32 native pieces of *already known* inputs. [T6](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_SEGMENT_PACKET.md) measured ~5× faster frozen extraction and matched actual downstream program choices. It passed the 150M update tolerances but missed one 2.22B-feature post-step controller parameter bound. Do not silently replace the bytewise reference on that geometry, mix the two file bindings, or use an approximate backend clock as evidence of equivalent training.

A value-learning control must hold fixed the **executed** choices, not merely the weights that select them. [`frozen_routes.py`](../ndm/memory_program/frozen_routes.py) can capture the discrete decisions and check real request keys, raw multiplicities and resulting register layouts during value-only replay. [T7](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_FROZEN_ROUTE_CONTROL.md) matched all initial natural execution/dispatch hashes but not the complete byte-vector hash between a gradient-disabled capture and a normal training forward. It stopped **before** the natural fixed-route update. The synthetic writer-gradient test does not qualify that comparison.

[T8](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_INBAND_ROUTE.md) records inside the **actual gradient-bearing sampled forward** (`record_training_routes`), returns the live objective, and seals the tape before backward. The initial value-only replay and the updated-weight positive replay each matched every score bit and every issued read. With the same updated full weights but the *initial* tape, 321/4,096 TRAIN argmaxes changed. The forced learner updated its writer with all execution fixed and no selector-only adjoints. This is a qualified one-step control on this host packet/stack, not a quality win or license to generate a frozen comparator's future routes from an already changed model.

[T12](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_PAIRED_FRONTIER.md) completed the **separate** fixed-execution reference on two disjoint TRAIN batches: capture a new tape from the original selector on each batch, reissue its actual calls, and carry only the value learner's parameters and AdamW moments into the next update. The candidate [`FixedFrontierPair`](../ndm/memory_program/paired_frontier.py) instead stages structural results for the same frontier and re-encodes values separately. Its synthetic writer-credit and admission tests passed, but the T12 driver stopped on a missing zero counter after the reference cell. **No T12 natural paired result or paired-resource recommendation.** [T13](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_FIRST_PAIRED_TRANSITION.md) subsequently ran the first natural paired worker against the sealed reference without retiming it. Both full value/AdamW transitions matched exactly, including after moving to 16 different documents; positive LF work and live appends were one role's rather than two. This is a working on-new-input fixed-choice control for the tested P2/encoder schemas, not a price promotion or a quality comparison.

For a trainable **direct retrieval** comparator, [`DirectTrust` and `DocumentCounts`](../ndm/memory_program/direct.py) use the causal host, bounded P100 suffix backoff, observed local follower frequencies and latest local follower. No instruction trajectory or delayed neural write. [T9](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_DIRECT_CONTROL.md) checked the full direct update on the same retained-host TRAIN fixture; grouping currently chosen immutable queries cut mean B32 step wall to .704× with bit-identical predictions and gradients. It did not compare trained heads on unseen text. Don't present BASE, fixed serving direct, W3 and this trainable model as interchangeable controls. [T10](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_TERMINAL_BRANCH.md) then cut this grouped comparator's m20 wire to .165× and whole-step wall to .634× by fetching the terminal or miss-certifying parent row after native literal resolution. The sampled P2 step still matched exactly, but m20 process peak RSS grew 1.572×, so the alternate transport is **not** its default.

**Reference interface qualification (CPU only).** The [API tests](../tests/test_memory_program.py) exercise chosen-only batching, model-issued dispatch, typed equality vs learned compatibility, multi-stage joins, noncontiguous composed keys, future credit to the writer and policy, and refusal rather than hidden truncation. Scripted bytecode is used as an executor oracle in some tests, **not** to supply actions to the trainer. There are separate gradient tests of an actual greedy mount switch after one sampled byte loss, of opcode choice, and of which fields to equate given the join. These are software checks, not a learned language result.

A [native integration check](../experiments/expressivity_tasks/x47_xsa_attention/memory_program_check.py) uses the frozen C14 Transformer, a warm P100 branch reader and separate live native sessions, only on prefixes of the first two already verified **training** windows. It checks the initialized program and full-byte probability parity against independent native suffix-ID frames. At local source `0d9cbd649`, the initialized policy issued 32 direct lookups on 32 predictions and agreed with the oracle to **1.20e−7** max absolute byte-probability error. The chosen archive adapter fetched 25 pages in 15 page batches (the separate parity oracle is not included). Live sessions advanced only with actual observations; this check did not learn or issue joins. [Native receipt](../experiments/expressivity_tasks/x47_xsa_attention/receipts/memory-program/native.json); [15 platform + 19 regression tests passed](../experiments/expressivity_tasks/x47_xsa_attention/receipts/memory-program/qualification.txt). No GPU run, new development panel, or confirmation access.

Recheck locally on CPU (`OMP_NUM_THREADS=4 CUDA_VISIBLE_DEVICES=''`): `.venv/bin/python -m pytest -q tests/test_memory_program.py` and `.venv/bin/python -m experiments.expressivity_tasks.x47_xsa_attention.memory_program_check`. Only the second requires the registered local mounts, binaries, checkpoint and training shard.

**First sampled training profile, not a quality comparison.** [Measured batch and scale veto](../experiments/expressivity_tasks/x47_xsa_attention/RESULT_MEMORY_PROGRAM_PROFILE.md): 512 natural training targets, 56 writes, 85 nonempty recalls from earlier bytes, 31 nonempty equality joins. The model obtained occurrence spans but did not use them as addresses of successful value reads in this batch. One full update took 10.24 s (~50 targets/s); no dev run at this price.

The next natural-text comparison is **one platform with different policies**: initialized direct program frozen vs trainable, with the same mounts, byte LM, row/round budget, windows, all-byte loss and measured work. Log actual decisions and operands before and after training. Replay their requests, freeze or reassign operands, disable writes/joins independently, and compare the best cheap direct policy. A different gate value or more joins is not success. Success is a *changed executed memory program* that improves held-out prediction for its cost. Fixed-trace parity now qualifies the packed path on the tested workloads, including credit across writes. Do not open a fresh quality panel until the full comparison fits at measured dynamic-training rates.
