# Retrieved passages as states and state transformations

**Question:** On the *same retrieved passages*, is it more useful for a language model to ask “what did these passages encode?” or “what would they do to a copy of my current memory?”

**Recommendation:** Start in an actual token model, with one frozen host, one auxiliary recurrent head, one lookup per question, and a task with known supporting passages. Find out first whether the host benefits from the right text. Then hold retrieval fixed and change only what the passages return. Do **not** start by building a large token index, training two backbones or running a grid of mixtures.

**Status:** Research design and an executable CPU algebra check. Not a natural-data registration, checkpoint admission, resource authorization or neural quality result. [X53](../experiments/expressivity_tasks/x53_token_spelling/RESULT.md) showed that token alternatives improved a *byte count reader* over their first-byte projection; their contextual preferences added .04026 nats/byte over a general spelling dictionary. That is a reason to study richer values, not an effect-size forecast for a pretrained token LM.

## The interface: find text, compute a hint, keep the actual history

1. **Address.** From the visible prompt, a search program returns `(source/version, document, span, mass)` records and coverage information. A span is a verified range of tokens *and* source bytes, not an anonymous suffix-node number. Exact suffixes, gapped anchors, soft alignment and later a semantic retriever can all return these records. For example, `pump stopped` and `firmware update` can point to the same incident report despite intervening edits. A rare exact match is useful evidence; matching the entire suffix need not be a condition for relevance. The [token suffix reference](../experiments/expressivity_tasks/token_suffix_fanout/README.md) gives counts and continuation handles, **not** occurrence-specific passage states.
2. **Value.** Independently encode the *surrounding passage*, not just the matching phrase. For hit `i`, the head defines a function `F_i(S)` of its incoming memory. A **stored state** is `B_i = F_i(0)`. A **seeded effect** is `F_i(S*)`, where `S*` is derived from the live prompt. Search need not know which field of that memory the host will read. Changing the search changes the evidence distribution, not this interface.
3. **Merge.** Normalize nonnegative masses to `p_i` over eligible hits. Predict from the actual host as usual, but offer a gated extra vector at its residual stream. For example, at the end of the prompt take one seed `S* = Seed(h_prompt)`. Keep the resulting side memory while answering. At each answer frontier let `q_t = Query(h_t)` ask a different question of it: `hint_t = Σ_i p_i Read(q_t, F_i(S*))`. Add `gate(h_t, support) × W_out hint_t` just before the frozen token output head. `h_t` sees the real prompt and actual preceding answer tokens. The retrieved paragraphs are neither generated tokens nor extra observations in the recurrent host's history. No hit means an exactly zero hint. An immutable archive may supply text after the matched location; a live source stops at the observed prefix. Neither can consult a future target to choose the location. A later model could save a hint on its work tape or use it to issue another query; neither is needed to test the first read.

Keep support, returned mass and truncation status separate from the normalized hint. Four retained hits are not “all corpus occurrences.” If a hard top-k changes, immutable summaries can still be reused, but the reduction is exact only for the declared returned set and weights. Where a kernel decomposes into weighted interval memberships, cached interval sums can implement that particular reduction; arbitrary learned reranking or deduplication is not free.

### What is exact, and for which head?

For one GDN‑2 head with fixed passage-derived keys, erase/write gates and decay, the token update is affine in `S`:

```text
D = diag(decay); r = erase ⊙ key; u = write_gate ⊙ value
S' = (I − key rᵀ) D S + key uᵀ
```

A whole span is `F_i(S) = A_i S + B_i`. In time order, **later after earlier** composes as `(A₂ A₁, A₂ B₁ + B₂)`. Across **alternative hits** we sum, not compose: for a common seed and weights, `M = (Σ p_i A_i) S* + Σ p_i B_i`. With a linear head read, `q_tᵀ M` equals the weighted sum of the individual reads. Two passages can write exactly the same `B` yet erase different rows of incoming memory; only a nonzero seed exposes the difference. This is the extra capability worth testing.

This identity concerns the recurrence core, **not the whole LM**. Compute passage controls with pinned encoder weights, tokenization, span reset/left context and convolution initialization; they must not be recomputed as a function of the live seed. Apply nonlinear output gates/norms at the specified place: pooling before a per-hit nonlinearity generally changes the answer. For [nonlinear Emender E97 split-edit](../ndm/models/e97.py), explicitly replay each passage from a copy of the seed, read each result and then mix the outputs. Do not relabel a nonlinear E97 checkpoint as affine. An **identity-state** linear variant has its own [scan implementation](../ndm/models/e88_fla_hybrid.py) and must be checked against *its* gate/decay conventions. Likewise, [routed Emender edits](../experiments/expressivity_tasks/x45_matrix_emender/scan.py) with decisions that depend on incoming memory cannot silently reuse a route taken from zero. Distinguish the named model/config in every comparison.

## Experiment sequence

### 0. Check the algebra before training anything

Run from the repository root on the local CPU:

```sh
env CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  .venv/bin/python -m pytest -q experiments/expressivity_tasks/retrieved_span_effects/test_affine.py
```

The [reference](../experiments/expressivity_tasks/retrieved_span_effects/affine.py) composes maps. The [tests](../experiments/expressivity_tasks/retrieved_span_effects/test_affine.py) independently replay rank-one updates from multiple live seeds. They check FP64/FP32 outputs and first derivatives, unequal lengths and duplicate hits, temporal composition order, zero support vs an identity span, the equal-`B`/different-`A` example and a saturating counterexample. **Local check: 5 tests passed on CPU.** This checks algebra on invented token IDs, not production kernel parity, useful language representations or speed.

Next, extract the actual control tensors from one named head on invented token prefixes. Compare compiled vs sequential **production** state/read and bridge gradients, including resets, the real precision, short convolution, normalization and terminal positions. Changing the live seed must not change the recorded controls. Verify an empty source gives bit-identical base logits and exploring a hit never mutates the live state. If parity fails, keep explicit replay as the reference and fix the discrepancy before interpreting a merged run.

### 1. Admit one tokenized host and one answerable task

- Pick the smallest **competent, already trained** token LM for which we can reproduce no-hint logits, read a hidden activation and inject a residual. Prefer a token GDN‑2 or E97 checkpoint if available; record weight/config/code hashes, tokenizer vocabulary/merges, special-token behavior, state activation and reset convention. A model name, tokenizer file, throughput smoke or logits-only serving binary is not that admission. The repository has [p50k_base GDN‑2 geometry](repro/lb_gdn2_mlp_20260612/anchors_gdn2_mlp.json) and [E97 token-inference configuration](../configs/pi/e97-e1-chat-probe-panel-v1.json); these are leads for inventory, not weights or permission to use that panel. No second full model is required: the auxiliary reader can be a single head. If only a different frozen token host is usable, label the result as a reader test on that host, not an E97/GDN‑2 host comparison.
- Use an approved evidence-annotated QA collection. **One concrete candidate is QASPER:** papers are source documents, questions are queries, annotated paragraphs supply support labels. For a pilot, use answerable short-answer questions with an annotated supporting paragraph under a preregistered inclusion/reference rule. Keep the scope honest: this doesn't test long synthesis or unanswerables. Supply topic/paper scope to every arm equally or to none. For a subject with no suitable licensed collection, assemble versioned manuals and independently authored questions with source citations first; don't turn random next-token windows into a purported QA test.
- Split **by paper/manual family**, not question or chunk. Keep FIT, design/dev and locked evaluation families distinct; hash/version sources and check near-duplicate passages/questions across roles. The evaluation archive intentionally contains the evidence for its questions, **never QA records, model answers or gold support annotations**. Only passage text goes through the archive encoder. Freeze providers, bridges, retrieval recipe and scoring before opening evaluation questions. Gold is for a separately labeled diagnostic, never a production address. A pretrained host may already know public facts: compare paired no-source and wrong-source answers. Respect collection scope before matching or aggregation.
- Pin the host tokenizer and use document-local token spans with byte offsets. Encode the prompt without the answer; lock the prompt/answer boundary (including separators and special tokens) so a tokenizer merge cannot smuggle answer bytes into the query. Use the same tokenizer across hosts for direct token-NLL comparisons. This is a **separate token-native proposal**; don't feed token IDs to C14 byte training or reopen X49–X53 spent cohorts. Any reuse of the Pile lineage needs fresh reservation/exclusions through both X53 roles. No P100 retokenization is required.

### 2. Calibrate the task and the search with ordinary text

A concrete starting geometry for a meter: split approved archive paragraphs into spans of up to **64 native tokens**, truncated at the document boundary. Build an in-memory positional postings index with stable span IDs. Query **once at the end of the question**, not on boilerplate answer delimiters. Return up to **four** positive-scoring spans, never pad misses with fake hits. This makes a literal evidence arm at most 256 tokens and makes explicit replay affordable to price. These are pilot sizes, not architectural limits; lock the choice after the cost meter and before measuring held-out quality.

Use this small ladder with the same frozen host and evidence formatting:

| Input beyond the real question | What the comparison diagnoses |
|---|---|
| Nothing; and length-matched irrelevant passages | Host knowledge and the effect of extra text alone |
| Annotated support as literal evidence | Can this host use the right text? A diagnostic, not a deployable reader or mathematical upper bound |
| Literal passages from the longest matching token suffix | Literal-address baseline; report fallback depth and misses |
| Literal passages from several anchors | Robust-address alternative, same candidate/span/token allowance |

For an implementable anchor baseline, use distinct 1–3 token grams of the **visible question**, weighted by archive inverse document frequency. Let matches vote for a span; add a fixed bonus for two nonoverlapping anchors in query order. Do not require every anchor to match. Pin stopword/boilerplate handling, score-to-mass rule, tie breaks, duplicate handling, hit cap and same-document clipping on FIT/dev. Log actual postings visited and evidence tokens. Add paired paraphrases written without changing entity, negation or answer; group them with the original for inference. Report support recall in the *returned tokens*, not merely whether the right paper was found.

**Decision:** if even known evidence doesn't improve answers, address the host, context formatting or task before optimizing search. If known evidence helps but retrieved text doesn't, address recall/ranking; test semantic candidate generation specifically on low lexical overlap. If retrieved text helps, lock the retriever and proceed. This spends no training on a sophisticated reader whose inputs are useless.

### 3. Test states against transformations on the very same hits

For the first value trial, save a private hit receipt per question: query frontier, versioned span IDs/offsets, scores, normalized masses and mask. Replay that **identical** receipt across all value arms. On locked evaluation, generate it from the prompt only, after all fits are frozen. Keep the host weights and base-token stream fixed. Use one small matrix head (e.g. `d_k=d_v=32` for a new auxiliary head) and one insertion point. If an identified pretrained GDN‑2 head is available, its frozen controls and actual dimensions are the cheapest scientific starting point. Verify that the zero-seeded reader can extract something from known-support passages on FIT/dev. For a small bridge, start with `z = down(h_prompt)`, `S* = left(z) right(z)ᵀ` (one outer product), a linear query from the current host state and a projected, gated output. This avoids learning a full `host_width → d_k*d_v` projection from a few hundred answers. A compatible native host head state is a later seed ablation, not a prerequisite. Do not infer a limitation of the idea from a random, unreadable frozen matrix.

If there is no suitable pretrained **value head**, train a standalone small head from frozen token embeddings on FIT: keys, gates, values from passage embeddings; seed/query from frozen host activations; answer-token NLL through the hint. Use both zero-seeded and live-seeded reads in a balanced FIT objective so both modes see the same FIT examples. Recompute selected passage encodings whenever head weights change. Then freeze the common provider; fit equal-width bridges for each comparison on the same FIT-only examples and order. Choose optimization settings/dose on dev only. No per-checkpoint reuse of old learned states or maps. Bind the saved passage sidecar to encoder, tokenizer, precision, reset rule and source hashes. An archive later admitted for evaluation is *encoded*, not used to update weights.

| Arm | Returned value at fixed hits | What would a win establish? |
|---|---|---|
| HOST | No archive value; allow a parameter-matched host-only residual/seed path and the same support metadata | Stops an extra local adapter or match count masquerading as passage information |
| STATE | `Σ p_i B_i` from zero; same host-conditioned query | Does a stored passage state help over HOST and unrelated values? |
| NEUTRAL-A | Same true `B_i`; replace `A_i` by an archive/FIT-only mean transition matched by span length; same live seed, query and gate | Controls access to the extra live-state pathway without knowing the actual passage's transition |
| EFFECT | `Σ p_i (A_i S* + B_i)` | Primary: does the specific retrieved transformation beat NEUTRAL-A **and** STATE? |
| TEXT | The same spans as ordinary labeled evidence, with original question preserved | Is the hint worth using relative to reading text, including cost? Not the same compute |

Use the same usable host-only path and adapter budget in the fitted value arms. At frozen EFFECT weights additionally replace **only A** with unrelated, length-/support-matched donor maps, leaving true `B`, weights and seed unchanged. Also try unrelated whole values with the same hit metadata. Pin donors without labels and disclose donor coverage; merely reordering equal-weight hits leaves a linear sum unchanged and is not an intervention. Compare both fixed-weight reliance and separately trained controls. In this linear readout one cannot infer binding between a particular `A_i` and `B_i` beyond their two weighted sums.

### 4. Cross the families, then try a mix

First compare GDN‑2 and E97 **readers on one host**, using the same hits, value-training opportunity, total hint width and byte/compute accounting. For nonlinear E97 the exact seeded arm is explicit per-hit replay from the prompt seed. If a Jacobian or other local linearization is later proposed, measure its error against that replay as seed magnitude and passage length vary; call it an approximation. Next put the better reader on the other verified token host. Only then fill in the fourth host × reader cell. Compare improvements relative to each host's own no-hint baseline; unrelated pretraining is not a controlled architecture comparison.

A mixed reader searches **once** and returns both answers. Give each a projection into the host residual space and an independent gate that can decline it. Never average unaligned E97 and GDN‑2 hidden matrices. Compare E-only, G-only and dual against a widened best single reader with matched total width/parameters and an actual matched-cost point; mask each channel at fixed weights. Advance a mix only if it earns something beyond the better single reader, not merely because both gates are active. Mixing **searches** is a different experiment: hold the winning reader fixed, vary which spans are returned, and compare one route vs multiple routes at the same searchable scope and evidence budget. If conflicting results cancel in one weighted mean, try separate summaries per anchor or source before enlarging the host.

## Measurement and next decision

- **Before the natural trial:** run the real geometry on invented/FIT-only inputs. Time search, span fetch, archive encoding/compilation, per-query reduction, host prefill, teacher-forced scoring, backward/update and serial decode separately. Record cache hits, bytes copied, peak host/device memory and index-build amortization. A frozen final-layer bridge can reuse private host features from identical inputs and weights during fitting; that is not the price of deployment.
- **Storage sanity check:** one FP32 `32×32` state costs 4 KiB; `A+B` costs 8 KiB. Ten thousand spans × one head is about 39 vs 78 MiB before indexing. Four uncompressed `(A,B)` pairs are **32 KiB**, versus **1 KiB** for four 64-token passages of 32-bit IDs. Compiling helps only if reuse, local reduction or saved host processing pays for it. Start with per-span sidecars or on-demand encoding, not one matrix per occurrence in 100 GB. Compare explicit batched replay, cached states, cached maps and server-side reduction returning a single hint; include all resident weights and the cost of moving the seed/query.
- **Dose:** a planning example is a few hundred FIT questions and a few hundred evaluation questions across distinct families, not millions of pretraining steps. Meter `questions × hits × span length × head count` and total answered tokens first. Use FIT/dev between-family variation and the measured tradeoff to pick a meaningful resolution and freeze the sample size, seeds, dose, gate, compute authority and stop rule *before* evaluation. If the feasible interval is too wide, call it a feasibility study, not proof of equality. No GPU/remote run, archive reservation, new final or retry is authorized by this document.
- **Primary quality metric:** paired total answer-token NLL difference divided by total real answer tokens; all questions, including misses. Also report free-answer task score (predeclared normalization/reference policy), support recall, metrics on paraphrases, and end-to-end time per answered question. For a byte comparison additionally report canonical sequence NLL per original answer byte, not an online byte predictor claim. Use paired whole-family bootstrap intervals, resampling all associated questions/paraphrases together and recomputing denominators; report training-seed signs if bridges are fitted. Keep exact-token/passage-copy cases visible. No selecting the best seed, queries, or hit-only subset. Price a faster but worse reader as a tradeoff; don't infer noninferiority from a null.
- **First experiment worth running beyond the oracle:** bind **one token checkpoint + tokenizer + hidden-state seam**, then compare **no evidence / wrong text / known-support text / retrieved text** on a fresh registered development panel. If that works, the first *neural* result to seek is **EFFECT vs NEUTRAL-A vs STATE on fixed hits**, with wrong-A substitution at frozen weights. For example, preregister a directional claim only if the paired lower bounds against both controls are positive, fitted seeds agree in direction, and disrupting `A` at fixed weights costs loss. Otherwise report which contrast failed; parity, attention movement and a live seed alone are not evidence for a useful span effect. Only a useful, affordable effect earns the architecture crossover or more elaborate search programs.
