# Retrieved passages as states and state transformations

**Train the token model and the passage reader together.** The live model learns what to ask, the search kernel finds and weights text, and the reader learns what to return. The empirical question is whether giving them that opportunity improves predictions on unseen text, relative to models that get the **same training opportunity**. Starting from a pretrained checkpoint is useful; freezing it is not part of the mechanism.

There are two different claims to test: **(1)** a learned passage state helps compared with having no passage; **(2)** a passage-specific transformation of the live memory helps beyond reading a stored state. The first can hold without the second. Neither requires a win for a frozen-host adapter first.

**Status.** Changing the facts in an [invented manual](../experiments/expressivity_tasks/retrieved_span_effects/JOINT_RESULT.md) changed the fitted models' answers on 4,096/4,096 queries with the prompts unchanged. Both blank-start and live-seeded readers solved it. The [Triton device check](../experiments/expressivity_tasks/retrieved_span_effects/TRITON_METER_RESULT.md) and [full token-LM step meter](../experiments/expressivity_tasks/retrieved_span_effects/TOKEN_STEP_METER_RESULT.md) qualified a [registered natural-text comparison](../experiments/expressivity_tasks/retrieved_span_effects/NATURAL_PROTOCOL.md) with fresh small GDN‑2/E97 host and reader cores. The [closed natural panel](../experiments/expressivity_tasks/retrieved_span_effects/NATURAL_RESULT.md) found that all 14 passage readers lost to their same-host LOCAL comparator on 1,101,793 fresh probe tokens, at equal dose and at the time checkpoint. Rotating only the seeded GDN‑2 residual cost a small but nonzero amount; the primary conjunction did not pass. This is a four-page reader result, not a test of exhaustive corpus attention. [X53](../experiments/expressivity_tasks/x53_token_spelling/RESULT.md) measured spelling in a byte count reader, not this neural architecture.

## Full-corpus attention is the target; MEMs and extensions are an access path

[Corpus attention, with optional local memory](../experiments/expressivity_tasks/retrieved_span_effects/CORPUS_ATTENTION.md) defines the reference: the current query weights **all** eligible memory rows. Each source returns its normalizing mass as well as its value read, so local and external rows can compete in one attention distribution. The [runnable corpus head](../experiments/expressivity_tasks/retrieved_span_effects/corpus_kernel/README.md) implements this for static values: exact scores on proposed rows plus a positive approximation for every other row, with a CPU oracle and Triton kernels. The [GPU meters](../experiments/expressivity_tasks/retrieved_span_effects/CORPUS_DEVICE_RESULT.md) separate fixed-bank read speed, full update cost, and the blocked all-frontier timing attempt. A MEM need not be a hard eligibility filter for a learned semantic score. The following exact lexical rule is one reference and a way to propose useful rows; it does not by itself approximate an arbitrary dense attention head.

The retrieval object is **not a list of four pages**. Its question at time `t` is **what comes after the actual prefix `x[1:t]`?** Distinguish where evidence can be found from where the answer must align. For direct next-token votes, use maximal exact matches (MEMs) ending **at the live frontier**; an informative internal MEM can help choose or weight the relevant occurrences, but the token after that internal phrase is not automatically a candidate for the next live token.

One exact reference law: for each position `j` in each reference document, let `L_j` be the length of the longest suffix of `x[1:t]` matching a span ending at `j`. Each endpoint with `L_j > 0` and a real same-document successor contributes once to its first branch, `c[j+1]`, with nonnegative weight `w_j` based on match length, specificity and the current query. Sum by token and normalize; account for document ends separately and fall back to the local LM on no token support. This keeps shorter matches at *other* endpoints rather than keeping only the globally longest match, or repeatedly voting the same endpoint for every nested suffix. Longer corpus extensions remain available behind each branch. This is a reference retrieval distribution, not a requirement that the host literally copy an archive token.

For instance, in “For the ZX-3 pump, set the pressure to …”, `set the pressure to` aligns a corpus successor to the missing token. The earlier `ZX-3` can upweight matching passages about the right pump; the word after `ZX-3` in a manual does not get a direct vote for the pressure. An internal occurrence that already disagrees with the observed intervening text cannot be made exact by just shifting its cursor forward. Use it as evidence for the live query, or specify an explicit gapped alignment that lands at the frontier. Learn relevance from causal next-token loss, never by looking at the missing token when routing.

For example, if one matched phrase occurs 1,000 times and has 30 distinct next tokens, the kernel starts with **all 30 branches and their occurrence counts** (plus any document ends). It can represent each branch by a handle to its occurrences and expose its next fork without sending 1,000 passages to the model. The host can query a weighted distribution of extensions or their learned states/effects. Following an archive branch does not append it to the live prefix.

Define the full answer before choosing how to compute it: specify how to weight match position, length, occurrences and extension paths, how overlapping MEMs contribute, and how mass stops or is distributed across depths. Share work over identical prefixes; collapse occurrences by count only when their weights and values permit it. Distinct occurrence-specific neural values cannot in general be recovered from a histogram. A work budget may limit expansion or approximate the weighted answer, but it is **not** the definition of the kernel. Report retained/omitted mass when known, or mark the remainder unknown. The [token fanout oracle](../experiments/expressivity_tasks/token_suffix_fanout/README.md) illustrates exact branch handles; it does not find all MEM alignments. The [registered panel](../experiments/expressivity_tasks/retrieved_span_effects/NATURAL_PROTOCOL.md) votes on 1–3-grams and returns up to four 32-token pages: a controlled reader test, **not** an implementation or test of the full retrieval kernel.

## What the host can learn

Suppose the observed text mentions a pump, a restart, and a recent firmware change. Those three anchors can vote for an incident report even if the exact suffix of the prompt never appeared in it. Return the **surrounding passage**, not just the matched words or their immediate followers. The same passage might answer “which component?” at one frontier and “what changed?” at the next.

- **Address.** From the actual prefix, return versioned document/span IDs, weights, retained mass and truncation information. Retrieve fixed document-local token and byte ranges. The [token suffix reference](../experiments/expressivity_tasks/token_suffix_fanout/README.md) has counts and continuation handles; those alone cannot fetch occurrence-specific text. A live source can return only tokens already observed. A separately mounted archive can return text on either side of its match.
- **Value.** Encode each candidate passage independently. A reader starting from blank memory returns `B_i = F_i(0)`. The alternative runs the same passage on a copy of a common live memory `S`, returning `F_i(S)`. For different host and reader families, `S` is a trainable projection into the reader's state space, not a reinterpretation of one model's memory as the other's.
- **Merge.** With normalized nonnegative weights `p_i`, the host receives `r_t = Σ p_i Read(q_t, F_i(S))`. `S` can come from the last lookup frontier, and `q_t` from the current causal host state. Pass support separately, so one weak hit doesn't look like strong consensus. No hits means zero hint. Insert the projected hint through a learned gate, preferably before a subsequent trainable host block so it can affect later computation. Retrieved tokens never become tokens in the live transcript. A later query can use a prior hint; start with one read per prompt or a fixed refresh schedule so timing isn't confounded with value.

The [fixed-weight streaming reference](../experiments/expressivity_tasks/token_span_serving/README.md) exposes `observe(token_id)`, document-local token **and byte** span handles and an optional bounded passage cache. It demonstrates why a GDN‑2 reader can reuse `(A,B)` but a nonlinear E97 reader can reuse only controls for a new seed. The [serial clock](../experiments/expressivity_tasks/token_span_serving/RESULT.md) prices both cold packet construction and repeat lookups; faster lookup need not mean faster full decoding.

### Fixed within a forward pass does not mean frozen during training

For a GDN‑2 head, with passage-derived controls, one step is

```text
D = diag(decay);  r = erase ⊙ key;  u = write_gate ⊙ value
S' = (I − key rᵀ) D S + key uᵀ .
```

A span therefore acts as `F_i(S) = A_i S + B_i`. Along a passage, *compose in time order*: later after earlier is `(A₂ A₁, A₂ B₁ + B₂)`. Across alternative hits, *average*: `M = (Σ p_i A_i) S + Σ p_i B_i`. For a common linear read, reading `M` once equals pooling the individual answers. Two spans can have the same blank-start write `B` but erase different rows of a nonzero seed. That is the extra information available in principle; the loss may or may not reward preserving it.

The controls must stay the same **when varying the incoming seed** to reuse that passage map. They need not stay constant across optimizer steps. Token loss differentiates through the seed, passage controls, readout and weights. During training just run the selected passages on copies of the live state with autograd: no global matrix index, dense `A` construction or differentiation through file offsets is needed. Encode a repeated span once within a step if gradients are correctly accumulated. Cache raw IDs/locations across steps; do **not** silently use old learned keys, states or maps as if they came from the current encoder. Compile/cache neural summaries for serving once the encoder is fixed, binding each sidecar to weights, tokenizer, span/reset rule and precision.

The compact identity is **not** an identity for the whole stacked LM. Seed-dependent controls, per-hit nonlinear output norms and [routed edits](../experiments/expressivity_tasks/x45_matrix_emender/scan.py) can invalidate it. For [E97 split-edit with nonlinear state](../ndm/models/e97.py), replay on separate copies, read, then pool. A linear-state variant or approximation needs its own comparison against explicit seeded replay. For linear GDN‑2 there are [CPU output and gradient checks](../experiments/expressivity_tasks/retrieved_span_effects/test_affine.py); verify the native implementation's controls, convolution reset, precision and gradients before claiming a compiled speedup. **Explicit replay can be trained without waiting for that optimization.**

## The first natural experiment: joint training

1. **Choose a trainable token host.** Start all arms from the same checkpoint, including a no-passage continuation. Make embeddings, recurrent layers, downstream blocks and token head trainable from the first update, together with the new reader, query, seed projection (if used), scorer (where learned) and merge. No detached live seed, detached archive encoder, or permanently closed gate. Give all arms the same optimizer treatment for inherited vs new parameters. A smaller model trained from the same random initialization in each arm is also a legitimate test of this architecture from scratch; don't read an undertrained small LM as an upper bound. [Token GDN‑2 config](repro/lb_gdn2_mlp_20260612/anchors_gdn2_mlp.json) and [E97 inference config](../configs/pi/e97-e1-chat-probe-panel-v1.json) are leads, not verified trainable weights or permission to reopen an existing panel.
2. **Give the loss a reason to use the archive.** For general language modeling, train and score the next real token at every unmasked target in document-local windows, including retrieval misses. Mount a separate allowed reference collection; the future of the live document is not a retrievable support passage. Also include a separately reported evidence-sensitive condition with known supporting text. One option is a collection of technical questions and versioned manuals, or approved evidence-annotated QASPER questions and papers. There the LM predicts *every answer token*, and the archive intentionally contains supporting documents, not QA records, answer labels or gold citations. Include paraphrases and unhelpful evidence, not only exact copies. Do not require a generic frozen LM to answer from those passages before training. Train a known-support arm by giving it the annotated passage but not its answer label as an input. This separates learning to use evidence from finding it; do not give a deployable address program gold citations.
3. **Pick candidates independently of their values.** A starting provider is an inverted index of token 1–3-grams with inverse document frequency weighting and a bonus for nonoverlapping anchors in order. Record the actual candidate spans, coverage and cost. Compare against longest exact suffix, and later semantic proposals, without redesigning the reader. A useful metering geometry is four spans of up to 64 native tokens; one read per question, or a refresh every 32 real tokens in continuous LM training. The latter means up to **eight passage tokens per live token**, not eight additional full host evaluations: the passage head can be small. These are examples to price, not architectural limits.
4. **Make precise what learns to search.** On a small archive one can score *all* candidates and softmax, so token loss trains the live address query, passage keys and the weights with ordinary backpropagation. At corpus scale, use a fixed high-recall lexical or hybrid proposer, then learn the scores **inside its returned set**. Hard top-k membership and integer posting-list seeks do not acquire gradients just because their results enter the graph. Missing evidence cannot be rescued by the reader. If learning the proposer itself matters, compare a trainable retriever on TRAIN positives/negatives, measure candidate recall and the cost of refreshing learned keys; don't attribute its gains to changing the value. For a narrower value-only comparison, use identical prefix-derived IDs **and masses** while still jointly training both host and reader. In the learned-reranking comparison keep the eligible candidates the same; the learned weights can differ between separately trained arms.
5. **Keep the training step simple.** At a lookup: run the real prefix, form the seed and query, locate spans, encode them with the **current** passage parameters, mix their reads, run the rest of the host and compute causal token cross-entropy. Backpropagate that loss once through the whole neural computation. Don't train on predictions of archive tokens as if they were live targets. Use a small nonzero hint path initially; verify token loss actually gives gradients and parameter changes to the host, reader, scorer and gate on informative examples. Keep a no-hit check against the same host with the branch bypassed. A gate statistic or a nonzero gradient is not a quality metric.

### Which comparisons answer which question?

Run the following as **separately co-trained** models with paired starts, examples, order and number of target tokens. Allocate a comparable usable local computation path to the controls; report parameters and time rather than assuming equal cost. All passage arms can query their values from the live host.

| Arm | Value supplied beyond the live context | Contrast |
|---|---|---|
| LOCAL | No passage content. Match scheduling/support metadata and give the host a trainable local residual path. | Controls for continued LM training and extra local capacity. Also retain the plain continued host's quality/cost. |
| STATE | Weighted blank-start states `B_i`. | STATE vs LOCAL: did learned passage content help? |
| NEUTRAL | True blank-start writes plus a passage-independent transition applied to the **same** live seed, e.g. `B_i + A_len S` with a shared length-conditioned map. | Can extra access to the live state explain EFFECT? Pin the neutral parameterization and count its capacity. |
| EFFECT | True `F_i(S)`, using the same form of seed, query and merge. | EFFECT vs STATE and NEUTRAL: did the passage-specific operator earn its keep after both sides could adapt? |
| TEXT | Same retrieved spans as marked textual evidence; don't count evidence as targets. | Could ordinary passage conditioning do better or cost less? Match evidence allowance; explicitly measure the difference in computation. |

Here “true `B_i`” means *from the specified passage under that arm's current weights*. Co-trained arms share the starting point and data, **not** the fitted representations. To measure **reliance** separately, at a jointly trained EFFECT checkpoint hold its weights, actual prefix, candidate weights and `B_i` fixed and replace **only** `A_i S` with length-/support-matched unrelated contributions evaluated on the same seed. Also mask the hint and separately swap whole passage values. Use genuine changed donors, not a permutation that leaves a weighted sum unchanged. Log donor coverage. Changed loss under an intervention says what that fitted model used, not which training regime is best. A simple linear sum exposes two weighted sums; it cannot establish a separate `A_i`–`B_i` binding within each hit.

A frozen-host adapter can be useful as an optional arm: *can we retrofit this capability without changing existing weights, and at what training cost?* A known-support text read diagnoses search vs host formatting. **A negative in either is not a veto on the joint experiment.** If a co-trained system fails, separate absent support, weak/no credit into the new branch, collapse of the seeded contribution over long spans, and a learned reader that works on informative examples but adds little over a strong LM on ordinary text. Report the failing regime rather than concluding the architecture cannot work.

### Cross the hosts and readers after establishing a usable path

On matched candidate inputs train Emender←Emender, Emender←GDN‑2, GDN‑2←Emender and GDN‑2←GDN‑2. A tractable order is to change readers on one host, then hosts for one reader; unrelated pretraining does not by itself isolate a family effect. A mixed host can search once, ask both reader families and give each answer its own trainable projection and gate. Mix answers, not arbitrary raw matrices. Compare to a widened best single reader at matched total hint width and a measured cost point, and disable each channel at fixed weights. Another independent axis is to vary the **search program** with reader and evidence budget unchanged. There is no need to run the full grid to start joint training.

## Checklist for a natural run, and limits of the current pilot

- **Engineering:** admit one token model/tokenizer and a verified document-local span source; wire the joint forward/backward/update through a named host block. On invented inputs change the evidence with the live prefix fixed, verify gradients against explicit replay as applicable, and check causal masking, document/reset/position boundaries and no-hint logits. Time and size the *actual training step*, not an adapter-only estimate. Measure base and retrieval arms separately: search/fetch, passage forward/backward, host forward/backward, optimizer state, peak memory, and serial decode with/without cached summaries. A four-hit FP32 `32×32` head need not ship four 8 KiB `(A,B)` pairs instead of 1 KiB of token IDs; compute near the archive or replay the raw tokens if that is cheaper.
- **Data and dose:** before fresh natural membership, register roles, permissible evidence, corpus/model hashes, optimization and score rules; review and publish CPU source and invented qualification. Split/deduplicate by document/family across roles, check near-duplicate passages, and bind a real prompt/answer token boundary. For QA keep paraphrases of one source together. For LM never retrieve from a held-out continuation. No C14 byte-model substitution, reused spent roles, or target-dependent query. Use training/development learning curves and the meter to budget enough *joint* updates; a few hundred questions designed to fit a linear bridge aren't presumptively enough to train the whole system. Freeze all fits and index version before locked evaluation. This design does not allocate a GPU or authorize remote training.
- **Read the answer at two prices:** paired nats per real target token, first at equal exposures and also at matched measured training cost, with inference cost reported. Bootstrap by document/family, recomputing denominators; report seed directions and include misses. For QA also report whole-answer quality, recall within returned evidence tokens, paraphrase sensitivity and response time. Report separately (i) learning a useful passage read, (ii) additional value of the seeded transformation, and (iii) benefit relative to literal text at its actual price. A null on one does not settle the others.

The [registered pilot](../experiments/expressivity_tasks/retrieved_span_effects/NATURAL_PROTOCOL.md) covers LOCAL, STATE, NEUTRAL, EFFECT and the fixed-width mixed reader. It does not cover marked TEXT conditioning, semantic proposal learning, evidence-sensitive QA or adaptation of a production checkpoint. For those questions, start the relevant comparisons from matched trainable hosts; no frozen-host win is required.
