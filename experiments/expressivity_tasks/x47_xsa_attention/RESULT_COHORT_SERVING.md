# Batching compute separately from blocking I/O recovers sampled throughput, not every latency gate

The [S2 queue](../../../ndm/memory_program/serving.py) submits chosen immutable I/O and delivers committed responses first, then batches ready controller work by dependency step before batching new byte inputs. It does not wait for all clients or time out a slow key. Two tests distinguish these properties: heterogeneous program lengths **without** I/O use one host batch per byte; a blocked lookup cannot prevent a fast client's **second** response. 59 CPU tests, separate CUDA fixed-program/old-write gradient checks, source `7682afba1`, [preregistration](COHORT_SERVING_PROTOCOL.md) `f8e255a72`.

**Result: do not promote the scheduler unconditionally.** All 13,056 generated bytes across the 24 cells, all per-document action/operand/reader/status traces and logical work matched the registered S1 streams. Counters below sum both blocks (two B1 streams or 32 B16 streams per arm); rates pool complete wall time, client intervals include queueing and first-byte native setup. Triton in all arms.

Sampled B16 cohort used **21%** as many host batches and **27%** as many controller batches as immediate; issued the same programs, delivered **345** bytes while a native positional worker was busy vs 158 immediate and zero barrier. Time inside the serial positional worker was 1.31/1.29/1.36 s cohort/immediate/barrier. Server+native CPU time 8.93/18.82/8.04 core-s and PyTorch peak 42.12/32.73/41.95 MiB. The correct attribution is **2.28× vs fragmented immediate dispatch, 1.05× vs barrier**, not a general 2.28× decoder speedup. Barrier had better typical latency. Direct S1 comparator was a different predictor (1,035 B16 bytes/s).

Greedy B16 cohort/barrier **0.901** meets the 0.90 floor; B1 sampled p99 ratio **0.994** passes. B1 greedy ratio **1.116** exceeds the registered **1.10**, so the conjunctive gate **fails**. Small p99 sample, no retry to fish for a different tail. Keep opt-in; use barrier for the independent host feasibility work, not this failed default. No evidence here about held-out loss, wide-host timing, mixed arrivals or concurrent tenants.
