# A1 result: Triton read and first-order backward work on resident address pages

**Retain this primitive for the mount integration; no end-to-end speed or LM result yet.** `bank_read_triton.py` fuses key/value gathers, log prior plus scaled dot, per-source softmax and vector reduction. One program per `(query,head,source)` row, 1–64 local addresses and 1–128 channels; FP32 accumulation. The VJP recomputes probabilities and scatters duplicate key/value contributions into FP32 buffers. The wrapper is independent of backbone and collection. It requires a previously resolved, validated working set of K/V records. It neither searches the XSA nor creates a controller program. Native adapters must produce the logical-to-device mapping and access policy.

`test_bank_read.py`: 14/14 passed with CUDA on RTX 6000 Ada (sm89), Torch 2.9.1+cu128, Triton 3.5.1. Ten parametrized device checks against FP64 over FP32/BF16 inputs, including empty table/rows, aliasing, singleton, tails and large log-prior differences. Four CPU contract/reference tests including finite-difference gradcheck. Empty handling and gradients to Q/K/V/prior qualified at the registered tolerances; not a bit-identity claim. Kernel inputs/outputs have no corpus-specific vocabulary or layout. This does not test completeness, boundary exclusion or identity of an archive adapter.

Warm median **synchronized wall µs per invocation**; each invocation reprobes the same resident working set. `rows` counts independent query/head/bank reads, **not tokens**. Vectors already on card; no native search, value construction, transport or full language model. Torch SDPA here *includes* its required gather and log-prior mask. SDPA numbers below are the identical FP32 prior version. Full grid (including BF16, shared/contended addresses, native BF16 SDPA with rounded prior, p95 and first-observed calls): [bench.jsonl](receipts/a1-attempt2/bench.jsonl).

| FP32 random page / mode | Triton | eager Torch | gather + Torch SDPA |
|---|---:|---:|---:|
| 1 row × 8 candidates × 64 channels, forward | 102 | 332 | 168 |
| 128 × 32 × 64, forward | 107 | 286 | 172 |
| 2,048 × 64 × 128, forward | 119 | 743 | 501 |
| 2,048 × 64 × 128, forward + all four adjoints | 751 | 1,808 | 1,331 |

At 2,048 rows the FP32 random forward is **4.22×** faster than gather+SDPA; forward+backward **1.77×**. Alias contention affects this operator: on the separate eight-hot-address table the Triton FP32 pair took **1,179 µs** instead of 751 µs. The singleton public wrapper still costs ~0.1 ms. Stream events in the JSON bracket API calls and may include GPU idle time while the host submits: do not call these instruction/kernel times. Repeated warm reads, six shapes/layouts, one card/session; timing is neither a cold-storage estimate nor a scaling law. Backward allocates and zeros the *compact* gradient tables; if providers pass much larger ones, reprice this. This speed test is not against a hand-optimized alternative sparse-attention kernel.
