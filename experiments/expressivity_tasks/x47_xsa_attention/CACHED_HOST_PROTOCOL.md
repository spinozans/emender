# S3 — byte-host cache seam and incremental Transformer attention

X47 ≤393/1800 after [S2](RESULT_COHORT_SERVING.md). Test the host seam **with the barrier**, not promotion of a failed scheduler. Preserve the engine's meaning: a backbone consumes observed bytes; every instruction at a given byte uses the same causal host features. Do not append a scratch token to the large backbone. Establish a checked cache path first on the real frozen C14 weights. A 2M-parameter, 128-position host is not a large-model throughput estimate.

**Seam.** A process-local owner admits a bounded number of exclusive session handles against an explicit tensor-byte cap. Retain per-layer pre-norm projected keys/values and last normalized host/base outputs, byte frontier and admission generation. Prefill actual prompt bytes; one-token queries attend to *all and only* that session's valid prior keys plus itself, using its true learned absolute position. A non-square single-query `is_causal=True` mask is not that mask. No sliding or modulo wrap at capacity, no predicting twice or advancing twice by accident, no values/keys reused across documents or stale handles. Scrub released persistent slots. A reset/re-admission must match a new full prefix. This is logical allocation/erasure inside a trusted process, not a cryptographic or multi-tenant security assertion. Inference-only; no cached training gradients claimed.

**Qualification.** Compare hidden state and all 256 byte log probabilities on CPU and leased CUDA to the existing *full* visible-prefix C14, atol 5e-5 / rtol 2e-5 in FP32, with unequal lengths, order swaps, repeated reads, reset/reuse, capacity edges including 128th byte and rejected byte 129. Negative tests: duplicate/stale/foreign handle, wrong frontier, inadmissible shape or over-budget. Verify no extra host-token work on repeated reads, no padding/token-IDs substituted for bytes. After release assert zero persistent tensor payload; show live/allocated bytes and transient peak separately. Verify before timing; retain failure if tolerance fails, do not widen it after viewing.

**Cells.** Same two registered W3 TRAIN prompt blocks, weights, mounts, RNG, B1 and B16, 32 real prompt bytes + 64 actually emitted bytes/client as S1. Three predictors: fixed direct backoff, P2 step-1 Triton/barrier greedy and sampled. Full-prefix versus incremental host **for each**. Block 0 order direct full/cache, greedy full/cache, sampled full/cache; block 1 reverse. First timed prediction includes prompt host compute for both; next 63 consume one newly observed byte each on cache path. The final delivered byte need not be encoded until the next request. Record all byte and per-stream program digests relative to S1; if a mode differs, no same-work speed claim. Same ordinary reader service and CPU append in both. 24 cells, 13,056 bytes. Expose host calls/token positions, reserved payload and measured PyTorch peak, host submission (nested, not device time), setup, wall and all response intervals. Also time the synchronized **host only** on the same real 32-byte prompts then 63 observed train bytes, without querying memory or generating. Descriptive; not decode throughput. Report actual B1/B16, no extrapolation. No optimizer/held-out/quality, no new data.

**Decision.** Require semantic parity and exact fresh work for paired comparisons, one prefill + one host token per subsequent request, bounded/scrubbed slots. Carry the seam to a separate larger host test if qualified. Do not replace the C14 default unless for **every** predictor B16 throughput is ≥1.10× and B1 p99 ≤1.10× full. Tiny host improvement is neither necessary nor sufficient for making a 150M or larger host fast. ≤200 additional inclusive card-s across attempts. Detached owner, watcher of service progress/release, GPU 0/1 only, CPU tests/source freeze as before.
