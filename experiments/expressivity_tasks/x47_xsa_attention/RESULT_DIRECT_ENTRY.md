# T11: queued entries sped up gradients even with trained direct retrieval on bypassed bytes

**Use the queue for this teacher-forced DIRECT/ENTER predictor on the registered B32 fixture.** Mean complete forward/backward wall fell from **4.706 to 3.296 s (.700×, 1.43× faster)**. The queue waited for more *already chosen* workbench entries; it didn't skip the direct computation on other bytes. Gate decisions, program instructions/operands, ordered register bindings, direct evidence, work charged to each frontier, and all predicted argmax bytes matched. This is not a comparison to dense P2 at equal quality, nor a recommendation to make a live client wait.

**Which computation earned credit.** [`DirectEntryProgram`](../../../ndm/memory_program/direct_entry.py) starts with T2's host-only 257-parameter gate at 1/16, the reproduced **post-T9** 17,604-parameter direct head, and the 288,987-parameter step-1 P2 workbench. All three were differentiable; the retained T4 bytewise host packet was frozen. DIRECT runs the four-expert trust head and neither reads nor mutates program cells. ENTER runs the full sampled program on the original host scores, without fetching a direct backoff or evaluating its trust head. Both paths observed the actual next byte only after scoring. The loss prices every chosen direct probe or program key and every non-emit program instruction; the gate and conditional sampled decisions receive full subsequent within-document costs. A synthetic delayed recall after a direct gap still backpropagated into the earlier writer. The live interface uses only the current frontier, with no gate-mask argument.

**Same logical work, different batching.** Each cell executed **3,848 DIRECT and 248 ENTER** decisions. The gate positions matched T2 because its initial weights are zero, not because later weights will preserve that rate. The queue held an unresolved ENTER at its own watermark until eight were ready or no DIRECT could proceed (545 held stream-ticks). Directs made 5,275 logical probes: 3,848 selected, 1,421 unavailable, six absent. ENTERs requested 175 keys and performed 40 SAVEs, 14 RECALLs, 34 JOINs and 33 RELATEs. Occurrence service certified five over cap; three actual native raw searches (80 ranks) were also over cap. **No positive LF walks here.** Both clocks made all 4,128 live append calls. There were 80 live branch and seven live locate RPCs; 16 live value reads / 120 bytes. The 32 private live workers added ~111 MiB in summed per-process high-water marks, separate from the main, m20 and positional workers.

One fully checked m20 process/cell; independent cold 256-page caches for terminal direct queries and reference program traversal. Byte-code choices weren't priced by assuming a cache hit. Both sent 5,256 `S` frames (37,140 literal bytes). Indexed vs queued `R` frames/rows: **595/4,637 vs 679/4,639**; 15,555,399 vs 15,561,987 total wire bytes including the handshake. The speedup did not come from smaller wire. Actual program reader dispatches changed from 169 to 157. Worst main, m20 and positional peak ratios .974/1.000/1.000, all under 1.20. Native work, CPU placement, callbacks and backward were included in gradient wall; prior host feature production and interpreter startup were not.

**Equivalence is numerical *across* schedules, bitwise *within* each.** Per comparison, 1,387,450 FP32 score/return/gradient elements checked. Between clocks 793 byte-score elements differed (max `1.91e−6`); max trust error `5.96e−8`, joint `1.91e−6`, cost-to-go `1.53e−5`. Identical parameter-used masks, nonzero contributions from gate, direct and program; max adjoint error `8.35e−7`. Zero registered violations. Both independent same-clock repeats matched every comparison bit. TRAIN mean NLL 1.609924 and surrogate 30.093376 are diagnostics on one batch, not evidence that the policy learned useful times to enter.
