# S18 — do retired positional/value readers keep whole archive metadata alive?

In S17 the server HWM rose from ~2,406 MiB in cell 1 to ~3,551 MiB in cell 10. The last reading was before interpreter exit, not a post-GC diagnosis. P100 has 16,119,767 int64 starts (128,958,136 B per independently verified descriptor). The existing `ArchiveRecords` owns `SpanValues` containing bound methods back to itself. An exported `Reader` can also retain its callable's environment. Test explicitly retiring those references at mount close, without trusting reference-count/GC timing, an empty cache or a reaped PID as proof of memory release. **CPU only**; no serving-rate/trajectory rerun, learned action, host model, optimizer, quality panel, new binary or new corpus. X47 stays ≤1429/1800. One bounded diagnostic, ≤360 s total in driver, no timing rescue or manual cache drop.

**Candidate boundary.** S15 `p100_domain(..., max_grants=1)` and a fresh `BranchGrant` under the same admitted whole P100 on every wave; no S16 retained image or worker. A scoped positional/value reader owner may open only under the *active grant for the exact supplied descriptor object*, never by matching a source string or copying a version. Fresh text fd and real pinned-build positional process per wave, same raw-8 verifier, same certifying parent, same span-value encoder. Three normal typed endpoints (`occurrences`, `contents`, `following`). Only expose schema and revocable read callbacks to clients, not the underlying descriptor, file, worker, raw callable, or encoder. One synchronous owner PID/thread. Validate before touching native state, including calls with empty/foreign keys; reject changed/expired grant or dead worker and fail closed on ambiguous reads. At close invalidate exported callbacks, verify and close/reap even on failure, and sever references to the backing callbacks, value encoder and descriptor. Retaining a stale public endpoint must not retain a usable reader or the heavy table. This does **not** reclaim values/answers that a caller deliberately keeps, mint authority to arbitrary files, or change S13's threaded positional service. Keep legacy adapter available; a captured raw descriptor/worker is outside the promise. Exercise cleanup with a positive fixture, same-version/different-descriptor and scope refusal before open, wrong owner, stale parent/domain, invalid response/close failures and retained handles. No issuing real reads after revocation.

**Real exerciser: issued capability checks, not learned routes.** Original B2 whole-P100 keys at registered pattern indices 2 and 6 (`x43.../receipts/p100_query_verification/registration.json` SHA `5ea29f13388c3a3b3fc402cb54f41be51c61fdef664707a7f1d6b215e2b0bef1`; `receipts/b2/samples.jsonl` SHA `520c669473b714ad00e92b396d064663efa176d9312f7d8ff65da0d1f153aaba`). As in the existing positive native mount test, request those two keys plus `b' the '` under cap eight on every wave. Require all three positive spans (two plus one) at the original verified positions, and the common-key overcap refusal (never truncate). Fetch contents and up to 16 visible following bytes from the actual returned logical addresses. Validate absolute/document-relative coordinates, no cross-boundary or false END, exact bytes against independent bounded preads, and all encoded values against the specified per-byte mean. Use a fresh, weak-referenceable CPU FP32 diagnostic byte encoder per wave, not an LM forward. Bind both native binaries, input receipts, FD/source/version, complete requests/results/statuses, encoded values and real native ranks/LF work. No raw patterns/text, byte-value arrays or position lists in new git receipts. Charge all opens/handshakes, searches, preads, encoding, closes and checks.

**Four independent processes, one variable.** `ordinary-A,retire-A,retire-B,ordinary-B`, four-thread CUDA-invisible, six sequential full **fresh** verified domains per cell. Ordinary uses the current `ArchiveRecords.close` and its ordinary public Readers, candidate the scoped retirement path. Both use one new real branch and one positional worker and new value encoder per wave, same already-admitted BranchGrant, same positional service and read results. Keep default cyclic GC enabled; **no explicit collection, allocator purge or process restart between the six waves**. Drop every external reference to raw owners/descriptor/encoder/answers after each scope. In waves 1–3 keep NO exported handles; in waves 4–6 intentionally retain just the three public record `Reader`s from each retired wave, identically in both arms. No legacy stale calls. For candidate, probe retained callbacks for *refusal before native work* (no keys); active capability checks exercised separately. No retained `gc.get_referrers()` graphs. After each release sample current RSS and VmHWM and weakrefs to that wave's descriptor, exact starts ndarray and fresh value encoder, including earlier waves. Report GC counts/threshold, fds, clean native exits and checks. After measured wave 6, diagnose once with full GC **while handles remain**, then release them, full GC and sample again. Neither GC is a production fix or part of primary time. This separates ordinary no-handle use, explicit stale-handle pressure, delayed cyclic collection and allocator behavior. It does not recreate S17's GPU interpreter.

**Decision.** Exact equality of all active-operation evidence to independent expected values and between all 24 waves, fresh/fully reaped actor lifetimes, expired candidate handles refused, post-final-GC no retained descriptor/offsets/encoder in either arm. Candidate must have **zero** weakly observed descriptor/starts/encoder objects alive at *every* post-close sample absent manual collection, including while public handles remain. Ordinary held wave 4–6 tables/encoders must still be demonstrably reachable with full GC and those handles retained to attribute a stale-handle contrast. Report unheld waves separately (no requirement that ordinary retains them). For a synchronous footprint recommendation also require that with handles held after diagnostic GC, current RSS is lower by ≥2× the actual starts-table byte size in each matched A/B process contrast; mean whole six-wave wall (including first open through all closes) ≤1.25× ordinary. Record peak native and process RSS separately; do not sum HWMs as simultaneous or attribute all RSS delta to one object. No support for unlimited horizons, positive per-byte program utility, a live service leak or GPU throughput claim.
