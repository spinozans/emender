# S20 — defer the immutable locator, not authority, value reads or the first hit's cost

[S19](RESULT_ONCLOCK_MOUNT.md) opened a new positional process on all 32 waves (typically 118–149 ms native launch; ~208 MiB individual HWM) and issued **zero** raw archive locates. Its image did not pass the on-clock promotion gate. Conversely [S12](RESULT_ARRIVAL_SERVICE.md)'s unrestricted sampled program made real positional reads, including positive LF work. Test whether synchronous scoped records can be mounted and used safely without starting the native locator until its **first actually selected, valid and unresolved positional batch**. Use both these natural service regimes on one real retained 150M host. Not a retry of S19's image comparison. No image at all, no synthetic or supplied locate inside generated traffic. Preregister before code/measurements. One ≤160 inclusive card-second panel under the detached broker, after frozen CPU conformance. X47 ≤1489/1800 (311 left); hard stop 14:50 UTC. No new corpus, external source/driver changes, quality holdouts, optimizer steps or timing retry.

**Two lifetimes, same authority.** Every group gets a full, freshly checked whole-P100 descriptor, new m20 worker + handshake + initially empty reference LRU, one new exclusive branch grant and revocable synchronous record companion. In both modes at admission: validate actual parent/descriptor identity, pin/verify executable and source file identities, open and validate actual text fd. Check pins, m20 liveness, record fd/path, owner PID/thread and expiry on every reader call (even empty/foreign); check locator liveness if one exists. Eager starts exactly one positional-worker process at admission; demand starts none until a chosen `occurrences` call still has eligible keys **after** width/scope and exact parent-histogram over-cap certificates. Use the identical native spawn/handshake and bound executable/index/text in both arms. `contents`/`following` must still serve real in-scope values without a locator. Empty, invalid, certified over-cap, other operations, obtaining a capability, stale/foreign handles and teardown must never trigger startup. Nonempty ambiguous/unmaterialized is not empty: if no exact certificate, use the real worker. Never fabricate `rc=0`/peak/launch duration for a nonexistent PID. Once started, reuse only until this one grant retires. A fault kills the capability; never retry an uncertain start or request. No pooling between waves, prewarm/background start, target/route masks, or borrowing another client's live index.

**Single registered workload.** Same checked rows/prompts as S19, four independently timed FIFO groups of eight descriptors at 0/60/120/180 ms; three replies then cancel the first row of each group, twelve for the other seven. `ByteService`, capacity16/context64, exact step-width cover `(1,4,8,16)` ≤6, demand-private tapes and four CPU threads. All work after actual offers charged per S19, including retired-handle checks, all four domains/companions and cleanup. Prepare the retained FP32 host and its arena once, account separately; no wide build. Eight independent trials (fresh mounts/clients, NOT eight independent model loads). First four use **S17 entry** (frozen T9 direct/P2/BASE–ENTER initial gate seed 7823, program seed 7530; bypass is DIRECT not bare): `eager-A,demand-A,demand-B,eager-B`. Next four use **S12 unconditional, unrestricted sampled P2** (same step-1 policy, seed 7530; no gate, direct call or dummy gate probability), `demand-A,eager-A,eager-B,demand-B`. Compare only within each predictor, not their quality or speed against each other. 8×348 = **2,784 new bytes**, 224 completions/32 cancels, observe every actual response including the last. No closed oracle rerun. Any prior bytes/positions/scores are for post-prediction checks only.

**Evidence before price.** Full frozen CPU suite plus new faults/real F6 tests: no inactive launch, actual contents/following before first locate, exact over-cap certificate vs unknown positive edge, one start on real selected keys, correct byte spans/values, both successor and final revocation, no relaunch after failed birth/death, foreign ownership and pinned binding. For service, exact S17 size-specific entry oracle prefixes; plain P2 exact byte + normalized event prefixes against the two sealed S12 `b16-oracle-fused-sample` cells, no invented entry-gate scores. Additionally, for each predictor all three trials after its first must match its first on observed-prefix/decision and ordered register evidence, all 256 byte scores, joint scores, and the actual trust/gate/conditional scores where applicable (`atol=5e-5, rtol=2e-5`). Verify true group membership, causal host work, native traffic digests, actual chosen unresolved pattern/result/ordered span/row-work hashes and raw/certified refusals, all private appends/watermarks/exits, clean m20/position exits iff started, no dangling authority. Distinguish eager birth before first wave tick from demand birth contained in the actual issuers' first native call and service tick. Independently total calls/keys/ranks/LF/verified spans from requests. Require identical logical/physical query evidence across all four cells within predictor (worker start is not a read); zero locators in no-native demand waves, exactly one in each native wave; **positive LF and verified spans required in plain P2**. Retain counts, clock intervals and digests, not text/arrays/payloads/RNG tables.

**Decision.** Report exact function and start-count gate separately from adoption. For recommending an opt-in demand locator for this sparse-on-clock service, require positive-path conformance above, sparse starts ≤.50× eager and ratios of two-trial means (demand/eager) on first actual offer→final sync release and offer→first p95 both ≤.95. Sparse wave-zero cold first p95 ≤1.10×. Plain program must not simply move cost into an unpriced first lookup: require whole lifecycle and offer→first p95 ≤1.10× each, pooled interresponse p95 ≤1.20×, mean of trial **max tick wall containing actual native request(s)** ≤1.25×. Report absolute cold launch/first-native batch and its full enclosing tick, native/m20 and main current/HWM and device peak, setup, queue/sojourn, core-seconds; max actual locator HWM under plain policy ≤1.20×, and within each router max GPU allocation ≤1.05×. No device/worker peak ratio for an unstarted locator. Missing required work or missed threshold means no promotion; no rounding/tolerance rescue. Not an asynchronous authority, changed general-LM quality, or promise on a different hit distribution.
