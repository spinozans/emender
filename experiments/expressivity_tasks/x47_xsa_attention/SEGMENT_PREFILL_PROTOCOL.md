# S10 — long FP32 prompts using only the native short recurrent operator

S9 couldn't launch the external FP32 chunk kernel (122880 vs 101376 bytes/block). Close S9, don't rerun it with relaxed precision or tuning. Instead define a **streaming recurrent reference**: start empty, apply the unchanged short FP32 host transition to genuine observed bytes in order. This is not a reference to the non-runnable monolithic stock FP32 chunk call. X47 ≤927/1800.

For prompts ≤2048, split a client's real prompt into consecutive pieces of **at most 64**; consume the first as prefill, pass the full recurrent matrix and each of the three conv histories in and out of every later piece with their proper layer, padded by **no** synthetic symbol. One byte graph for all later responses. No additional client slots or context-length-dependent persistent state. Count native invocations and actual input tokens, including prompt work. Never feed later generated bytes back until delivered. Keep direct baseline, CPU workbench and P2 weights unchanged. One opt-in bounded interface. Default short path unchanged. Don't select by which subset of words happened to match.

**CPU:** real adapter + protocol double checks non-divisible segmentation (>2 pieces), states, ragged order, failed/overlong frontier and stale reuse. **Device before panel:** verified 2049-byte TRAIN windows; compare one owned slot prompted with 2048 observed bytes segmented vs a distinct admission receiving a single observed byte then 2047 real one-byte graph steps, compare full final hidden/logp, argmax and each layer's stored recurrence and q/k/v. Independently compare per-document native `past_key_values` (no managed indexing) one byte at a time through at least 129 observations on a second document against the segmented path, incl. the first new token after prefill. Additional 65 and 513 ragged admissions, reordered next byte, release/reuse. Same S4/S9 FP32 tolerances 5e-4/2e-4. No comparison to a nonexistent long FP32 stock result. Fail before panel on state/output/lifetime mismatch; retain partial checks/errors. No changing widths/tolerances after observing outcomes.

**Fresh service:** exact S9 planned traffic, same 32 TRAIN rows (all 2049-byte windows reverified), two blocks B1/B16, 512 prompt + 8 actual responses, direct/CPU greedy/CPU sampled, barrier, 24 cells / 1632 generated bytes. Comparison uses **the same resident 1/16 graph pool**, released/checked between cells: (a) first byte prefill plus 511 one-byte recurrent graph advances on the actual prompt, vs (b) 8 × 64 native recurrent pieces. Both then apply 7 new-byte replays per client before last delivery. No unobserved prefetch. Forward/reverse arm order as S9. Score both output and logical-event digests, prefill tokens and native-call counts. Include prompt preparation in first response, native session creation/initial observed prompt appends in separate setup. Report first vs later intervals, aggregate wall/rates, memory/CPU and per-model topology. Recommend segmented prefill here only if all 6 B/mode groups match byte/event hashes and ≥1.20× throughput vs serial graph input. No requirement that decoder compute *after* first response be any cheaper. ≤175 inclusive card-s, detached 0/1 lease, CPU gate, local-only. No updates/quality tests.
