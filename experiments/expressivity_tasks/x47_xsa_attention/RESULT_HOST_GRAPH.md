# Replay the host, not the program: a measured large-host serving win

**Use a prebuilt single-token graph for the retained FP32 GDN2 host in the tested closed-load envelope.** Leave the small controller, its conditional operands, verified native reads, writes and byte delivery dynamic. B16 speedup vs the same cached-eager host: **6.78× bare, 3.24× direct retrieval, 2.64× greedy program and 1.56× sampled program**. All 8,704 actually emitted bytes and logical-event digests matched S4 and the eager pair. B1 p99 ratios 0.945/1.008/0.642/0.912 all meet the 1.10 limit. Passed [registered gate](HOST_GRAPH_PROTOCOL.md) `1d76b1ef2`; not an SLA or a result about learning.

[Implementation](../../../ndm/memory_program/host_graph.py), measured source `4a90e4cea`. After validating each old frontier, copy current byte IDs and real slot indices into the precompiled single-token host computation. No graph at the prompt or padding inactive clients. A mismatched width uses the counted eager fallback. The graph owns its temporary outputs and returns copies. Private, unadmittable slots pay for neutral capture/warmup and overwriting the private workspace on release without touching surviving sessions. Arena for B16 active plus 16 scrub slots 229.61 MiB (double S4). This is trusted-process logical erasure, not physical/GPU-driver memory sanitization. External kernels unchanged. 69 CPU gates; actual CUDA reorder/width-miss/partial-release/slot-reuse check: over **21.2 million** compared recurrent-state elements plus all short-conv states, hidden/logp errors exactly zero vs same-geometry eager. Full-prefix singleton max hidden/logp errors `4.77e-6/1.15e-5`. Every graph service cell had 1 eager prefill, 31 real graph replays, 0 misses, 1 neutral retirement. No optimizer/held-out reads.

**Remaining costs.** With this host now fast, sampled B16 delivers ~28% of direct throughput and ~10% of bare, not 1,000+ arbitrary-program bytes/s. The subsequent memory instructions and blocking I/O did not become graphable. The per-cell construction benchmark also shows allocated memory increasing by ~9.1 MiB on most fresh arena builds, including eager builds. Each constructed its own warm/capture stream; these observations don't by themselves prove which allocator/stream cache kept the bytes. Do not size a long-lived service by multiplying one slot alone. Test a bounded number of resident graph buckets and repeated admissions, actual memory plateau and orderly shutdown **before scaling that configuration**.
