# S15 — isolate reusable immutable-mount setup, not decode throughput

S14's fresh domain preparation took 2.22–4.61 s per arrival trial versus 0.97–2.64 s from first offer through final release. The clock includes more than a handshake; it does not identify a particular slow check. Test keeping **only** one admitted immutable m20 process and its validated descriptor across four sequential, disjoint client groups. Do not amortize away setup in the primary price, share a prediction/result cache, or reuse any client's state. Use a CPU-only prefix diagnostic, not another GPU run for a native lifecycle question. X47 through S14 ≤1386/1800; S15 uses zero card-seconds. No new corpus/panel, training, holdout, SXGC/driver change, workers outside the local native adapters, or publication.

**Authority.** One trusted owner PID/thread, one explicitly admitted whole P100 version/binary, at most one active grant, finite number of grants. Pin the executable, index, text and both sidecars with read-only file descriptors; compare open-file + path identities (device/inode/size/mtime/ctime), keep the existing binary SHA, descriptor/header/CRC, sidecar SHA and document-boundary checks at native open. Launch the immutable worker on pinned executable/index FDs on Linux. Check liveness and pins on admission, through each grant read (including cache hits), and on return. Reject foreign scope/version, filtered mounts, concurrent, expired and post-close grants without answering. Poison and close on ambiguous native reply/identity drift. A stale reader must not consume a later grant's resources. No claim of hostile OS/code isolation, full 65 GB index content hash, or safe cross-process handoff. Each grant gets a **new** 256-page Python LRU, emptied on return. Registered path is S14's reference `R` traversal, *no `S` requests*. One-shot reference has the same pins/guards and cache policy; only m20+descriptor lifetime changes. Actual positional reader/fd/encoder and private native live clients are fresh per sampled wave, never pooled. Native-side effects/RSS and OS page residency count; no cache purge.

**One bounded diagnostic.** Frozen runnable source + CPU contract/regression tests first (incl. stale warm hit, file replacement/same-size drift, failure cleanup, distinct grants, packet row binding). Use the S14 verified post-T9 CPU `DirectTrust`, original P2 step-1 CPU `PackedMemoryPolicy`, same T4 retained *bytewise* packet and verified 32 TRAIN windows. No grad, eval, strict algorithms, four threads, CUDA invisible. For each of four waves take eight different rows (0–7, 8–15, 16–23, 24–31); bind actual fresh sessions and the full observed input hash/origin to their packet rows. Give the predictor only this frontier's host packet. Score after observing each of the **first 32 real bytes**; before the next prediction append the next actual observed byte, never an oracle memory result. Waves 0/2 use grouped trained direct; 1/3 execute freely sampled full P2 with pattern 16, other P1 limits, action-independent row/step/factor uniforms seed 7530. Argmax recorded for diagnosis, not fed back. These are predictions at known prefixes, **not generated-byte service, executed updates, or NLL evaluation**. No supplied actions, addresses, LF outcomes or extra probes in the timed forward. No model/optimizer update. Verify retired-grant refusal after each wave separately from logical work.

Four fresh CPU subprocesses in order fresh-A, resident-A, resident-B, fresh-B. Reference opens/pins/reaps m20 once per wave (4), resident once for all four (1), no process survives a measured cell. Fresh mode does not mean cleared OS caches. Each cell computes 1,024 full predictions (512 direct, 512 sampled). Total 4,096 computations on 1,024 distinct TRAIN frontiers. Whole diagnostic cap 360 s, no retry to improve rates/gates. Fail closed on any score/evidence drift: compare complete byte vectors, trust weights or joint scores, per-document argmax and logical evidence hashes; sampled decisions/conditional operands/dispatch, per-operation native work incl. LF steps, live counters; actual m20 row IDs/reply digest, frames/rows/bytes per wave exact except one vs four opening handshakes. Retain counts/hashes/timing, not text, query tapes, score arrays or weights. Private packet and head separately verified, no regeneration.

**Decision.** Functional qualification requires exactness, file/lifetime/refusal/reaping and causal work checks. For a resident recommendation on this *four-wave workload* additionally require mean complete domain-through-final-close wall ≤.85× fresh, mean summed native-domain-open wall ≤.60×, worst main and worst m20 worker peak RSS each ≤1.20× fresh. Charge both modes' first opens, final cleanup, positional/live setup + actual read/compute and CPU time. Report per-wave work/service, total lifecycle including interpreter/input preparation/attestation, native peaks, sampled occurrence/LF and release. A timing fail never justifies skipping file verification. An RSS fail isn't a leak diagnosis. No claim about GPU service defaults, unbounded daemon churn, other authority scopes or prediction quality.
