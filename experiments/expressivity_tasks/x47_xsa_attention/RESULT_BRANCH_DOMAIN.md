# S15: reusing the m20 process saved setup time but exceeded the native memory gate

**Keep fresh m20 workers as the default.** One pinned worker across four groups gave exactly the same prefix predictions and reader work as opening four workers. Mean open time fell from **1.208 to 0.284 s** and mean wall from first open through last close from **5.503 to 3.910 s**. But the worst worker high-water mark rose from **261.2 to 370.4 MiB (1.418×; limit 1.20×)**. The one-worker mode is an optional, bounded memory/time trade, not a general service recommendation.

**Exactness.** Each cell ran 32 real, observed TRAIN frontiers on each of 32 disjoint windows. Eight clients per wave, trained T9 direct on waves 0/2; freely sampled step-1 P2 on waves 1/3. Both used the same verified retained T4 bytewise host packet, not an online host call. Across cells, all per-document hashes of the 256-way FP32 scores, four direct trust weights or sampled joint log probabilities, argmaxes and logical evidence agreed. So did the sampled dispatch and actual `R` frame/reply digests. Per cell: 760 direct logical probes, 512 selected, 244 unavailable, four certified absent. The sampled waves ran 300 reader dispatches, 512 EMITs, 67 SAVEs and 64 RECALLs. Fifteen P100 occurrence keys all exceeded the raw cap: 12 certified from m20, three through real positional requests (80 ranks, **zero LF rows/steps**). No claim about improving the expensive positive locate case.

No `S` frames or cross-grant Python cache. Total m20 wire differed only by three 16-byte handshakes: **8,844,008 vs 8,843,960 bytes**. Fresh describes process lifetime, not OS-cache state. The resident worker touched more memory over its four-wave lifetime; VmHWM neither identifies the pages responsible nor demonstrates a leak. The first open was charged in both modes. Do not apply the **.710×** primary wall ratio to interpreter-inclusive time, S14 offer-to-reply throughput, or an arbitrary number of waves.

**Lifetime.** [`BranchDomain`](../../../ndm/memory_program/branch_domain.py) grants one immutable whole-bank reader at a time to a trusted PID/thread. Its [local P100 opener](pinned_branch.py) pins the executable/index/text and both sidecars, validates the descriptor and compares file identities and native liveness on borrow, return and reads (including warm hits). Each grant starts with an empty 256-page LRU and clears it on return. All 16 retired-reader probes refused. Ten m20 workers and 72 separate positional/live workers exited rc=0; none was shared across cells. Direct counts, live clients, program cells and learned numeric values were not lent across waves. This is not an ACL or hostile-process isolation.
