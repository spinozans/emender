# Grouping already chosen workbench entries sped up gradients for a different, sparse predictor

**B32: 1,197 vs 779 all-byte gradient targets/s at the *same* gate draws, byte predictions and executed memory decisions.** A 257-parameter trainable host-only gate chooses BASE or ENTER. BASE returns the host LM, not a trained retrieval head. ENTER runs the full P2 workbench and may write, recall or follow actual pointers. The untrained gate was initialized to a content-independent **1/16** entry probability; 248 of 4,096 positions entered. Reducing contact this way changes the predictor. The valid same-work speedup is **1.536× compact vs per-index for that sparse predictor**, not 1,197 vs historical dense P2 or T1 at equal quality.

[Registered protocol](SPARSE_CLOCK_PROTOCOL.md) `6a44ab36d`, source `49aefb751`, [API](../../../ndm/memory_program/sparse_clock.py). During teacher forcing only the causal host/entry gate can be scored ahead. The compact clock groups each document's *next chosen entry* with other documents' entries even when their visible lengths differ. It appends only intervening already-scored BASE bytes before issuing the next real program. No read, write, gate feature or lookup sees a later observation. Live prediction takes only current causal tensors, has no future-mask input. The trajectory objective includes the gate log probability on **every** byte, conditional op/operand probabilities only on ENTER, exact future losses and work prices. No forced routes in the natural gradient batch. CPU gates (92) include ragged, all/none/mixed, literal singleton decode parity, delayed gradient to old writes across bypasses and checked live lookup watermarks.

The schedule is useful when admission depends only on a causal host state. It is invalid if a future gate reads cells whose values are not yet known. It does not discover a useful policy, guarantee a learned 1/16 rate, or qualify a denser policy at this throughput.
