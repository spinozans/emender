# S9 — does a real chunk prefill hand off to a persistent one-byte graph?

S5–S8's max GDN2 frontier was **64**. T1 ran the BF16 training chunk kernel but never handed its state to decode. A constant-size recurrent store isn't by itself a long-context host. Test actual **FP32 eval** long-prompt→incremental service on the retained 149,855,670-parameter checkpoint. X47 ≤912/1800. No model update, corpus changes, raw window publication, SXGC change, alternate precision, or relaxed parity tolerance. No popularity/quality measurement.

**Opt-in scope:** explicit `chunk_prefill` back end with bounded maximum frontier **2048**; regular short-only back end still refuses >64. Full prompts >64 go through the external layer's normal chunk forward; prefill <=64 and newly delivered one-byte advances use its normal fused recurrent forward. The absolute visible frontier may exceed 64 even though the step length is one. Same 27 recurrent matrices and q/k/v conv states as S4; no concat of documents, cache across clients, m20 as position oracle or periodic state reset. Price actual cold long prefill, no extrapolation of 32-byte clocks.

**Conformance before service.** Real hash-verified W3 TRAIN 2049-byte windows, same 32 selected S7 rows. Check singleton full-prefix oracle on disjoint admissions at lengths [63,65,128,1025,2047], reordered steps at 64/66/129/1026/2048 and crossing 64→65. Check an independent stock-layer cache oracle that uses each stream's native prefill/step in isolation (no managed gather/scatter) against all persistent recurrent **and conv** components at prefill and reordered step. Inspect both kinds of parity: same split + ownership versus stock full recomputation. Require all finite and all argmax equal; atol/rtol 5e-4/2e-4 hidden and logp (as S4), state allclose same thresholds. At limit refuse the next byte without touching a peer; scrub/reuse one slot on another long prompt, stale handle rejected. Retain which comparison failed and its numerical diagnostics. Any conformance failure stops before timing: don't force the native kernels to agree by changing the input precision/tolerance or pretending training-mode output is an FP32 decode oracle.

**If both oracles pass:** same TRAIN blocks/row order as S7, B1 and B16, **512 prompt + 8 actually generated bytes**; two execution arms: full native recomputation and fresh resident 1/16 graph store (built once for all its cells, eager long prefill), real direct, greedy and sampled P2 programs. Small controller CPU as S8 for learned arms; fixed direct archive/live on host's GPU. 24 cells / 1,632 responses, block 0 full then resident per predictor, reverse arms in block 1. Compare per-document output and logical events; no matched-work ratios on divergence. Price long first-response and one-byte interresponse intervals separately as well as inclusive wall/rate, process RSS, GPU peak, exact prefill and step token counts, native and byte-host costs. No assertion that 8 responses characterize tail SLAs. Select as **long-prefix speed default for this load only** if correct work and ≥1.20× bytes/s versus full in each of 6 cells pooled by B and mode; otherwise keep opt-in/unsupported as appropriate. ≤170 additional inclusive card-s across attempts, physical 0/1, detached/independent observation. Time-out or numerical mismatch is a result, not an invitation to change workload.
