# T12 — one verified read for two executions of a fixed-choice, trainable-value control?

T8 recorded an actual frozen set of choices and reissued real requests to train values on the same batch. It did **not** provide a moving-input control for the next batch. T5/T8 cost 99,152 positive LF steps/rollout on 32 rows. S18 measured 1.664 s median native locate for just two positive literals. A fixed selector and its value learner should not need *two* walks for exactly the same issued query at the same frontier under the same authority. Test a one-frontier handoff, not a persistent answer cache or a fixed program chosen by the experimenter. **CPU only**, ≤480 s in one diagnostic driver, no timing rescue. No additional host extraction, quality scoring, alternate seeds, adaptive workload, download, card or new source. X47 ≤1429/1800.

**Interface.** Two distinct train-mode FP32 packed P2 copies: (1) immutable original **selector** samples opcodes and operands from its own states/values and fixed per-document uniforms; (2) **value learner** executes those choices using its *own* neural pages, encoder, pair weights, writes, recalls and byte head. The latter has only the pathwise all-byte NLL objective. Never update selector weights, accumulate their gradients, or use its logits, numeric cell contents, value vectors or gradients as learner inputs. Use gradient-enabled forward arithmetic in both copies as in T8 (T7's no-grad capture was not exact). No entry gate, DIRECT branch, prespecified addresses, supplied joins, score-function update, answer from another document, or next-byte target in either prediction. On batch two, keep the trained value state and AdamW moments, **not** batch-one routes or cells. The original selector must choose afresh from the new observations, regardless of current value weights.

Reference: per disjoint batch do a whole sampled in-band T8 selection/capture under original weights, then checked forced value replay with separate native calls and fresh private sessions. Candidate: synchronous co-licensed selector/value views of *one* fresh private source per document, distinct writable cells. At the current observed byte sample all choices normally, route only actual reads from admitted structural providers, stage only their complete **non-neural** bindings, raw masses or explicit refusal for the matching forced execution, re-encode span text under each model separately. No target, cross-frontier/cross-grant cache or speculative query. Preserve exact per-session chosen request keys, cap, capability identity, watermark, instruction, status, field provenance, order and multiplicities, and the physical coalesced call order. Fail closed on ambiguity, stale authority/watermark, mismatched request or unconsumed record, numeric provider input, over-budget staging or changed/mixed models. One trusted PID/thread, RAII, no serializable tape. Bound at construction and enforce per-frontier physical frames, keys, output rows, raw text/keys and structural evidence; clear staged private data at end of frontier or on fault. Only after both predictions score may the one actual source observe the delivered byte, including the last. Diagnostics may hash decisions; they cannot steer them. The API is for this coupled control, not a cache for arbitrary users/readers.

**Workload.** Four independent strict deterministic, 4-thread CUDA-invisible workers, `separate-A,pair-A,pair-B,separate-B`. Within each: exactly two consecutive updates on disjoint sets of 16 of the 32 registered T4 retained *bytewise* TRAIN windows (rows 0–15 then 16–31, 128 real shifted targets each). Verify source/index/window/packet/encoder/P2 bindings as in T5, use global row IDs and `StreamUniforms` seed 7809. Same causal features in both copies. Empty AdamW at start, LR .002 / weight decay .01 / foreach False / clip 1, one mean-NLL step per batch. Do not share weights, states, sessions, tapes, native caches or moments across experimental cells. One fresh fully attested whole-P100 domain, one grant, one scoped positional reader, reference branch traversal with initially cold 256-page LRU per batch in both schedules. Retain only through the two roles on that batch. Eager private live workers in both arms. Reference opens 16 fresh live workers per role, candidate opens 16 total; reference dispatches/encodes from real providers separately, candidate reads one set of structurally verified results and encodes twice. Use only defined contents/following text fields for the experimental mean-byte encoder; unrecognized schema/value refusal, not a guessed feature. Charge setup and teardown; no warm start/metadata image across batches. Retain transient full-batch tape only in the separate oracle; no public raw texts, positions, scores or tapes.

**Tests and gates before recommending.** Positive synthetic fixture with different encoders, authority/identity/watermark, partial, duplicate/mass, empty/refusal and invalid/over-budget cases; guard a saved value's later gradient and absence of selector gradient. On real workloads compare both selectors and both value learners against separate-A **bit-exactly** using complete hashes: normalized per-doc events/operands, request/results/register evidence, physical-equivalent logical dispatch and observations, all 256 byte scores, all joint log scores, NLL, gradient used masks, every actual preclip adjoint, post-step parameter and AdamW moment/step. Verify value before==selector on the first batch, selector digest unchanged through both, second value initialization/optimizer chain from first; require some different value score on batch two despite identical executed choices, nonzero writer adjoint and an old-write recall, no change of dedicated selector-only weights. Count actual forward sources, staged keys/rows, positive native ranks/LF, appends, copies, backward targets, updates and elapsed/CPU/main+native HWM, separately. Reject on incomplete equivalence/ownership. For resource recommendation require actual positive LF work, pair ≤.55× separate total native LF steps, live opens and append calls in **each** match, and mean two-batch setup-inclusive wall ≤1.10×, worst main/m20/positional HWM ≤1.25×. Report whether whole wall is actually ≥1.10× faster separately. One pass per cell; do not turn a cost failure into a looser speed claim. This is one fixed-execution control's functionality and price at this fixture, not optimization of the learned arm, a held-out win, an SLA or a training campaign.
