# T8: fixed executed routes can train values; changing the route changed predictions at the same weights

**Qualified on the retained 150M host's bytewise features and this strict CPU stack.** Record the discrete program during the actual sampled training forward, before backward or an optimizer step. There is no second selector pass. An independent, initially identical value learner executed the recorded instructions against fresh authorized readers and scored **every byte identically** before its step. After the full update, forcing its *new* tape reproduced its own new live predictions exactly. Forcing the *old* tape instead changed the argmax at **321/4,096** TRAIN positions at those same updated weights. This is an executed-route intervention, **not a held-out gain or evidence the chosen policies beat direct retrieval**.

**Why this is matched.** Same 32 SHA-verified document windows, T4 FP32 host packet, initial P2/empty AdamW, and indexed sample uniforms on fresh rolls. The [in-band recorder](../../../ndm/memory_program/frozen_routes.py) checks the parameter versions through the last committed frontier. It seals only instructions and structural/request digests, not target bytes, probabilities, native answers or learned state. Each forced pass reissues the actual selected keys and checks raw reply mass/order, typed register layout, refusal/empty and per-document events without fixing differentiable payloads. All six forwards had gradients enabled; no inference/grad-mode substitution. Source step matched T5/T7's strict uninstrumented update and all **179** independent reference tensors (scores, pre-clip adjoints, updated weights, AdamW state). T7's separate gradient-disabled capture remains a failed gate; T8 does not identify the kernel responsible for it.

Both exact-replay controls checked **1,052,673** scalars each (all byte scores, all joint scores and all-byte NLL), zero differing bits. The forced update used **only pathwise all-byte NLL**. Thirty parameter tensors received gradients, writer.weight norm **.02487** and its weights changed. The five dedicated opcode/transition/pointer/prior tensors had neither gradient nor change. Shared value representations may train even though they would influence a live selector: the *executed* instructions and operands, not just selector weights, stayed fixed. Under that fixed assignment the value update changed 2,766 byte distributions.

**Sensitivity, not quality.** With the same indexed uniforms before/after the full step, opcode sequences changed on 370 positions, complete instructions (including operands) on **1,742**, nonempty read sequences on **980**, and structural evidence on 1,818. At the same updated full weights, new vs original route changed 1,995 complete byte vectors and 321 argmaxes across all 32 docs. Only **95** positions retained identical entire route history through the current frontier; max byte-score difference there **4.77e−7**, within the registered tolerance. Batch geometry can change floating-point results; differing earlier writes can change later emissions without changing a current opcode. These counts do not show that 321 individual reads were useful or identify a particular join operation. The fixed and full updates optimize different objectives. All losses here are on the repeatedly measured training positions.

**Cost and limits.** In-band source recorded 14,518 instructions while issuing the same 2,165 dispatches as the ordinary update. Removed the duplicate selector rollout and its reads. Historical T7 capture + ordinary step lifetime was 30.474 s vs 15.061 s here, **not a randomized wall-speed comparison**. Source consumed 47.08 process/child core-s during its measured region, value step 37.23. Main-process RSS at measurement ~2.17–2.23 GiB plus ~0.88–0.90 GiB summed native workers' RSS (can include shared pages). Complete diagnostic 71.13 s inside runner, `proc_330c` rc=0 after ~80 s with interpreter startup. Six passes, **24,576 computations on 4,096 distinct positions**, two disposable independent one-step updates, zero host updates, **0 card-s**; X47 ≤1324/1800, **476 s remain**. Not a multi-step frozen-selector run: on *new* windows a comparator would still need an unchanged initial selector to generate its routes independently. No held-out or 2B result.
