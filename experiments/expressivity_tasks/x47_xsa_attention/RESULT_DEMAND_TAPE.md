# S17: build the private native tape on demand for sparse generated-byte clients

**Five of the 32 arrivals needed a native live index.** With the same DIRECT/ENTER predictor, deferring that index until the first chosen live branch or locate reduced private child starts from **32 to 5**, peak simultaneously open from **16 to 2**, and actual acknowledged native appends from **380 to 5** in every arrival trial. All predictions and memory evidence passed the closed-oracle checks. The registered resource and nonregression gates passed at both sizes and both loads. **Only one of four rates improved by 10%.** Recommend the change to save private processes on this workload, not as a universal throughput improvement.

**Which work changed.** The host consumed all 1,024 prompt bytes and 316 subsequent one-byte advances in each arrival trial. Every client observed its own complete prompt and all its committed replies: **1,372 logical bytes**. Eager submitted all 1,372 to private native workers. Demand submitted **177** on five required synchronizations; the remaining **1,195 bytes** were observed in private document state and did not need to be appended to a native index before release. No final catch-up, worker reuse, history truncation or donor session. All 32 live bindings were still real. Sum of private workers' *individual* exit high-water marks was 110.0–110.7 MiB eager vs 17.2–17.4 MiB demand. This is not simultaneous RSS.

**Which model ran.** [`ByteService(entry=EntryReadout(...))`](../../../ndm/memory_program/entry_service.py) placed one real `[B,512]` host packet per tick. The frozen, host-only gate chose 329 trained T9 direct computations and 19 unrestricted sampled step-1 P2 entries among 348 actual arrival replies. No holding an ENTER to fill a training queue. Directs made 503 archive probes (329 selected, 154 unavailable, 20 absent); ENTERs requested 14 keys and ran 45 non-emit instructions. Only the chosen head saw its evidence. Program cells and direct counts had the same private stream lifetime, including across switches. The four live branch RPCs, one positive live locate and one 16-byte live value read were identical in each arrival cell. No P100 positional query or LF walk: the separate positional worker **was** opened and charged (~207–208 MiB). Both predictors used reference P100 traversal in separate initially cold caches, not T10's grouped-training terminal transport. Actual `R` traffic was 6.531–6.556 MB/arrival cell with zero `S` frames.

**Independent checks.** Two closed eager oracles generated 384 bytes/shape (20 ENTERs each). Eight independently sampled arrival cells: 224 clients finished 12 bytes, 32 stopped after byte 3 and their tickets were refused. Every delivered prefix matched the corresponding closed oracle in bytes, sampled decisions, ordered register contents/provenance, direct evidence, prices in keys/instructions, and logical observations. Also compared the full two size oracles. Across those nine comparisons: 811,008 byte scores, 3,168 gate and 3,168 joint scores, 172 conditional program scores and 11,984 trust weights; zero tolerance violations. Largest absolute errors: byte `6.68e−6`, gate zero, joint `9.54e−7`, conditional `4.77e−7`, trust `8.95e−8`. All 212 actual private tape children, ten m20 and ten positional workers exited cleanly. All hosted slots scrubbed, graphs freed on arena close. The synthetic gates additionally covered stale versions/same public origins, malformed native sync or query, and an attempted swap of two clients' direct decisions.

**What is not priced by the rate.** Domain setup was 0.76–1.75 s/cell; setup variability reversed the retained-burst full-lifecycle ordering. Measured service CPU (main and native) ranged 2.55–4.28 core-s/arrival cell; inclusive lifecycle 3.50–5.27. The wide host is a real dense replicated-weight geometry, **not** a separately trained 2B checkpoint. Wide build/verify .343 s, small→CPU .271 s and wide drop/small restore .540 s; graph preparation 1.148/.535 s wide/small. Peak device allocation/reservation 11,356/11,516 MiB. Main-process high-water rose over the ten cells (~2,406 to 3,551 MiB); these are successive cells in **one interpreter** and not arm-specific peak bounds. Closing a pipe is not proof that every Python descriptor became unreachable. No sustained-lifetime result, leak diagnosis, network SLA, or estimate at a higher learned entry rate.
