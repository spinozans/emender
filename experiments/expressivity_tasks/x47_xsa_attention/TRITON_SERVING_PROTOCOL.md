# S1: Triton operand scores and a ready-session serving loop (registered before measurement)

Start `a000f9e7e`, X47 ≤180/1800 card-s. Local, single attended implementation, no training, quality panel, index rebuild, SXGC modification, or publication. The question is whether the *same* program can be served faster. GPU scoring is not verified positional search.

**Change.** Fuse ragged operand embedding/feature gathering, pointer dot and prior into a masked score tile (FP32 Triton; first adjoints for repeated indices). Gather the actual chosen feature for dependent decisions. Keep the packed eager path. Add a bounded local ready loop: one outstanding instruction per session, batch compatible ready policy work, park only waiters on a chosen immutable P100 occurrence read. A single serialized native positional worker may overlap independent frames/bytes on the main GPU thread. Protect the shared m20 transport/cache separately; no learned tensors produced on the I/O thread. No new query, wider cap, skipped refusal, new routing mask or cache of future choices. Commit only on valid EMIT per service session. A provider error is fatal, not an empty page.

**Gates.** Keep P2 suites; CPU tests of real cross-byte progress during a deliberately blocked chosen lookup, batching/duplicate bindings, scoped readers, error and commit boundaries. GPU vs eager fused scores and first gradients (ragged, aliasing, absent second embedding, width tails, singleton); fixed programs incl. reads, join, save, later recall: exact per-session logical events/addresses/bindings/status, log masses, byte and policy scores and pre-clip gradients incl. old value. Use P2 FP32 tolerances (values/logps atol 5e-5, rtol 2e-5; tensor grad error ≤2e-4 + 2e-4 × ref max). Compile/qualification separate from timed serving; report a warm resident operand timing, not as decode speed. Source/tests frozen before device measurement.

**Registered service workload.** Two blocks of 16 SHA-verified W3 TRAIN prompts, first shard rows 0..15 then 16..31. Use only first 32 real bytes of each registered window to open an empty-cell session; all following 64 observations are the system's actual generated bytes (argmax), not hidden continuation text. No quality scores. B1 uses first prompt of each block; B16 uses all. Closed-loop burst of independent clients with no think time, no new arrivals. Same frozen C14 weights in FP32, causal visible-prefix recomputation without KV cache, same P2 packed-B32 step-1 weights/identity, eight admitted reader capabilities and limits. Price both greedy controller and fresh categorical routing stress (one action-independent seeded uniform per document/byte/step/opcode-or-operand factor, inverse CDF; no preselected route). Byte generation remains greedy in both. Stress is not assumed representative of production traffic. Direct cost comparator: C14 plus longest positive P100 8/6/4/2/1/root and live 8/4/2/1 branches, fixed base/archive/live weights 1/2/2 renormalized on availability. No positional or workbench calls for direct; not the W3 trained head or a matched-output arm.

**Cells and verdict.** For B1 and B16 run direct, packed barrier eager, barrier with Triton score, ready with Triton score; both routing modes for program arms. Also ready-inline Triton (same ready loop without I/O offload) for sampled B16 only. Forward order on first block, reversed on second. Fresh sessions/mount-local caches per cell, warm runtime/OS not cold storage. No dropped streams or tail trimming. Report per-session inter-byte p50/95/99/max including queueing, first byte from admission and sustained total emitted bytes/wall (setup/prompt ingest and JIT reported separately); CPU time of host plus native children, peak GPU allocation and host/child memory, provider work, real overlap, controller/kernel call counts. Check per-document generated-byte AND logical-event digests across equivalent fresh arms. If floating-point near ties change routes, keep all outcomes, no same-work speed claim for that family. Promotion only on conformance, complete exposure, equal trajectories and ≥1.20× B16 throughput vs packed with ≤10% B1 p99 regression in **both** traffic modes. Relative engineering screen, not a customer SLA. Single-host small closed-load tail quantiles are descriptive. No claim that this prices a training arm or proves prediction quality.

**Cost.** ≤420 additional inclusive card-seconds incl. failures/release rounding; verify detached broker owner/starttime/PPID, heartbeat and advancing service work. Physical GPU 0/1 only. Stop on nonfinite/invalid results, parity, OOM, timeout, identity or lease failure; repair only genuine engineering faults with retained evidence under the same cap. Retain all completed cells even for a failed attempt, no rerunning for better clocks. No new dev/confirmation, model update or production launch.
