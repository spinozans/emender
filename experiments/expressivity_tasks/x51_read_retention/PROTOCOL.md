# X51: is a single archive read useful now, later, or both?

Register before new membership or outcomes. X50's learned second question lost to one read. X50 did not isolate the value of consulting the archive at all or of keeping its answers for later. Test these two questions separately on the X50 one-read architecture; no operand selection or child reads.

## Matched readers

All arms keep every observed byte row. At each byte t, each also has an answer slot with the same endpoint byte, type and position. Its **shell** contains only those three embeddings. Filling the slot adds X50's projection of the square root of the current 256-bin P100 kernel answer. There is one attention layer, with raw row keys/values (no deeper hidden-state path around erasure). The current answer slot queries the preceding rows, current observation and itself, then predicts the real next byte. Use the same trainable parameterization, initialization, causal topology and number of visible rows at every prediction. No scratch is observed or scored. Reset per window.

- **NONE (no read):** no XSA call, archive vector, support, or archive logit prior at any position. All slots are shells. Use a fixed add-half byte unigram prior from the 32,768 real shifted **FIT targets only** so the byte-only model does not have to start from uniform. Seal this prior before fitting; never estimate it on PROBE.
- **DISCARD:** one current XSA read per prediction, with X50's exact materialized suffix kernel and `.99*p+.01/256` logit prior. Fill the current slot. For every subsequent prediction its older slot is just the shell; **no histogram or representation derived from it** survives on the model path. Keeping the shell prevents duplicate endpoint bytes or the number of available slots from confounding KEEP vs DISCARD.
- **KEEP:** same current P100 read, prior and slot, but earlier slots keep their original answers. Exactly the X50 ONE function at the same weights, up to floating point. This equivalence, including gradients, must be checked on invented data. No initialization from spent fits.

**Fixed-weight diagnostic, DROP:** during KEEP probe only, make a second set of predictions with earlier answer contents erased (DISCARD mask, same KEEP weights, same original current answer, no extra XSA reads). Diagnostic time is outside the chosen path. The fixed-weight first prediction in each document must agree; a retained answer cannot affect that prediction. Count later positions on which the 256-way distributions differ by total variation >`1e-6`, and report mean TV. Differences are not in themselves gains. This diagnostic cannot substitute for beating a separately fitted DISCARD. NONE and DISCARD need no intervention.

## Endpoints, interpretation and price

Report NONE, DISCARD, KEEP, DROP, archive prior alone and FIT unigram alone (the last two descriptive, not additional trained arms). Gains = control loss minus candidate loss in nats per real byte. Register **KEEP:DISCARD** (value of retaining answers) and separately **DISCARD:NONE** (value of a current read, including its direct prior), plus **KEEP:NONE** and **KEEP:DROP**. Jointly bootstrap paired whole probe documents across the three fixed seeds, 10,000 draws, RNG 5100, linear 95% percentiles. For each comparison separately: require positive gains at all three seeds and lower bound >0 for a directional win; symmetric for a loss; otherwise unresolved, not equivalence. Claim both a benefit of training with retention and useful reliance by the fitted reader only if both KEEP:DISCARD and KEEP:DROP pass. The separate current-read conclusion does not depend on either test. No data-selected subgroups, checkpoint selection, tuning or default/scale promotion. NONE is a matched small-reader baseline at this dose, not every possible byte-only model.

Report actual logical reads, native page activity, FIT/PROBE wall and CPU, common startup/data cost and diagnostic time separately. The model-visible lifetime of the answer is manipulated, not physical storage during vectorized training: DISCARD may batch exogenous current answers for separate frontiers. These timings are not streaming latency or necessarily memory savings. Do not claim a simpler reader is equivalent from an uncertain difference.
