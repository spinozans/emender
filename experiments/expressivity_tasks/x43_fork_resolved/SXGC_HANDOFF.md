# Handoff: emender → sxgc

From the X43 fork-resolved LM program (repo `/home/erikg/emender`,
`experiments/expressivity_tasks/x43_fork_resolved/`). We build language models
on top of `xsa`; everything below is receipt-bound with verbatim logs.

## 1. What worked — keep exactly as is

- **The documented three-command pipeline** (`xsa corpus` → `xsa build --tape`
  → `xsa query`) ran clean end-to-end on a 1.1 MB text corpus: container
  published, `full_SA=0`, `persistent_positions=0`, journal bindings verified.
  Receipt: `receipts/part1d/`, commit `a6111985`.
- **The fork machinery is exactly right.** We independently derived per-position
  forced/fork labels from first principles (direct suffix array + LCP of the
  maximal repeated left-context; derivation in `DERIVATION_PART1C.md`, validated
  on 511 exhaustive small/random examples), then cross-validated against the
  xsa container's structures: **1,115,394 / 1,115,394 labels and context lengths
  agree.** Two independent formalizations, zero disagreements.

## 2. Bugs / limitations found (receipts linked)

1. **`0xff` matches virtual END** — `validate_index.py`'s query oracle, 1 of 13
   test patterns: a query for byte `0xff`, *absent from the corpus*, incorrectly
   matches at the virtual END position. Suspected: the query-side symbol mapping
   collides an absent byte with the END symbol (the build side's k=257 split —
   symbol 0 = END, 1..256 = bytes — needs the same augmentation on the query
   side). Repro + verbatim: `RESULT_PART1D.md`, `validate_index.py`.
2. **Byte preservation through the XML corpus stage** — wrapping exact raw bytes
   in minimal MediaWiki XML exposed entity-escaping corners. For byte-exact LM
   work, corpus-stage byte fidelity is load-bearing; either a documented
   byte-exact route for plain text, or documented constraints on what survives
   the XML path. Receipt: `RESULT_PART1D.md` (corpus binding section).
3. **Legacy direct-text entry reaches the cyclic machinery with an in-text
   terminal.** Our first attempt (`xsa build --text input.txt --mode text`,
   terminal `0x0a` — an invocation *not* in REPRODUCE.md) put 15,606 newline
   occurrences into the cyclic seam: `CYCLIC_SEAM_REFUSED class_size=40000
   limit=1000 policy=max(1000,raw_r/1000)` (verbatim: `receipts/part1b/`).
   The refusal was CORRECT — fail-closed caught a contract violation. Suggested
   hardening: (a) preflight terminal-occurrence count at entry (fail in
   milliseconds with the same diagnostic); (b) guard/retire the legacy text
   entry so no path reaches the cyclic seam with an in-text terminal; (c) for
   the transition period, a size-aware policy floor (small multi-document
   corpora can legitimately exceed the 1,000 floor) or an explicit
   `--allow-seam-class=N` acknowledgment flag. The A1 virtual END closes this
   class structurally — our incident is a receipt for A1's necessity.

## 3. What we need for tier 2 (Wikipedia-scale fork-conditioned LM)

The fork-resolved LM consumes these query primitives at inference; if `xsa`
exposes (or can expose) them, the model integrates directly:

- **O(1) backward step** on the current interval per generated byte
  (the walk advances on any bytes, generated or corpus).
- **Branch enumeration + exact counts** at fork positions: given the current
  left-context interval, the multiset of observed next bytes with counts.
- **Empty-interval detection** (OOD abstention) and a documented re-entry
  strategy after the model's generation leaves corpus support.
- **Batch/bulk labels for training**: a one-pass dump of per-position fork
  labels, maximal-context lengths, and branch counts over the training corpus.
- **Byte-exactness guarantees** end-to-end (see 2.2) — our loss decomposition
  is defined per byte position.

## 4. Why this matters (one paragraph for context)

We measured: on held-out text, fork positions (57% of positions on this
corpus) carry 65.9–82% of neural LM loss; fusing models with the index's
exact branch counts + walking forced bytes flips a standalone transformer-vs-
EmenderLM result into an EmenderLM win (`RESULT_PART2.md`). The fork-resolved
architecture — index as deterministic spine, neural model as the organ of
decisions — is our next design tier, and `xsa` is its spine.
