All four pass the preregistered quality and call-count clause. At 8192 both beat the always-read predictor on NLL as well as calls. Calibration selected zero explicit read price throughout: the restricted optional-read design itself saves calls. Savings are end-to-end **protocol read counts**, not equivalent computational work or measured speedup; the filtered positional path fetches only surviving payloads. Training data volume, local mixture head and action execution differ from v1, so the full gain over v1 is not attributable solely to learned routing.

**Stronger control:** the calibration-selected fixed move at 8192 (recent anchor, otherwise stop) scores 1.59858 / 1.59868 at 6.35 calls. Learned selection takes 15–25% fewer calls than this control but is slightly worse in NLL point estimates. No claim of a predictive gain over the best fixed move. Successful selection of an optional read is not evidence of learning arbitrary multi-step programs or persistent bookmarks. The policy operates on a mandatory depth-3 summary and candidate metadata, before the optional reply.

Chosen-only checkpoint replay on one test document per cell verified selected action, exact read count and target probabilities. At 8192, max target-probability discrepancies <5.3e-7; p50 ~0.99 ms and p99 ~51 ms on that single CPU debug replay, including observed-byte append and scheduled seal. No matched full-test latency comparison. Greedy-generated byte smoke also ran from the published 8192 checkpoint.
