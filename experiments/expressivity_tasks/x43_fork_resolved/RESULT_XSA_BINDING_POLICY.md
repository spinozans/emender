# Native XSA positional trace and trained operand selector

The first count-identical witness pair yields `byte 662 -> e8` versus `byte 662 -> 9e`. The address is derived by locating a group, restricting a row lookup to that group, and restricting a field lookup to that row. No gold address is passed in. All 128 oracle targets matched on a live tail, a partially sealed prefix and a fully sealed prefix. Across each schedule: 948 reads, 666 positions returned. Fully sealed: 3852 candidate suffix rows enumerated; fully live: 551528 candidate starts scanned. This is correctness evidence in a debug build, not decoder latency. Retaining seal's sorted positions adds memory; old release timing/RSS must not be attributed to this engine. Rust session tests and the original 1128-reply branch replay passed. Full example RPCs in `receipts/xsa_binding_live.json`.

Then we trained one eager X45 MatrixBlock (4348 parameters including input/output heads) to select handle operands using answer likelihood over the small interpreter's executions. Network input is the history of counts and availability of three shuffled handles, not payloads or gold positions. Ranges survive between dependent operations. No program labels were required; exact training enumeration and abstention on invalid operands make the credit assignment easy. This is NOT the 150M K15 controller. The instruction schedule, grammar, singleton precondition, bookmark semantics and field-value offset are supplied. Training used one seed, 128 synthetic examples, 200 updates; first/last minibatch NLL 1.899/0.000115. Reloaded checkpoint for greedy live inference.

| 4 groups × 2 rows × 3 fields | 32/32 | 32/32 | 0/32 |
| 8 groups × 4 rows × 4 fields | 32/32 | 32/32 | 0/32 |

On the larger set, learned and unique-first each used 692 index reads, 3380 returned positions across 64 targets. Counts at the first larger example's steps were `[1,32,8] -> [used,4,1] -> [used,1,used]`: the policy selected handles 0,2,1 and read byte 38. Reassigning the final occurrence cyclically (same field frequency, extra lookup for the intervention) produced 0/64 correct on each size; payload values within a fixture are distinct by construction. The model can drive positional reads, but no advantage over the simple rule was found or expected. Do not infer general program induction or learned use of internal writable slots. The CPU test uses an already sealed session at inference, not an accelerated incremental locate benchmark.

**Next discriminating test:** make candidate cardinalities tie and let a second anchor's relative position disambiguate a value; vary which relation is asked for. Provide generic range/offset/set operators, not a group/row resolver. Require the policy to choose the operation as well as the operands. Compare against count-only selection, fixed positional heuristics and oracle at matched read/enumeration budgets. Probe whether stored alternative addresses matter by clearing them before the dependent read.
