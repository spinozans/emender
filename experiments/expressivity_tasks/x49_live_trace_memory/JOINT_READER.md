# Prepare the frozen two-note reader for a fair second test

Prospective, 2026-11-25 UTC. [LS](RESULT_LITERAL_SURPRISE.md) found that the two records together improved on U by .002046 nats/byte on a disjoint TRAIN probe. But LS was a six-way comparison: it built a wrong-occurrence control a user wouldn't need, and spent 21.50 ms per full window on the Python count writer. Before spending any more held-out text, implement an **evaluation candidate** that calculates just the winning fixed rule. Can we make the count note cheaper without changing a single note or prediction? This is a CPU engineering check in service of a later no-refit replication, **not** another model search or an LM result.

**No new predictor.** Use precisely the J coefficients, seed-to-weight bindings, vocabulary and latest B address of the closed [LS aggregate](receipts/literal_surprise_result.json), SHA `4e2789566883cbaf11131919bfa72781f0ac0c0d74a0c58289caea2728fe99a2`, FIT seal `443f3161f2dbfe075e6ece00329e6c2dc0ebedb19693100cf40292a672e47847`. U remains unchanged. No coefficient fit, center/scale change, approximation, alternate count estimator or different quantization. Build the same U bound-only fields with one prefill, no rotated search. Add only the correctly bound literal code at B's exact old position; the five J fields must be in LS order. Return all 256 log scores **before** any label access, including misses; no corpus reader, supplied address, sham, comparison arm, cross-window state or GPU acquisition in the predictor. Bind any candidate load to the actual matched checkpoint in an already admitted worker; do not make J the default.

**One native writer.** A small local CPU routine reads one observed prefix in order, appends the identical `uint8` marks, and maintains the [registered](LITERAL_SURPRISE.md) KT and 1/2/4/8-byte interpolated follower counts. An 8-byte rolling key is enough, provided depths are disjoint namespaces and multiplicities/distinct followers are exact. No corpus-dependent tables, sorting keys using future text, peeking at a later input, fast-math, predicted bytes or reuse across invocations. Keep the Python writer and independently enumerated dense oracle. Source-bind the local build and reject missing/stale builds rather than silently switching algorithms in timing. Track actual lookup/update and context/pair counts. Entries are logical work, not allocator bytes.

**Acceptance before any natural use.** Exact equality to the Python writer for every code and logical work count on invented inputs: short boundaries (1,16,64,65,4095,4096), binary/leading zeros, periodic and highly repetitive strings, random prefixes, the saturation case, overlaps and reset. Check prefix extension and reject out-of-range lengths. Compare the bound-only J to the full LS reference on *all* 256 scores, wrong seed/coefficient refusals and no-sham access. Use tiny invented host and heads or independent synthetic logits for these CPU checks, not fresh natural text.

**Timing is descriptive.** Time the whole writer call (fresh tables and output byte tape, including the Python/native interface) on exactly three invented 4096-byte windows: all `0x00`; repeated `b'color: blue\ncolor: black\n\x00\xff'` truncated to length; uniform bytes from `numpy.random.default_rng(4911).integers(0,256,4096,dtype=np.uint8)`. First verify exact outputs on each, then two untimed calls per implementation and 31 paired trials/fixture on lambda01, alternating which runs first. Single CPU thread (`OPENBLAS_NUM_THREADS=1`, Torch/OMP threads=1), GPU invisible, fresh state per call. Record per-fixture median and p90 time for both writers, median paired speed ratio, compiler/flags, build time and identity. No timing threshold tuned on these cases, no natural throughput or end-to-end speed claim. If parity fails retain the failure and don't time or expose that implementation. A timing improvement would justify carrying the exact writer into a separately qualified no-refit comparison. It cannot change the local predictor recommendation.

**Access boundary.** This step has no data reservation, no natural access, no lease or remote run. All 321 unreserved short final documents remain outside it. Do not rerun LS, U, V or open any private windows to time this code. Publish reviewed source and small synthetic measurements only. A separate prospective population, decision rule and cost envelope would be needed for a new natural confirmation.
