# EH: putting old mistakes under the key where they happened

[Question and fixed comparisons](ERROR_HISTORY.md). J already uses the newest eligible occurrence. EH asks what the *other* occurrences say: did the model keep guessing a byte that did not follow this pattern? Guess the byte first from the old host forecast; mark a mistake only once the actual input arrives. At a later query the correction can use only the counts accumulated at that key. All revealed next bytes are still scored, including misses and singleton keys.

[`error_history_index.py`](error_history_index.py) uses one pending record per key. A later eligible occurrence commits the prior pending record before replacing it. This preserves overlaps, the 16-position delay, and the deepest-key decision even when a shallower key has more evidence. The true branch adds five integer fields per occupied key/byte: observed count, two arrival-code sums, how often the observed byte was missed, and how often this byte was guessed incorrectly. The last count can be nonzero for a byte never observed after this key. A separate control pass uses the previous mistake with the same observed follower and neural surprise code instead. Distinguish earlier mistakes, displaced uses, genuinely changed guesses, and queries with a different **sum**: multiple changes can cancel in a histogram. `peak_keys` includes pending singleton keys; `peak_cells` counts allocated committed key/byte entries, not 256 dense bins per key. Packed snapshots and FP64 features are transient research tensors, not an estimate of Python resident memory.

[`error_history.py`](error_history.py) checks that the live index agrees with B's own key, depth and latest address, reuses J's original notes, and changes scores only on active older-history rows. The standalone ERROR path has no sham map and does not compute U or a competing response. [`error_history_fit.py`](error_history_fit.py) computes the Fisher system sparsely over nonzero feature coordinates, preserving the 256-way normalizer and accounting for zero-feature rows in the all-target denominator. HISTORY's five common columns and their target exposures must match in both six-dimensional fits. SWAP never gets its own coefficients.
