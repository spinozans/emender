# X49-EH: does a live pattern benefit from remembering which guesses went wrong?

Prospective, 2026-11-25 UTC. [RB](RESULT_RESIDUAL_BYTE.md) is closed: no retuning or transfer of the third-byte reader. Keep B as baseline, the confirmed U and the replicated two-note J unchanged. Ask a **different** question. Suppose `color: ` has occurred several times. Text counts say what followed; J also knows about the latest occurrence. But perhaps the model repeatedly **guessed `r` when it saw `b`**. Does remembering *which wrong bytes it guessed* at the other occurrences help it predict the next one? Not a search over compressions or an attempt to buy another final. [V](RESULT_ALTERNATIVE.md) nominated one alternative from one old forecast, even if that forecast was correct. EH instead indexes a running tally of past **observed mistakes**, on every earlier eligible occurrence **except the latest one**. It can change odds for multiple bytes, including a wrong guess that was never actually observed after this key.

## The record and the read

For the three exact W-B weights and their original U/J coefficients and verified native text writer (bindings in [RB's aggregate](receipts/residual_byte_result.json), SHA `5a8f76f6e2f9cb20e8f426b2a86957327d33b9a81d2d9c86229f1ef31af7849d`), retain the normal B vector and both correct arrival notes. At `j>=1` let `c=x[j]` and `a=argmax_b z[j-1,b]` of the bare causal host, **including c**, smallest byte on ties. When `c` becomes observable compare `a` to `c`. A mistake is `a != c`, not a high-loss threshold. The extra guess is a uint8, not a scratch observation or a trained oracle. No cross-document state, current label, supplied address, dense archive of old logits or speculative neural reads. Slot 0 unread. Price the writes, aggregation and readout.

After input `t`, use exactly B's deepest available 8/4/2/1-byte suffix, window H4096, overlapping histories, delayed followers `j<=t−16`, same left edge. Let `I` contain **all** eligible follower positions of that key **except B's latest**. No shorter-key fallback on a singleton. `n=|I|`. On misses and `n=0` the new readers return J unchanged. The latest stays with J; none of the new tallies counts it. One way to implement this online is to keep the newest eligible record pending at each key, folding it into that key's counters only when a newer one arrives. All admitted keys and index work are charged. A hypothesis about correcting an error is not proof that the fitted sign will be corrective.

For every possible next byte `b`, compute integer sufficient statistics over `I`:

- `C_b`: number with actual follower `b`; `L_b,N_b`: sums of their true literal and neural **uint8 surprise codes** respectively; `M_b`: number with actual follower `b` that the old host guessed wrong.
- `W_b`: number of mistakes whose **guessed** byte was `b` (across all actual followers). Thus `sum M = sum W`; `M-W` is a signed top-1 error tally, **not** a dense softmax gradient. No changed live address or new neural value read at the frontier.
- Research sham `V_b`: at an old mistake keep its actual byte, true surprise notes and wrong/correct status. Substitute the guess from the **most recent strictly earlier mistake in this window with the same actual byte and exactly the same neural surprise code**, if available, else keep its guess. Compute the donor at arrival, before updating that map. Never use a correct guess, different byte, looser code match, future row or a donor selected by guess content. Sum the resulting wrong guesses over the same `I`. `sum V=sum W`. The sham is not an independent null, nor does it preserve exact ages or literal codes of donors. It never changes the source record's literal/neural codes. Standalone correct inference has no need for a donor map.

## Fixed comparisons

Start at J's full 256 log scores `l`. Write `p=softmax(l)` in FP64 and `v_b=(C_b/n, (C_b/n)*Q(-log p_b)/64)`, with the existing half-up bounded surprise quantizer; use log-softmax for the code. Define `h_b=[v_b,L_b/(64n),N_b/(64n),M_b/n]`. One feature vector per possible byte; zero entries need not be materialized. All later-label gathers are outside the prediction path.

| Reader | Additive feature vector on byte b | Fit |
|---|---|---|
| B / U / J | Original readers, no new tilt | frozen, checkpoint-specific |
| COUNT | `v_b` | 2 scalars |
| HISTORY | `h_b` | 5 scalars |
| ERROR | `[h_b, -W_b/n]` | 6 scalars |
| SHIFT | `[h_b, -V_b/n]` | 6 scalars, fitted on its own sham |
| SWAP | `[h_b, -V_b/n]` | **same frozen ERROR coefficients**, no fifth fit |

Return `l_b + s_b − (logsumexp(l+s)−logsumexp(l))`, `s_b=beta·feature_b`, at active rows only. Preserve incoming log mass; this can alter both copy and non-copy odds. If the signed last coefficient is positive it suppresses historical wrong guesses, and if negative it *favors* them (e.g. they may still be plausible alternatives); report which occurred. HISTORY already has which actual bytes were missed, both scalar marks, their counts and current confidence. ERROR:HISTORY isolates adding the identities of the incorrect guesses, not adding an error flag. ERROR:SWAP changes no coefficient, can act only on rows with changed count vectors. ERROR:SHIFT separates the correctly bound scheme from an equal-size fitted control, not just a mismatched deployment.

One FP64 Newton/Fisher step at unchanged J for each fit at each seed, per-real-target normalization, ridge `1/4096` on every coefficient. At an active row `mu=E_p F`, add `F(y)−mu` to RHS, `E_p FF^T−mu mu^T` to Gram. Inactive rows add zero but count in the denominator. Solve once, no coefficient sign constraint, neural updates, U/J refit or optimizer search. Freeze all 12 readouts (four per weight), identities and FIT journals **before raw PROBE**. Independent Cholesky/residual check. No EH coefficient or natural membership exists at registration.
