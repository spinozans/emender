# X49-V — remember which *other* byte the model expected

Prospective, 2026-11-25 UTC; before V natural selection, fitting or scoring. [X49-U](RESULT_SURPRISE_CONFIRMATION.md) established that a single old forecast-surprise byte can tell a frozen model **how much to trust a copy**. But U cannot favor one *different* byte over another: it preserves the relative odds of all 255 non-copies. Test that missing capability, not another way to recalibrate the copy. **Does remembering the old forecast's strongest alternative help identify the next byte when it isn't a copy?** The primary denominator still includes *every* real target.

### One private byte, one changed question

Use the three confirmed W continued-B checkpoints and their own already-fitted U coefficients from `receipts/surprise_confirmation_result.json` SHA-256 `9c9bbabdf8cbb146af32f6b031e2c946c3840834c42779c6fc8cfd135bbc5626`. No refit of U, neural updates, change to the H4096 literal index, or change to B's 32-D payload. At arrival of observed byte `x[j]`, `j>=1`, write one **additional uint8**:

`a[j] = argmax_{b != x[j]} z[j-1,b]`, where `z[j-1]` is the preceding **bare frozen host** forecast. Ties choose the smallest byte. Slot 0 is zero and never read. This stores the runner-up if the old forecast got the byte right, otherwise its top choice. Write at every arrival, not selectively at future useful addresses. No byte of the old forecast is appended to observed text. Reset both tapes at each window; no cross-weight reuse. No old dense forecast fetched at query time.

At a hit let `j` be B's original address, `c=x[j]`, `L` the **unchanged** full U log scores, and `p(b)` the conditional softmax of `L` over `b != c`. Define the current alternative `i = argmax_{b != c} L[b]` (smallest byte on ties). For a nominated non-copy `a`, the feature block for hypothetical next byte `b` is `F_a(b) = 1[b=a] * [1, Q(-log p(a))/64]`, with U's fixed half-up saturating quantizer. Features use the **current** conditional odds, never whether the proposal actually succeeded.

| Predictor | Feature blocks for non-copies | What varies? |
|---|---|---|
| U | none | Confirmed incumbent, unchanged |
| D | `F_i` | A two-scalar calibration of the strongest current non-copy with no extra historical tape |
| V | `[F_i, F_{a[j]}]` | Four scalars; correct earlier forecast alternative |
| K | `[F_i, F_{a[k]}]` | Same four scalars; wrong occurrence for the **alternative only**, fitted with that intervention |

Use U's existing `rotated_payload_index` at that frontier for `k` (same actually observed follower, same log-age bin, singleton stays). For **all four**, the surprise `m[j]`, actual byte `c`, B vector, direct head, current logits and query stay correct and fixed. `a[k] != c` by construction. Do not rotate U's mark or B's vector; V does not consult K or choose between addresses. When current and historical proposals coincide, **add** both blocks' offsets to that same byte (and include their covariance in the fit). K need not have zero signal.

On a hit set `s_b = beta · F(b)` for non-copies. Keep `L'[c] = L[c]` **exactly**; for `b != c`, `L'[b] = L[b] + s_b - logsumexp_{d != c}(log p(d) + s_d)`. Preserve total non-copy mass. Misses stay exactly U. Construct a 256-way answer before seeing the observed next byte. A gain cannot come from increasing or decreasing total copy probability. This is a frozen forecast readout, not a trained attention layer or unbounded model-generated text.
