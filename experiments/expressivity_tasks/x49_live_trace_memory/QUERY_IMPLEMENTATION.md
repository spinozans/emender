# X49-Q implementation and address gate

[Registration](ADDRESS_DEPTH.md), published at `9369cd760c653359aa435345d74c3da46d0aed4d` before natural Q selection. This is a **frozen native TRAIN diagnostic**: no new model, optimizer or final board. The head receives the latest literal follower's byte and unmodified direct evidence in every case. Only the source of its single neural payload read varies.

- [`query_depth.py`](query_depth.py) appends a historical slot to suffix-plus-follower postings only when it is old enough. E searches entries from most recent to least recent for a strictly longer bounded left-context match; reader weights and stored vectors are never used to rank addresses. Only M seeks the nearest eligible non-extended substitute in E's log-age bin, breaking exact distance ties towards the newer slot. Without one, it uses E. J calls B directly, without building the extra index. J/E/M each read one value on a hit and none on a miss.

- **Corrected address gate.** At `98ad561602dcf082f88ea76bc31a15e24a03b0ce` all 16 Q-address/compact tests passed. [`query_native.py`](query_native.py) independently agreed on 108 E/M policy frontiers (54 queries across horizons and sealed/unsealed sessions, 24 hits, 4 extended moves with matched alternatives, 108 locate and 752 byte requests, two closed sessions). This is synthetic parity, not a coverage or NLL estimate. No natural Q document or GPU lease was opened in either attempt.
- [`query_data.py`](query_data.py) rederives W's exclusions and all W reservations. It verifies the new rank prefix also equals the exact suffix after W TRAIN under the earlier exclusion set. Only a source-qualified CPU process can do the single-use preparation; each full native TRAIN document must hash-match before the aligned window and its two shifts are written. An incomplete reservation is not a request to choose replacement documents.
- [`query_run.py`](query_run.py) and [`query_panel.py`](query_panel.py) separate CPU/source qualification, preparation and a **distinct** one-lease admission. Qualify strict-loads all three actual W continued-B models on CPU. Before opening the prepared diagnostic stream the frozen reader checks the trainer, current owner, single-use stage, dataset identity and all three checkpoint file digests. Models load strictly again against those frozen identities. No calibrator, training step or second acquisition is available. After scoring, only closed receipts enter the analysis.
- [`query_score.py`](query_score.py) uses one frozen host prefill for a given seed/document. Three policy orders rotate by rank plus seed index. All 256 scores must be identical at unchanged addresses (including E:M where no matched alternative exists). Only after all policies return does the scorer gather the shifted target. It records shared host prefill, standalone policy time, extra address time within that policy time (zero for J), work and strata. These times do not pretend the diagnostic checks or setup are free: the total charge is reported separately. No hidden rows, addresses or per-target scores are published.
- [`query_analysis.py`](query_analysis.py) pairs all 128 documents across the three fixed seeds. It checks the all-target denominator, support partition and unchanged scores, then computes the registered joint document bootstrap. Report contributions on the all-byte denominator as well as conditional effects; no fabricated conditional loss for an empty stratum. Do not publish singleton-stratum scores. [`test_query_pipeline.py`](test_query_pipeline.py) exercises new-rank exclusions, binary shifts, changed identities, premature access, real full-window scoring, pairing and receipt/progress semantics on invented inputs.

`query_run qualify` is CPU-only and needs the private parent checkpoints plus registered XSA binary. `query_data prepare` is single-use, not a reproduction command for an already reserved population. Only separately admitted local inference may read the prepared stream. Do not reopen past tests or reserve more short final documents for Q.
