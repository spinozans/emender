In what follows all counts refer **only to older records at that key**, excluding that latest one (even at a singleton; no shallower fallback). `C_b, M_b, W_b` are ERROR's existing actual follower counts, actual miss counts and wrong-guess counts. In PAIR also accumulate sparse `D[a,b]`: the number of those mistakes with `a_j=a` and `c_j=b`. Thus `D[a,a]=0`, its row sums are `W`, its column sums `M`; no probability vector or 256×256 dense table per key. At the current forecast `q=q_t`, define:

- `h=W_q` previous mistakes guessing `q`; `k=C_q-M_q` previous correct guesses of `q`. If `h=0`, return ERROR unchanged. Otherwise `A=h/(1+h+k)` is a count-discounted past error fraction for this guess; `m=sum_b M_b`.
- `v_b = 1[b!=q] M_b/(m-M_q)` is the **unpaired** law of missed alternatives, excluding `q` because a wrong guess of `q` could not have been corrected to `q`. The denominator is at least `h` on every active query. `r_b=D[q,b]/h` is the observed correction distribution for this particular guess. This comparison does **not** reward PAIR just for knowing the diagonal is zero.
- MARG feature `f0_b=A*(v_b-1[b=q])`. It moves scores from the query toward plausible alternatives, but doesn't know their pairing. PAIR adds `f1_b=A*(r_b-v_b)`, redistributing evidence **among alternatives** with `f1_q=0`. No labels enter either feature. If an earlier mistake has only one possible alternative under both laws, `f1` vanishes. No trigger based on future support.

**Margin-preserving control** within each key. Number the *committed older mistakes* in arrival order, ignoring correct records. Before the second mistake is committed the first is visible **only as itself**. Commit means displaced from the pending latest position by a newer eligible record, not merely seen in the input.
