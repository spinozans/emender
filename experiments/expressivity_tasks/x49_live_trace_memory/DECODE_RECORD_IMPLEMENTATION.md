# Decoding a value from two arrival codes

[Prospective question and inference rules](DECODE_RECORD.md).

[`decode_record.py`](decode_record.py) has two separate input-only seams. FIT consumes the actual host outputs for the observed prefix. It writes B's `tanh` vector, builds the two arrival tapes and adds every slot after the first to [`Moments`](decode_fit.py); no address lookup or next-label argument. On PROBE the shared direct head sees ordinary C14 input bytes and B's normal count features. The common address is computed inside the reader. B/J/U get B's complete actual old value. P gets the per-byte mean; D and S read from the same FP32 table using the true or matched displaced pair. Each branch gets its **own** 256 corrected base scores and copy margin before applying the appropriate unchanged trust coefficients. S's trust marks are always right even when its value is wrong. Only `score` sees the shift. The full evaluation computes diagnostics; `compact_predict` alone never evaluates the historical writer, sham or siblings.

[`decode_fit.py`](decode_fit.py) accumulates FP64 sums grouped by observed follower (slot 0 always omitted), then fits two slopes for each output and follower from within-cell covariances. Centering is by cell, the ridge is per population covariance, and unseen followers get the global teacher mean and zero slopes. Decoder arithmetic after the fit uses FP32. Distinguish the 100,352-byte shared table from two bytes per occupied historical slot and from all other model/index/temporary memory. Reading a full host packet during the comparison is not evidence of a deployed bounded-memory incremental implementation.
