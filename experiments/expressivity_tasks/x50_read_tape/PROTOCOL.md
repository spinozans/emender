# X50 — one read, or read the answer and ask again?

Prospective local experiment, after X49-PT. This is a new program, not a resumption of W1–W3, X48 or a correction-table study. Build an append-only working context over real observed bytes and model-issued reads of the mounted P100 XSA. No correction-specific features or previous fitted readouts. Test whether learning which follow-up question to ask helps predict the next external bytes. Do not infer this from a changed address alone.

## Instruction and causal clock

`READ(source, string)` returns a byte-valued string-kernel read. Source for the natural comparison is the whole pinned read-only P100 m20 mount, not the target window. Given a literal query, each corpus position with a byte follower contributes a root vote plus `32**d` votes for **each materialized** matching suffix of length `d=1..8`; normalize the 256 accumulated byte masses. Equivalently add the corresponding full native branch histograms with those weights. END is structural, not a byte. An unmaterialized suffix contributes **no term by definition**, not evidence that its occurrence count is zero. This is exact up to floating point for this materialized string kernel and tied byte values, not dense neural attention over corpus positions. No top-k occurrences, location callbacks, document-crossing matches, speculative reads of child answers or corpus-sized neural K/V cache. A fixture must check this definition against explicit position enumeration, including overlaps, missing materializations, binary bytes and multiple documents.

After observed byte `x[t]`, append its typed observation and read the observed suffix from the XSA. Append a typed parent-answer row encoding the distribution, position and query endpoint. A two-read program emits one byte `a` from a 256-way policy, issues a second READ for the observed suffix extended by `a`, and appends the chosen operand and returned distribution as a typed work row. The actual prefix is unchanged; `a` need not equal the next observation. Predict `x[t+1]` using causal neural attention over **all rows so far in this window**. Then observe the true byte. Reset on every new window. There is no scratch loss or target byte in either query. First queries are forced and can be resolved by a causal native prefix scan; second answers must be generated from the actual chosen query. The predictor and adaptive selector can read prior child replies; retained pure archive pages may be cached on this mount, not model features or per-checkpoint predictions. The experiment fixes one or two instructions per target: no claim that it learns when to stop, which source to mount, or arbitrary query programs.

## Four paired arms

- **ONE**: parent read only. The predictor sees all observations and parent replies; no dummy second lookup.
- **GREEDY**: always follow the largest parent mass, smallest byte on ties. Fit the same two-read predictor.
- **BLIND**: learn the follow-up using attention to the observed bytes only (no answer-derived candidate mask, prior, or hidden work state for the selector). The predictor still sees both genuine replies and all preceding work. Same two reads as ADAPT.
- **ADAPT**: choose the extension with attention to the current parent and prior tape, including earlier second replies. Initialize action logits with `0.5 * log p` of the smoothed first read plus a zero-initialized learned correction; allow the prior scale to learn. BLIND starts uniform. Comparing to GREEDY tests more than inheriting an answer-dependent birth policy.

Separate fits with paired initial parameters and document order. Width 32, one causal dot-product attention block with residual and normalization, learned byte/type/position embeddings and a shared projection of square-root histogram probabilities. Predict via a learned 256-way logit residual at the common direct prior `p=.99*parent+.01/256`. No hardwired child vote at the parent target. Sample a single hard action in training, choose argmax at evaluation. Only sampled/chosen replies execute. Credit the action log probability by detached *remaining* window loss minus the corresponding action-independent direct-prior loss (past actions can affect later predictions); minimize together with ordinary all-byte NLL. No oracle operands, auxiliary action labels, straight-through lookup, or evaluation selection among policies. Check the sign and horizon against a tiny exact expected-loss gradient.

## Data and exposure (register before membership)

CPU only, no GPU lease, remote submission, previous weights, or paid panel. Pin P100 with the existing native W3BP0001 branch transport/descriptor; reuse the transport, **not** its panels or historical join policy. Verify native kernel results on invented inputs before the natural run. Reserve once after source/tests qualification. Reproduce the metadata exclusions through both PC roles and PT's entire spent calibration remainder (45,414 unique excluded SHAs). Use the next 768 unspent full **TRAIN** documents by the established `x49-live-v1:` SHA rank and whole-SHA exclusions: first 512 FIT, next 256 disjoint PROBE. Same raw-file identity, manifest `48b9095eeccb023ff1cb2a4f6da899a8b3e4eb3b76b2804e730f1d6ad031c414`, start offsets ≥100,600,000,000, length ≥4,097, prescribed aligned 4K-window start. Use just its first 65 bytes for exactly 64 real shifted targets in a single reset context; it gives 64 serial read decisions and up to 192 local attention rows. Verify whole-document SHA and C14 shift before use. The 100 GB archive ends before these documents; this excludes the targets' own positions, **not** duplicated passages. No new calibration or final payload. No extra sample if uncertain.

Train seeds 5001/5002/5003, three epochs over the same FIT windows, batches of 16 distinct documents, seeded shuffles paired across arms, AdamW lr .003, weight decay .01, global gradient norm clip 1.0, FP32 single CPU intra-op thread, no dropout. This is a small learnable reader at a strong direct archive prior, not a comparison against the 150M trained hosts. Each arm/seed has 98,304 FIT targets and 16,384 untouched PROBE targets. Lock all 12 terminal states, no checkpoint selection, before opening PROBE. Price actual execution: real reads, chosen query changes vs GREEDY, archive-page fetches, FIT and PROBE wall, CPU and memory, and common setup separately. Rotate arm order across seeds; cold user-space page cache per arm/phase, shared OS cache not a cold-disk benchmark. No automatic retries/extension; retain partial runs and gate failures.

## Interpretation

Report kernel prior and all four all-byte losses, per-seed and average. Primary gains are control NLL minus ADAPT NLL against ONE, BLIND and GREEDY. Bootstrap the same whole documents jointly across the fixed seeds (10,000 draws, RNG 5000, linear 95% intervals). Report GREEDY:ONE and BLIND:ONE too. Call it positive evidence for **useful learned follow-up selection on this probe** only if ADAPT beats all three controls at every seed, their lower bounds exceed zero, and it actually departs from GREEDY. A two-read gain alone doesn't establish useful learned selection. A null isn't equivalence or proof that more general search cannot work. Matched exposure is not matched time; no scale/default decision. Report the natural finding or an honest blocker. Public output: reviewed source, tests, protocol and compact aggregate only; never publish raw text, keys, actions, membership, fitted states, per-document scores, native binaries, or private ancestry.
