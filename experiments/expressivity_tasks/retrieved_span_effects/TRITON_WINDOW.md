**What is implemented.** For fixed-control GDN‑2 and a *single terminal read*, don't build a passage matrix. Walk its tokens backwards: `s = dot(k,a); b += s*u; a = d*(a-s*r)`, starting at `(q,0)`, with `r=erase*k`, `u=write*value`. This gives `(Aᵀq,Bᵀq)` per passage. Reduce both across alternatives and add `Sᵀ Σp_i A_iᵀq` once. The first VJP walks forwards and needs a tape of key-width vectors, not matrices. Arithmetic per hit goes from O(T K V) to O(T(K+V)) before the shared seed read. This is not the same speedup factor in wall time. Parallelize independent frontiers, hits/heads and features; fuse masking/softmax in candidate scoring, control activation, the seeded reduction and their backwards. Missing slots, present empty spans, partial tails and duplicate hits are distinct. Hard candidate proposals are not differentiated. Generic BLAS projections and optimizer are not rebranded as custom Triton kernels.

For many downstream queries between lookups, compute the terminal memory once and reuse it. For nonlinear E97 split-edit, replay each passage on the same seed, reading/averaging only as permitted by the output map. Its erase reads **before decay** and it applies tanh per real token. The matrix path has a first-order VJP to all controls and the seed, and an all-reads scan for the causal token host. It currently saves FP32 pre-step states during training. Profile tape memory and compare checkpoint/chunked variants before claiming scale readiness. No in-place overwrite of live state, future labels, Python loops over passage hits or per-token GPU launches in the implemented recurrent kernels.
