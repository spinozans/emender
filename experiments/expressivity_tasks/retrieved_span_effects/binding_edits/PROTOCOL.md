# Which archive row carries the answer? Independent edits with repeated values

**CPU only.** The [permutation result](../semantic_tail/RESULT.md) motivated this prospective diagnostic: three fits followed swaps perfectly with almost no mass on the intended key. Was a decoder using the *other* values to recover the missing one? Do not reopen the original probe. Test the **nine unchanged synthetic snapshots** on fresh, non-permutation books, and separately test whether the same architectures can learn the new task from the same starts. No natural data/weights, hardware run, feature-rank sweep or retry. A new result, not an amendment of the closed three-way comparison.

## Separate changing a row from changing its donor

Use the same synthetic tokenizer, eight `[key_i, value_j]` documents, aliases, learned **vector** head, local/skip options, exact or positive-summary corpus read. Every edition now has repeated values, including among the fixed background rows. No live key/alias overlap, no match even at one token. Only successor values change; row scores/source priors cannot change. Variable keys/values are fully crossed in each test set. No edition, panel ID, edited-key flag, or future label is a model input. Score the native trained laws of each cohort, without selecting a fit on earlier results.

- **Replacement FIT:** for each of the eight possible variable keys choose two new seven-value backgrounds. For each background enumerate all eight simultaneous cyclic relabelings of the seven fixed values, and independently all eight values of the variable key. Thus 8×2×8×8 = 1,024 distinct editions. All other seven rows are identical across eight possible answers for the variable. Every alias's marginal is exactly uniform. Train LOCAL / DENSE / INDEXED for each seed 5701–5703 from the *original starts*, not the permutation-trained weights. Same .003 AdamW, clipping, widths/rank/leaf, blocks of five, sixteen shifted targets/update, one freshly encoded bank/update. One shuffled pass (`default_rng(57100+seed).permutation(1024)`); **identical dose** to the old fits but higher edition diversity, not a pure data-distribution ablation.
- **Independent test:** for each unordered pair of variable keys `(i,j)` in lexicographic order choose a new six-value background; enumerate the **64 ordered** value pairs `a,b` independently. One such panel per pair, 1,792 books in total. Score the two variable-key prompts: 3,584 active answer positions per fit. With `j` and all six background rows fixed, consider **all** ordered changes of `i` from `a` to `b!=a`; likewise reverse the roles. This yields 25,088 isolated edited pairs, each at exactly the same live prefix and the same seven other rows. Separately, when the two values differ, swap them: 3,136 directed changed-key comparisons at exactly the same **bag of archive values**. Directed pairs share worlds and are not independent samples. A histogram-only reader cannot follow that swap. A reader that ignores the target row cannot follow an isolated edit.
- **Immutable generation:** choose each background by scanning counter 0,1,…; use SHA256 of ASCII `binding-edits-v1:{phase}:{comma-separated variable indices}:{rep}:{counter}` (first seven/six bytes modulo eight, in ascending order of the fixed keys). Require at least two distinct values and at least one duplicate among fixed keys. Reject a candidate if any of its full maps has a cyclic orbit in a previously admitted panel or FIT, or if its full maps repeat within its panel. Internally repeated orbits from cycling a FIT background are intended. FIT first, then PROBE; prepublish hashes before fitting. All books disjoint from old permutation books by construction. No choice uses outputs.

## The diagnostic is identifiable for this head

For a fixed live alias `i`, let `g_ij` be the **joint** probability of archive row `j` (including local/no-read competition). It is independent of the successor values in these two-token books. Let `M[z,b]` be logit `z`'s linear projection of the successor embedding of value `b`, through `value`, `out`, and the LM head **without its bias**. Then the logits are a fixed query-dependent term plus `Σ_j g_ij M[:,value_j]`. This identity relies on this vector decoder and fixed keys; it is not a theorem about arbitrary nonlinear language models.

For changing the label from `a` to `b`, define `κ(a,b)=M[b,b]+M[a,a]−M[b,a]−M[a,b]` using answer-token logit rows. An **isolated target-row rewrite** changes the new-vs-old log odds by `g_ii κ(a,b)`. **Swapping** with donor `j` changes them by `(g_ii−g_ij) κ(a,b)`. Negative `κ` with a low intended-row weight can get the swap right while a single intended-row edit moves the odds in the *wrong direction*. Compare these predictions to actual native log odds on all such test cases. Report signs and max absolute error; the FP32 consistency tolerance is `2e-4 + 2e-5 * |predicted delta|`. Do not infer direct key retrieval from output accuracy alone.
