# Corpus attention kernel v1

Implementation of the [whole-corpus attention specification](../CORPUS_ATTENTION.md). Build in this order: validate document-safe occurrences, exhaustive CPU attention, an indexed CPU read and its first derivatives; **only then** port the ragged reduction to Triton. All qualification here uses invented tokens or generated tensors, no natural role or fitted checkpoint. This is separate from the four-page panel.

## What one read does

1. `EndpointIndex` indexes every **within-document endpoint with a real successor**. It rank-sorts reversed causal contexts by doubling (O(N) rank workspace, no materialized list of all prefix strings). Given the actual prefix it binary-searches nested intervals for every supported suffix length. `frontier.maximal_runs()` gives each occurrence its longest frontier-ending exact match; no hit-count cap. `trail`/`branch` expose successive corpus extension tokens, their original occurrence row IDs and structural ends, without advancing live history. This first proposer aligns at the prediction frontier, not every possible gapped or internal anchor. IDs are tokenizer- and mount-bound; the caller must provision honest disjoint source identities. This is not a duplicate-text detector or an out-of-core suffix array.
2. `exhaustive` is the literal reference over all exposed corpus rows, causal local rows and optional no-read row. `Answer` exposes the read, joint log partition, each source's log partition and the three source shares. Omitting LOCAL does not remove the actual prefix from the query. An empty low-level read has zero hint and no support. For a probability law an unsupported source set needs a fallback.
3. `prepare` draws on fixed positive Gaussian features for exp-dot attention: if `a=x/d^(1/4)`, `log φ_r(x)=ω_r·a−||a||²/2−log(R)/2`. The expected inner product is the exact exponential kernel, **not** a per-query guarantee at finite rank. The caller supplies the projection (the helper uses antithetic standard Gaussians). Each leaf summarizes the log mass and weighted value mean of each feature **over all its rows**. Merge adjacent leaves into a dyadic tree. Ordinary dense projections and summary GEMMs use PyTorch, and gradients flow through the summaries, keys, base masses and values.
4. `Plan.build` accepts a different union of row intervals per query and deduplicates overlaps. Score all refined rows exactly; cover the rest with disjoint tree nodes and feature-scored partial leaves. This is mathematically whole-background-plus-replacements, but **never subtracts** a huge approximate sum to recover a tiny remainder. Empty refinement uses the whole background; full refinement equals exhaustive attention. A suffix-length threshold allocates exact work; it does not erase unmatched corpus mass. Complexity of query scoring depends on refined rows, summary nodes × rank, partial edge rows and local length, not obligatorily a full corpus scan. Worst-case exact work is still linear. Node storage is approximately `2 ceil(N/leaf) × R × (V+1)` floats, in addition to row keys/values/features. Fragmented refinements, high rank or wide values can be expensive.
5. `CorpusTokenLM` is a small trainable consumer. The query uses the last token and a causal prefix mean. Keys use only context through each endpoint. Vector mode reads learned successor embeddings and decodes over the vocabulary; pointer mode reads one-hot successors directly (suitable for small vocabularies). Only local successors **already observed** are stored. A finite no-read logit competes in the joint softmax; the example initializes its size offset to `log(max(1,N_exposed_corpus))`. The model rebuilds current corpus encodings and statistics on every training forward; integer routes have no VJP. `model.freeze(index)` builds one private weight snapshot and one bank for reuse in serving. A changed trainable encoder needs a new bank. This is a static-value attention head; dynamic nonlinear passage effects cannot simply be stored as static means.

```python
from experiments.expressivity_tasks.retrieved_span_effects.corpus_kernel.index import EndpointIndex
from experiments.expressivity_tasks.retrieved_span_effects.corpus_kernel.token_lm import CorpusTokenLM

idx = EndpointIndex([('manual-A', [3, 9, 1, 2]), ('manual-B', [3, 9, 5])], tokenizer='example-v1')
m = CorpusTokenLM(vocab=16, dim=12, rank=32, tokenizer='example-v1')
y = m(idx, [('live-doc', [7, 3, 9])])   # no label in the lookup
loss = -y.probabilities[0, 2].log()      # actual next ID, supplied only to loss
loss.backward()
# Fixed weights: m.freeze(idx).predict(requests, local=True, corpus=True)
```

## CPU result before porting

**9 CPU tests passed.** On the 4,096-row invented fixture, the mean joint row TV distance to true dense attention was **.18109** for background only, **.12292** with frontier-MEM refinement, and zero with full refinement. The corresponding **next-token TV** was **.09973 / .05823 / <2e-15**. The MEM plan scored 11,352 of 163,840 query–corpus pairs exactly (6.93%); all other rows contributed via 144 summary nodes and 424 explicit edge rows. Eight of forty queries had no lexical match. Mean absolute corpus-share error decreased from .12007 to .06496, not zero. Implementation error vs the *same mixed law* was <2e-15 per token probability. These are finite-rank approximation measurements on invented data, not performance or quality on language. [Compact numeric receipt](receipts/cpu-fidelity.json).

## CPU validation contract

Check suffix order, maximality and branches against literal occurrences (including >64 tokens and >4 hits); exact row coverage for arbitrary overlapping ranges, partial leaves, empty banks and odd trees; exhaustive concatenated softmax vs the intended mixed law, all source partitions, shares, reads, and first VJPs on odd/empty/ragged geometries in FP64 and FP32. Include many weak corpus rows, extreme score scales, mutated raw inputs, local masking, omission of sources, snapshot isolation and current-weight optimizer steps. On a fixed invented 4,096-row, 40-query, rank-32 fixture compare background-only, all last-token MEM occurrences refined, and full refinement. Include a semantic twin with no lexical matches. Report both row and next-token TV vs exhaustive attention. Require agreement with the **specified** hybrid law and full-coverage recovery; do not require partial refinement to improve every query or call a fidelity measurement an LM win.
