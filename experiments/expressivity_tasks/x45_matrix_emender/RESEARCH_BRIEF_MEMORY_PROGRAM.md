# Research Brief: Four Live Questions for the Emender Program

**Scope.** Part A (hybrid memory/dense interleaving), Part B (retrieval at training time), Part C (capacity beyond linear readout), Part D (short-convolution load-bearing-ness in the delta-rule lineage). All citations verified against fetched primary sources where noted; search-derived claims are flagged as interpretation. Settled-vs-open flags are given per finding and summarized per part.

---

## Summary

The literature strongly supports all four of the program's candidate directions. (A) Interleaving sparse/specialized memory or attention layers into a dense backbone at *minority ratios* (1:3 to 1:7) beats both pure architectures at matched parameters in every major study (Jamba, Samba, Zamba, Memory Layers at Scale), and Meta's ablations directly show sparse and dense layers are complementary, not substitutive — but there is a hard optimum (~3 memory layers) beyond which gains reverse. (B) Retrieval-augmented *training* at matched compute delivers effective-parameter gains of roughly 5–10× (RETRO, Memorizing Transformers), coupling is overwhelmingly via internal states rather than input tokens, and the main failure mode is that the dense backbone can silently absorb the retrieval pathway (InstructRetro's encoder ablation) — which is actually favorable evidence for the spine registration. (C) Theory (dense associative memory / modern Hopfield) *proves* exponential-capacity scaling for nonlinear readout under explicit distributional assumptions, and Anthropic's superposition work gives the empirical analogue — but no existing theorem covers a recurrently-written fast-weight state with a key-conditioned nonlinear decoder, so the X46 writeup can anchor on Hopfield/DAM theory but must mark the mapping as inference. (D) The short conv is genuinely load-bearing in the GDN lineage (FLA ships it with a "do not turn off" warning; published ablations show large gains in some settings, small in others), its mechanism is a token-shift/previous-token-head effect that makes fast-weight regression non-trivial, and its absence in the comparison machine is a real confounder — the conv-transplant arm is well-justified.

## Findings

### PART A — Hybrid memory/dense interleaving architectures

**A1. Jamba: 1:7 attention:Mamba ratio, hybrid beats both parents.**
**Claim:** Jamba mixes attention, Mamba, and MoE layers in blocks of 8 layers with an attention:Mamba ratio of 1:7, and at matched parameters outperforms both pure Transformer and pure Mamba baselines on standard benchmarks, with the 1:7 ratio later described as "found optimal" and confirmed in Jamba-1.5 and follow-up work. **Sources:** [Jamba (Lieber et al., arXiv:2403.19887, ICLR 2025)](https://arxiv.org/html/2403.19887); [Jamba-1.5 (arXiv:2408.12570)](https://arxiv.org/abs/2408.12570). **Support:** direct evidence (architecture description and ratio from both papers; Jamba-1.5 text states the 1:7 ratio "was found optimal in our work on Jamba and similar ratios was also confirmed as successful in follow-up work"). **Confidence:** high. **Settled vs open:** settled (hybrids beat parents at matched params); open (the exact ratio is efficiency- and task-dependent, not universal — see A6).

**A2. Samba: alternating Mamba + sliding-window attention; specialization mechanism.**
**Claim:** Samba interleaves Mamba layers with sliding-window attention layers (at ~430M–1.7B scale, 48 total layers with SWA at odd indices in the matched comparison) and beats Mamba, Mamba-MLP, and Llama-2 baselines at matched parameters (e.g., 6-benchmark average 58.54 vs Mamba 56.99 vs LLaMA-2 56.08 at 1.3B), while extrapolating to 1M-token contexts in perplexity. A mechanistic analysis suggests the gain is *division of labor*: with attention layers providing precise retrieval, Mamba layers relax their input-selection entropy and focus on recurrent structure. **Sources:** [Samba (Ren et al., arXiv:2406.07522, ICLR 2025)](https://arxiv.org/html/2406.07522v3) — fetched and verified, including Tables 2/4 and Section 4 mechanistic analysis. **Support:** direct evidence for architecture and numbers; the "specialization" explanation is the authors' interpretation (label it as such). **Confidence:** high. **Settled vs open:** settled (alternating hybrid wins at these scales); open (the causal specialization story is suggestive, not proven). Relevance to emender: the dense machine being "uniformly load-bearing" while the slot machine uses memory in ~5/24 layers is consistent with this literature — specialized memory layers let the rest of the network offload retrieval work.

**A3. Zamba: shared attention+MLP block every 6 Mamba blocks.**
**Claim:** Zamba uses a backbone of Mamba blocks with a *single, parameter-shared* attention+MLP block repeated every 6 Mamba blocks (input embeddings concatenated with the residual stream into the shared block); Zamba2 ablations refined this (Mamba-2 backbone, additional hybrid blocks). **Sources:** [Zamba (Glorioso et al., arXiv:2405.16712)](https://arxiv.org/abs/2405.16712); [Zamba2 technical report (arXiv:2411.15242)](https://arxiv.org/pdf/2411.15242). **Support:** direct evidence (abstract/architecture descriptions). **Confidence:** high. Notable for emender: even a *single shared* global-memory block, applied periodically, recovers most of the hybrid gain at fixed parameter count — a candidate cheap design point for a slot-store machine.

**A4. Memory Layers at Scale: sparse KV memory replacing FFN — gains and the complementarity ceiling.**
**Claim:** Meta FAIR replaced the FFN of one or more transformer layers with a sparse trainable key-value memory layer (product-key-style top-k lookup), using a *shared* memory pool across all memory layers. Results: memory-augmented models (base 134M–8B, memory up to 128B parameters) outperform dense models with >2× compute, and MOE/PEER baselines at matched compute and parameters; factual QA accuracy improves >100%; a 1.3B base with 64M memory values (138.7B total params) approaches Llama2-7B (10× FLOPs, 2× tokens) on factual QA; an 8B base with 64B memory params trained on 1T tokens approaches Llama3.1-8B trained on 15T tokens. Critically for emender: **multiple memory layers help up to 3 layers, beyond which replacing further FFN layers degrades performance — "showing sparse and dense layers are both needed and likely complementary."** They also report training instability for large memory layers (especially small base models), mitigated with qk-normalization. **Sources:** [Memory Layers at Scale (Berges et al., arXiv:2412.09764, ICML 2025)](https://arxiv.org/abs/2412.09764) — fetched and verified from full text, including Tables 1–2, §3.1.3 shared memory, §3.1.4 stability, §5.4 ablations. **Support:** direct evidence. **Confidence:** high. **Settled vs open:** settled (sparse memory layers add capacity at near-zero FLOPs and beat dense >2x-compute baselines on factual tasks); open (general-purpose perplexity transfer — Meta notes gains are concentrated in factual/coding tasks; hardware efficiency of memory layers remains an acknowledged engineering problem).

**A5. Product-key memories (Lample et al. 2019) — the precursor.**
**Claim:** PKM adds up to ~1B memory parameters with negligible compute overhead; a 12-layer transformer with PKM outperforms a 24-layer dense baseline on CC-News and runs ~2× faster at inference. Per Meta's 2024 paper, the field largely abandoned memory layers afterward because they were hard to scale/train until the new improvements. **Sources:** [Large Memory Layers with Product Keys (Lample et al., NeurIPS 2019, arXiv:1907.05242)](https://arxiv.org/abs/1907.05242); [Memory Layers at Scale framing](https://arxiv.org/abs/2412.09764). **Support:** direct evidence for architecture; the "12-layer beats 24-layer" and "2× faster" numbers from the NeurIPS PDF surfaced via search summary — treat exact figures as medium-confidence until re-checked against the PDF. **Confidence:** medium-high. **Settled vs open:** settled (product keys make sparse top-k lookup over billions of keys tractable); open (nothing about *sequence* memory — PKM is a static layer, unlike emender's slot store).

**A6. Memorizing Transformers as a hybrid-layer datapoint.**
**Claim:** Wu et al. add a single kNN external-memory attention layer to a transformer; memory layer placement mid-stack is best (12-layer model: ppl 2.36 at layer 6 vs 2.40/2.37/2.43 at layers 3/9/12), and a model with 8K-token memory matches a dense transformer with ~5× more parameters, with gains persisting from 200M to 8B scale. **Sources:** [Memorizing Transformers (Wu et al., arXiv:2203.08913, ICLR 2022)](https://arxiv.org/html/2203.08913) — fetched and verified (Tables 4, 5, 14; §4.4). **Support:** direct evidence. **Confidence:** high. This is both a Part A (minority hybrid placement, mid-stack) and Part B (training-time retrieval) datapoint: a *single* sparse/retrieval layer mid-stack carries a 5× effective-parameter gain.

**A7. Failures and caveats in the hybrid literature.**
- Samba-NoPE (no positional embeddings) collapses out-of-distribution (perplexity 28.97 at 8K vs 9.65 for Samba) — hybrid components interact with positional schemes. [Samba, arXiv:2406.07522](https://arxiv.org/html/2406.07522v3), direct evidence.
- The hybrid strategy is *not uniformly better*: Mamba-SWA-MLP beats Samba on GSM8K/SIQA/WinoGrande in Samba's own Table 2. [Samba, Table 2], direct evidence.
- Memory-layer training instability at scale (Meta) required qk-normalization fixes. [arXiv:2412.09764], direct evidence.
**Confidence:** high.

**Part A conclusion (for the hybrid-layer design decision).** The evidence is unambiguous that minority-ratio interleaving (1:3 RETRO-style coupling, 1:7 Jamba-style attention, every-6 shared Zamba-style, ≤3 memory-layer FFN replacements Meta-style) beats both pure dense and pure-recurrent/pure-sparse machines at matched parameters, and that the sparse/memory layers are complementary to dense compute rather than redundant (Meta's explicit ablation). The dense machine being "uniformly load-bearing" in emender's receipts is the *baseline* pattern; the literature's winning pattern concentrates memory work in a few positions and lets the rest of the network specialize. Recommended design anchors: shared memory parameters across memory layers (A4), mid-stack placement (A6), gated/optional use of memory per layer (Jamba gating, MT's gate), and expecting the optimum memory-layer count to be small with a hard degradation ceiling. **Settled:** hybrid > pure, complementarity, minority ratios. **Open:** the optimal ratio for a *slot-store* machine (no published study interleaves slot/fast-weight memory layers into a dense stack at emender's setting — this is genuinely novel territory); task-dependence of ratios.

### PART B — Retrieval at training time

**B1. RETRO: training-time retrieval ≈ 10× effective parameters, constant relative gain with scale, internal-state coupling.**
**Claim:** RETRO (DeepMind) retrieves chunk-level neighbors (k=2 in main config; up to 40 best) from a 600B-token database *during training* (1.75T at eval) using a **frozen BERT retriever**, encodes neighbors with a differentiable encoder conditioned on decoder activations, and couples them into the decoder via **chunked cross-attention (CCA)** — one Retro-block every 3 blocks starting at layer 6. Results: with a 2T-token database, 7.5B RETRO is comparable to GPT-3/Jurassic-1 on the Pile despite 25× fewer parameters, and beats Gopher (280B) on 9/16 Pile datasets (DeepMind blog). The paper's own Figure 1 states the retrieval gain "remains constant with model scale … and is comparable to multiplying the parametric model size by ∼10×." The leakage analysis (§2.6/§4.4) shows performance comes "from both explicit neighbour copying and general knowledge extraction." **Sources:** [RETRO (Borgeaud et al., arXiv:2112.04426)](https://arxiv.org/html/2112.04426v3) — fetched and verified from full text (abstract, §2.2–2.5, Fig. 1, Algorithm 1); [DeepMind blog](https://deepmind.google/blog/improving-language-models-by-retrieving-from-trillions-of-tokens/) for the 9/16-vs-Gopher claim (search summary). **Support:** direct evidence for architecture/figures; blog-derived Gopher claim medium-high confidence. **Confidence:** high. **Settled vs open:** settled (training-time retrieval gives large, scale-robust gains; frozen retrievers suffice; internal-state CCA coupling works at scale). Open: per-dataset transfer — I could not re-verify from the fetched slices the widely repeated claim that retrieval gives little/no gain on code (Github) and math (DM Mathematics) subsets of the Pile; treat it as unconfirmed (see Missing evidence).

**B2. kNN-LM and training-time variants.**
**Claim:** kNN-LM (Khandelwal et al.) interpolates the LM's output distribution with a nearest-neighbor datastore at *inference* (not training) and set SOTA on Wikitext-103; its training-time-aware successors — Regularized training of kNN-LM (Ton et al., arXiv:2109.08249), and training the LM to anticipate the kNN component (Xu et al., "Why do Nearest Neighbor Language Models Work?", arXiv:2301.02828 / ICML 2023) — show that *training with retrieval in mind* beats bolting retrieval on post-hoc. Xu et al.'s analysis (ICML 2023) identifies specific dimensions along which kNN-LM diverges from parametric LMs, ruling out simple "more data" explanations; Chiang et al. (NAACL 2024 short, arXiv:2311.09615) further probe why retrieval on the *same training set* still helps, and the EMNLP 2025 study of input-neighbor overlap (Doostmohammadi & Kuhlmann) confirms the effect is tied to retrieval-side neighbor availability, not generic augmentation. **Sources:** [kNN-LM (arXiv:1911.00172)](https://arxiv.org/abs/1911.00172); [2109.08249](https://arxiv.org/abs/2109.08249); [2301.02828](https://arxiv.org/abs/2301.02828); [2311.09615](https://arxiv.org/html/2311.09615v2); [EMNLP 2025 overlap study](https://aclanthology.org/2025.emnlp-main.1363.pdf). **Support:** direct evidence for abstracts/summaries; specific numeric gains not re-verified against full texts. **Confidence:** medium-high. Coupling note: kNN-LM couples at the *output distribution*; none of these couple into internal evictable state — the gap emender's slot machine fills.

**B3. Memorizing Transformers: the closest precedent — retrieval-shaped memory active DURING training.**
**Claim:** MT performs approximate kNN lookup into a non-differentiable memory of recent (key, value) *internal representations*, used during training and inference; adding 8K memory tokens improves C4(4K+) perplexity from 17.20→14.42 (vanilla) / 15.38→14.04 (Transformer-XL) at ~1B scale; a small-memory MT matches a 5×-larger dense transformer; gains improve steadily with memory size to 262K; models can be fine-tuned onto larger memories (staleness is a noted instability source); improvement is driven by a *sparse* set of tokens (rare words, function names, citations) — the retrieved content functions as per-token evictable lookups, not blended input text. **Sources:** [Memorizing Transformers (arXiv:2203.08913)](https://arxiv.org/html/2203.08913) — fetched and verified (Tables 4–5, §3.3, §4.3–4.6). **Support:** direct evidence. **Confidence:** high. Relevance: this is the strongest published precedent for emender's claim that retrieved content can enter state as addressable/evictable units *during training* — MT's memory entries are internal-state (key,value) pairs, not input tokens.

**B4. Atlas and the QA lineage; InstructRetro at 48B; RETRO++.**
**Claim:** Atlas (Meta/Facebook+HFP, JMLR 2023) jointly trains retriever and reader for few-shot learning, coupling retrieved passages as *input tokens* to a seq2seq reader — the main training-time-retrieval success in the QA regime. InstructRetro (NVIDIA, ICML 2024) scales retrieval-augmented pretraining to 48B by continuing pretraining a 43B GPT on 100B tokens with retrieval from a 1.2T-token corpus, for only 2.58% additional GPU hours; the instruction-tuned model beats its GPT counterpart by 7% (short-form QA), 10% (long-form QA), 16% (summarization) — **and, strikingly, the retrieval encoder can be ablated after instruction tuning with comparable results**, i.e., retrieval-augmented pretraining leaves a *better dense backbone* even when the retrieval pathway is removed. "Shall We Pretrain Autoregressive LMs with Retrieval?" (EMNLP 2023) gives the sober counterpart: perplexity gains do not automatically transfer to downstream generation/factuality, and proposes RETRO++ (feeding best evidence to the decoder, more to the encoder), which lifts NQ EM from 45.5%→54.1%. **Sources:** [Atlas (arXiv:2208.03299, JMLR 2023)](https://arxiv.org/abs/2208.03299); [InstructRetro (arXiv:2310.07713, ICML 2024)](https://arxiv.org/abs/2310.07713) — abstract fetched and verified; [Shall We Pretrain… (arXiv:2304.06762, EMNLP 2023)](https://aclanthology.org/2023.emnlp-main.482/). **Support:** direct evidence for InstructRetro claims (abstract, verbatim); Atlas/RETRO++ claims from abstracts and search summaries (medium-high). **Confidence:** high for InstructRetro; medium-high for the rest. **Key decision-relevant implication for the spine registration:** InstructRetro shows retrieval-at-training-time improves the *parametric* machine even if the retrieval pathway is later removed — i.e., training-time retrieval is not merely an inference-time crutch; the ability to register retrieved content as evictable units (emender's capability, which dense-state machines cannot express per your receipts) is the mechanism the literature approximates with CCA slots (RETRO), memory keys (MT), and input concatenation (Atlas).

**B5. Failure modes (documented).**
- **Latency/engineering:** on-the-fly retrieval was too slow for RETRO's training loop; neighbors were precomputed (frozen BERT makes this possible); SCaNN queries ~10ms amortized per 64-token chunk. [arXiv:2112.04426 §2.3], direct evidence.
- **Too many neighbors:** RETRO gains degrade past k=40 retrieved neighbors ("perhaps due to the reduced quality"). [arXiv:2112.04426 Fig. 1], direct evidence.
- **Staleness / training instability:** MT notes training instability when starting with large memory, attributable to stale keys; models compensate by adjusting queries; fine-tuning onto larger memories closes 85% of the gap in 4% of pretraining steps. [arXiv:2203.08913 §3.3, §4.5], direct evidence.
- **Quality transfer:** "kNN-LM Does Not Improve Open-ended Text Generation" (arXiv:2305.14625) and "Great Memory, Shallow Reasoning: Limits of kNN-LMs" (arXiv:2408.11815) show retrieval gains are concentrated in memorization/recall, not generation quality or reasoning. Direct evidence at abstract level.
- **Pathway absorption:** InstructRetro's encoder-ablation result (B4) — the retrieval pathway's function migrates into dense weights after instruction tuning. This is a failure mode for *deploying* the retrieval pathway, but evidence *for* retrieval-augmented pretraining as a training-time curriculum.
**Confidence:** high.

**Part B conclusion (for the spine registration decision).** The literature uniformly shows training-time retrieval yields effective-capacity gains far beyond its compute cost (RETRO ~10×; MT ~5×; InstructRetro: 48B-beating backbone for 2.58% extra GPU-hours), that frozen retrievers + precomputed neighbors are the scalable recipe, and that internal-state coupling (CCA, memory keys) has succeeded at far larger scale than input-token coupling for LM pretraining. RETRO's architecture — retrieved chunks bound to addressable, causally-shifted positions in dedicated layers (1-in-3) — is the closest published relative to "append retrieved documents into addressable slots during training." The documented failure modes (staleness, neighbor-count collapse, latency) are all engineering-addressable in a slot-store machine where eviction is explicit. **Settled:** training-time retrieval works and is scale-robust; frozen retrievers suffice; internal-state coupling at scale. **Open:** no published system couples retrieval into a *gated/slot fast-weight* machine at training time (novelty gap and risk); whether evictable-unit registration changes the gain profile vs CCA (untested anywhere).

### PART C — Capacity beyond linear readout

**C1. The formal results: dense associative memory and modern Hopfield give nonlinear readout a capacity super-class.**
**Claim:** Krotov & Hopfield's dense associative memory showed that raising the energy-function nonlinearity raises capacity polynomially (degree-F nonlinearity ⇒ capacity grows like N^(F-1)); Ramsauer et al.'s modern Hopfield network (softmax/attention readout) achieves exponential-in-dimension storage (P = c^d, c>1) *with one-step convergence proven*, under explicit assumptions (random patterns on a sphere, sufficient separation, appropriate temperature); the PRL 2024 statistical-mechanics analysis proves exponential capacity for dense associative memories but distinguishes typical-pattern retrieval from retrieving *all* patterns; the NeurIPS 2024 "spherical codes" paper gives provably optimal capacity bounds for modern Hopfield models and shows capacity depends strongly on pattern geometry; and a 2026 follow-up (Kafraj, Krotov & Latham) removes the linear-in-hidden-units bottleneck of two-layer constructions by changing the nonlinearity. **Sources:** [Hopfield Networks are All You Need (Ramsauer et al., arXiv:2008.02217; CMU-hosted PDF)](https://deeplearning.cs.cmu.edu/S24/document/readings/hopfieldnets_is_all_you_need.pdf); [Exponential Capacity of Dense Associative Memories (Lucibello & Ricci-Tersenghi, PRL 132, 077301, 2024)](https://journals.aps.org/prl/abstract/10.1103/PhysRevLett.132.077301); [Provably Optimal Memory Capacity for Modern Hopfield Models (NeurIPS 2024)](https://papers.neurips.cc/paper_files/paper/2024/file/82846e19e6d42ebfd4ace4361def29ae-Paper-Conference.pdf); [A Biologically Plausible Dense Associative Memory with Exponential Capacity (arXiv:2601.00984)](http://arxiv.org/abs/2601.00984); [Memory Capacity of Neural Network Models (Fusi, Oxford Handbook chapter, 2024)](https://doi.org/10.1093/oxfordhb/9780190917982.013.26). **Support:** direct evidence from fetched/search-verified abstracts and the CMU PDF summary; the Krotov polynomial claim is standard in the DAM literature (medium-high confidence as phrased here — re-verify exact exponents in the writeup). **Confidence:** high that nonlinear readout has proven superlinear/exponential capacity *under stated conditions*. **Settled vs open:** settled as existence proofs with conditions; open whether the conditions (random, well-separated, uncorrelated patterns; single-step retrieval) hold in any trained network — they are about *idealized* pattern sets, not learned key spaces.

**C2. What the theory explicitly does NOT cover.**
**Claim:** All proven capacity results concern a static pattern matrix read out by a fixed nonlinearity. None of them analyze: (i) a state matrix *written sequentially by a gated delta rule* (recurrently constructed, decayed, interference-prone in sequence-dependent ways); (ii) a *key-conditioned* nonlinear decoder (the readout is not a fixed similarity nonlinearity but an MLP conditioned on the query key); (iii) structured/correlated key distributions from byte-level text. The reservoir-computing literature (e.g., Takasu & Aoyagi 2025; Ballarin et al. on memory capacity of nonlinear RNNs) similarly shows nonlinear readout scales differently from linear readout but in different settings (temporal memory of stochastic signals, not exact association recall). **Sources:** as in C1 plus [arXiv:2504.19657](https://arxiv.org/abs/2504.19657), [arXiv:2502.04832](https://arxiv.org/abs/2502.04832), [Gonon et al., arXiv:2004.11234](https://arxiv.org/abs/2004.11234). **Support:** researcher inference from the scope of the fetched results (no negative-result paper exists; the gap is defined by what the positive results assume). **Confidence:** high (as a statement about the literature's coverage). **Open:** entirely.

**C3. The superposition hypothesis — the empirical analogue.**
**Claim:** Anthropic's toy models show trained networks store more features than they have neurons when features are sparse, accepting interference that nonlinearities then filter; polysemanticity is a consequence of this compression. This is the empirical, mechanistic-interpretability counterpart of "capacity beyond the linear count." It is explicitly framed as a *hypothesis* validated in toy models, not a theorem about LLMs. **Sources:** [Toy Models of Superposition (Elhage et al., arXiv:2209.10652; Anthropic)](https://www.anthropic.com/research/toy-models-of-superposition). **Support:** direct evidence (paper's own claims and caveats). **Confidence:** high for what the toy models show; the extrapolation to emender's X46 setting is inference. **Settled vs open:** open (superposition is established empirically in toy settings; its quantitative role at scale is ongoing research).

**C4. VSA/holographic-association theory — a formal bridge.**
**Claim:** Frady, Kleyko & Sommer's theory of sequence indexing in RNNs analyzes exactly the linear-readout vs error-correcting-readout split: for high-dimensional holographic codes, linear readout of analog data has limited capacity, but readout with winner-take-all error correction of symbolic data performs "superior to" the linear bound — a formal (if model-specific) result that nonlinear/error-correcting readout resolves more associations than linear-associative readout of the same state. **Sources:** [A theory of sequence indexing and working memory in RNNs (Frady et al., arXiv:1803.00412)](https://arxiv.org/abs/1803.00412). **Support:** direct evidence at abstract level. **Confidence:** medium-high (I did not fetch the full derivation). This is the most on-point formal citation for "resolving aliased blends": WTA-style readout disambiguating superposed/aliased encodings beyond linear capacity.

**Part C conclusion (for the theory writeup / ceiling refutation).** The X46 finding (trained GDN beating its derived Welch-bound/linear-associative key-space ceiling, 0.93 vs 0.80 at n=320; 0.87 vs 0.40 at n=640) is *consistent with, and anticipated in kind by,* two mature literatures: (1) dense-associative-memory/modern-Hopfield theory, which proves that nonlinear readout lifts association capacity from O(d) toward exp(d) under explicit distributional and separation conditions (with the strong caveat that "exponential capacity" is conditional and typically-pattern-based, not a guarantee for arbitrary or correlated memories); and (2) superposition (empirical: networks routinely pack more features than linear dimensions, with nonlinearity filtering the resulting interference). The honest writeup structure: state the linear-associative/Welch ceiling as the correct bound *for linear readout* (proven); state the DAM/Hopfield conditions as the proven mechanism class; present the key-conditioned nonlinear decoder as the candidate mechanism by which the trained machine exceeds the linear ceiling (inference, supported by C4's WTA result and C1's selectivity mechanism); and mark as open the formal analysis of capacity for delta-rule-written recurrent states with conditioned decoders — no theorem covers it, which makes X46 a genuine contribution rather than a corroboration. **Settled:** linear-readout ceilings are real and applicable to linear decoders; nonlinear readout lifts capacity (proven under conditions; observed empirically). **Open:** capacity theory for this exact regime.

### PART D — Short convolutions in the linear-attention/SSM lineage

**D1. The component is default-on and its authors treat it as critical.**
**Claim:** The FLA Gated DeltaNet implementation ships `use_short_conv=True` with `conv_size=4` applied to Q, K (and V) with SiLU activation, and the codebase carries the warning: "ShortConvolution is crucial to the performance. Do not turn it off unless you know what you are doing." The NVlabs lit-gpt port likewise always applies short convolutions. GDN2's registered block therefore includes a component that the emender comparison machine lacks by construction. **Sources:** [fla/layers/gated_deltanet.py](https://github.com/fla-org/flash-linear-attention/blob/main/fla/layers/gated_deltanet.py); [NVlabs/GatedDeltaNet lit_gpt/gated_delta_net.py](https://github.com/NVlabs/GatedDeltaNet/blob/main/lit_gpt/gated_delta_net.py); warning quoted via [Shalev, "A closer look at short convolutions"](https://noamshh.github.io/blog/short-convolutions/) — blog fetched and verified. **Support:** direct evidence (code + verbatim warning). **Confidence:** high.

**D2. Published with/without-conv ablations: large but heterogeneous gains.**
**Claim:** Aggregate of published ablations: DeltaNet (340M, 15B tokens) LAMBADA perplexity 50.87 → 37.37 with the short conv (the largest effect I found); GDN (400M) average perplexity 28.95 → 27.35; Kimi Linear (16-layer ablation model) 5.70 → 5.65 (small); a ~300M study of Mamba-2 306M: 20.26 without conv → 19.30 with static conv; and kernel-size sweeps across three independent studies (2Mamba2Furious; dynamic-conv study; Qwen3-1.7B static-conv study) show most of the gain comes from *having any conv at all* (e.g., loss 3.06 no-conv → 2.90–2.93 with conv; PPL 19.12 → ~18.1; 13.42 → ~12.8–13.1), with small and inconsistent differences among kernel sizes 2–4 (kernel 3 best in two of three sweeps; Primer found wider convs hurt). **Sources:** [Shalev blog (fetched, tables verified)](https://noamshh.github.io/blog/short-convolutions/) aggregating [DeltaNet (arXiv:2406.06484)](https://arxiv.org/abs/2406.06484), [GDN (arXiv:2412.06464)](https://arxiv.org/abs/2412.06464), [Kimi Linear (arXiv:2510.26692)](https://arxiv.org/abs/2510.26692), [Dynamic Short Convolutions Improve Transformers (arXiv:2606.03825)](https://arxiv.org/html/2606.03825), [Static convs (arXiv:2607.18413)](https://arxiv.org/abs/2607.18413), [2Mamba2Furious (arXiv:2602.17363)](https://arxiv.org/abs/2602.17363), [Primer (arXiv:2109.08668)](https://arxiv.org/abs/2109.08668). **Support:** direct evidence (tables in the fetched blog reproduce the papers' numbers). **Confidence:** high for the qualitative conclusion (conv helps; effect size varies by an order of magnitude across architectures/tasks); medium for individual cell values (transcribed via secondary aggregator — spot-check primary tables before quoting numbers in program documents). **Settled vs open:** settled (the conv is load-bearing on average in this lineage, and there is no published result where removing it at scale was free); open (the magnitude at emender's 150M byte-level setting — exactly what the conv-transplant arm measures).

**D3. Mechanism: a previous-token-head / token-shift, plus a regression-degeneracy fix, plus (in GDN) normalization/activation.**
**Claim:** Three complementary mechanistic accounts, all with published support: (i) **token-shift**: the conv lets a key/value written at position t carry information about tokens t-1, t-2, …, reproducing the transformer previous-token head inside a single layer and enabling induction-style recall (RWKV's token shift is the size-2 special case; RWKV-7 describes it as a size-2 short conv that helps induction-head-like behavior within one layer); (ii) **fast-weight degeneracy**: without position mixing, k_t and v_t are two linear views of the same input vector, leaving the fast-weight regression little to fit — mixing earlier tokens into the key gives it something real to regress; (iii) **asymmetry matters**: an "Achilles' heel of Mamba" study found that setting all conv kernel weights to 1 (eliminating asymmetric temporal behavior) changed what the model learns on composite tasks; and causal-intervention work (2025) finds Mamba implements induction *through the short conv rather than the selective SSM* — though a 2026 follow-up shows the conv's component effect varies by more than an order of magnitude across tasks (−12.64pp on S₃, −6.83pp on Parity, +4.04pp n.s. on Dyck-2), qualifying that conclusion. Additionally, in GDN specifically the conv carries SiLU activations on Q/K (and the layer applies L2 norm), so part of its role is activation/normalization, not purely positional mixing. **Sources:** [Shalev blog (fetched)](https://noamshh.github.io/blog/short-convolutions/); [RWKV-7 (COLM 2025)](https://openreview.net/pdf/74011cffc1082ac9394afde92802c810c51baabf.pdf); [Achilles' Heel of Mamba (arXiv:2509.17514)](https://arxiv.org/abs/2509.17514); [Mechanistic Evaluation of Transformers and SSMs (arXiv:2505.15105)](https://arxiv.org/abs/2505.15105); [Task Structure Reverses Layerwise State Encoding (arXiv:2606.00926)](https://arxiv.org/html/2606.00926). **Support:** direct evidence for each claim from fetched/abstract-level sources; the synthesis (three mechanisms) is researcher interpretation of converging results. **Confidence:** high. **Settled vs open:** mostly settled (the conv provides local positional history that makes recall writable in one layer; it is not a mere normalization nicety); open (relative weights of the three mechanisms; task-structure dependence).

**D4. Placement evidence.**
**Claim:** Two independent 2026 studies (a 300M transformer study and a Qwen3-1.7B study) swept conv placement: applying the conv to Q+K+V jointly beats Q, K, or V alone in both, and interestingly V-only helps more than Q- or K-only — which the key-shift story does not explain, supporting the normalization/activation role. RWKV-7's authors chose the simple size-2 token shift over RWKV-6's more adaptive shift because the loss-per-step gain did not justify the cost. A community result (shifted_gdn, ~100M models) reports that *removing* Q/K projections in GDN (using raw hidden states as q and previous hidden as k) slightly improves performance with ~15% fewer parameters — i.e., the conv is one of several ways to supply "previous-token" structure. **Sources:** [Shalev blog (fetched)](https://noamshh.github.io/blog/short-convolutions/); [RWKV-7](https://openreview.net/pdf/74011cffc1082ac9394afde92802c810c51baabf.pdf); [jfguan/shifted_gdn](https://github.com/jfguan/shifted_gdn/blob/main/README.md). **Support:** direct evidence (tables) for placement; shifted_gdn is a low-scale community result (low confidence, flag it). **Confidence:** medium-high.

**Part D conclusion (for interpreting the conv-transplant arm).** The missing kernel-4 conv in the comparison machine is a real, default-on, author-flagged-critical component of the GDN2 registered block; published ablations say it is worth anywhere from ~0.05 to ~14 perplexity points depending on architecture, scale, and task, with the biggest effects on recall/induction-structured data and at smaller scales. Expectations for the transplant arm, as inference from this evidence: (a) most of any gain should come from having any conv at all, not from kernel size; (b) place it on Q+K+V to match GDN's registered block; (c) gains should concentrate on tasks where the machine must write token-adjacent associations (i.e., emender's exact-recall tasks are the sensitive regime — the same tasks behind the X46 finding, so conv-vs-noise attribution matters there too); (d) part of the effect may be activation/normalization (SiLU placement), so a pure-shift control arm (fixed shift, no learned conv) would disentangle the mechanism; (e) if the comparison machine lacked the conv while GDN2 had it, the observed "parity within noise" at 150M may have been achieved against a *handicapped* dense baseline — the transplant arm could move the dense machine above the slot machine, and the program should pre-register how it will interpret that outcome. **Settled:** conv is load-bearing in the lineage; mechanism = previous-token/induction + regression-degeneracy fix. **Open:** magnitude at 150M byte-level; mechanism weights; whether the ceiling-refutation task (X46) is conv-sensitive.

## Contradictions

1. **Conv load-bearing-ness varies by an order of magnitude** across published ablations (DeltaNet: −13.5 ppl; Kimi Linear ablation: −0.05 ppl). Not a contradiction in results, but a heterogeneity that forbids a single expected effect size for the transplant arm. Sources: D2.
2. **"Mamba induction runs through the short conv" (arXiv:2505.15105 causal interventions) vs. task-dependence (arXiv:2606.00926: conv-ablation effect varies −12.64pp to +4.04 n.s. across tasks).** The 2026 result explicitly qualifies the 2025 mechanistic claim. Both retained; the qualified version should be cited.
3. **Kernel size 4 is the universal default but not the empirical optimum** (kernel 3 won two of three published sweeps; Primer found wider convs hurt). The default is a historical artifact of Mamba's d_conv=4 and the causal-conv1d CUDA kernel's {2,3,4} support, not an optimized choice. Source: Shalev blog (fetched).
4. **Jamba's 1:7 ratio "found optimal" vs. Samba's own Table 2 showing a different hybridization (Mamba-SWA-MLP) beating Samba on GSM8K/SIQA/WinoGrande**, and Zamba's every-6 shared block. No single interleaving ratio is universal; ratios are efficiency- and task-contingent.
5. **"Exponential capacity" vs. its fine print**: the PRL 2024 and NeurIPS 2024 results prove exponential storage for *typical*, well-separated, uncorrelated patterns under specific geometry; they do not guarantee retrieval of all patterns or of structured/correlated keys. Popular summaries routinely drop these conditions; the X46 writeup must not.

## Missing evidence

- **RETRO's per-dataset failure cases (code/math):** the widely repeated claim that retrieval gives little/no gain on Pile Github and DM Mathematics could not be re-verified from the fetched paper slices; treat as unconfirmed before citing in program documents.
- **kNN-LM exact perplexity numbers** (and several cell values in D2) are from secondary aggregators; spot-check primary tables before quoting numerically.
- **No published ablation of the GDN conv at ~150M on byte-level data** — the program's transplant arm fills this gap; no external evidence predicts the sign/magnitude at that setting.
- **No published system combines a slot/fast-weight memory machine with retrieval-at-training-time registration** (Parts A+B intersection is a novelty gap — no external evidence de-risks it, only adjacent precedents).
- **No formal capacity theory for delta-rule-written recurrent states with key-conditioned nonlinear decoders** (Part C gap): the X46 writeup must present the mechanism as inference anchored on conditional theorems.
- I did not find any study ablating the conv in the *Welch-bound/linear-associative* key-space analysis — i.e., whether the conv changes the key-space geometry that X46's ceiling was derived from. If the ceiling was derived from the conv-free machine, that's fine; if from the conv-having GDN2, the two findings interact.
