## Token and byte clocks

ASCII `A–Z a–z 0–9 _` are word bytes. Every other raw byte is a delimiter (**including** non-ASCII bytes). A token consists of zero or more word bytes followed by exactly one delimiter, included verbatim in its spelling. Thus `red,` and `red ` are distinct tokens, consecutive delimiters can make one-byte tokens, and no complete spelling prefixes another. No vocabulary/lookahead is needed to decide a boundary. This is a deliberately simple lexical view, not BPE. Ignore the leading fragment *through* the first delimiter as an index token (window may start mid-word), never flush the final unclosed fragment. Use complete spellings from BUILD only with stable lexicographically sorted IDs. Empty token streams are legal; structural end-of-window evidence is never a byte target.

Before the first delimiter, only the common byte predictor runs. **After consuming the first delimiter**, request the root fanout. After each later delimiter advance the previous navigation locus by the *actually completed* token and read the longest indexed token suffix; an unknown token resets to root. Do not shorten solely for sparse or terminal-only fanout: the formula below already backs off. On a word byte since the last read, extend only the local spelling prefix, with **no new suffix-index query or speculative child read**. No query after the final target just to learn how the last token ends. All 256 possible next bytes are scored before using the shifted label. Score all 262,144 external probe targets, including the initial fragments and unsupported prefixes.

## Four fixed predictors

The common byte model `B` is estimated on BUILD's real shifted targets: add-half unigram; back off one-byte contexts to that unigram, two-byte contexts to the one-byte law, each with total prior weight **16** (`(counts+16*shorter)/(total+16)`). On a window's first prediction use only the available one-byte context. No online parameter updates.

At a lookup let `C_h` be counts of *content* follower tokens at its suffix node and `C_*` at root. In token space give each spelling `v` mass `m_h(v)=C_h(v)+4*C_*(v)/sum(C_*)` (root gives its own normalized distribution). For an observed within-token prefix `p`, a fanout's next-byte law `R` sums masses for spellings beginning `p+b` and normalizes over bytes. All complete tokens end in a delimiter, so no branch can finish silently inside `p`. If total mass is zero, use `B`; otherwise emit `(B+R)/2`. Mixing and smoothing are fixed before outcomes. No stale first-byte forecast copied onto later targets.

| Arm | At every refresh | On intervening word bytes after a refresh |
|---|---|---|
| BYTE | No token capability; `B` | `B` |
| FIRST | Actual contextual lookup projected to the 256 first-byte counts; apply the common root backoff and mix | `B`. No saved spelling law. |
| LEX | Identical lookup, projection and first forecast | Use the shared BUILD **root** token spelling law conditioned on `p`, not the original node's within-first-byte preferences. |
| SPELL | Identical lookup, same first forecast, retain weighted token alternatives | Condition the returned `m_h` on `p`. |

LEX is a stronger control than FIRST: it knows general token spellings and frequencies. Reassigning each contextual first-byte group's mass to tokens in proportion to their root frequencies gives exactly LEX inside the group. SPELL vs LEX isolates the context-specific information *beyond* the first byte. Updating the navigator at the next true boundary is identical for FIRST, LEX and SPELL. Root-only or unsupported conditions must not be presented as contextual hits.
